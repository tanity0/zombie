## 0. 社長の言葉(経緯)

- 「**地面は割とゆっくり流れるのに対して、プレイヤーや敵、オブジェクトは等倍に動く。これは近さに比例せず、全て等倍。**」

  → 設計チャットの回答: 中身(位置・移動・当たり判定)は今の平たい板のまま変えず、**描く時だけ1つの遠近の計算(投影)を全てに通す**。
  当たり判定は縮めない(奥の敵が避けやすくならないため)。
- 「**当たり判定だけ左右に大きくズレない?**」→ 全部同じ計算に通せばずれない。**通し漏れがあればずれる。**
- HTMLモック(左=今/右=案2)を見て「**おお、これはかなり良くなるぞ**」。
- 「**段階的にやっていこう。まずは盤面とオブジェクトからかな。**」(→ §3 の段階分け)

**ゴール(1行)**: 画面に出る全ての物が、地面と同じ1本の遠近の計算で置かれ・大きさが決まり、
**どの奥行きでも物と地面が同じ速さで流れ、当たり判定と見た目(特に赤い予告)がずれない**。

前提の事実(判断材料):
- 直前の v0.25.5732 で「足元の地面を等倍の速さ」にした(`src/utils/groundScroll.ts`)。**足元が乗っている帯**だけは物と地面の速さが揃った(帯番号の切り捨て値で係数を出しているので、厳密に等倍なのはその帯。足元の点そのものではない)。
  **足元以外の行では今も地面と物の速さが違う**(下の試算: 画面下端で地面は物の約6倍の縦速度で流れる)。
- 試作 `?objdepth`(`src/utils/groundDepthScale.ts`)は**大きさだけ**地面の横の縮みに合わせた。位置は等倍のままだったので
  「BCの方が地面とのズレが大きかった」(社長)。**大きさと位置は同じ計算から出さないと逆に悪化する**、が教訓。
- 案2は以前「数百箇所・v0.25.3009 で一度見送り」(research/FAKE_3D.md)。v0.25.3009 のコメント(`updatePerspectiveGround` 内)に

## 1. 投影の定義(1本だけ持つ)

### 1-1. 今の地面の描き方(正本にする式)

`pixiScene.updatePerspectiveGround`(9563行付近)。地面は `worldGroup > groundBase`(位置 `(shakeX − marginX, farH + shakeY)`)の中に
**横長の帯(TilingSprite)を縦に並べて**描いている。

| 量 | 式 | 出どころ |
|---|---|---|
| 帯の高さ | `stripH = (screenH − farH) / 72` | `renderSpec.computeGroundBandLayout` |
| 帯 i の行位置 | `t = i / 71`(i>71 で1を超えて手前へ延長。本数は 72/ZOOM_MIN_ABS=180) | `renderSpec.groundStripT` |
| 縦の詰め | `scaleY(t) = gfar + (0.82 − gfar)·t^gcurve`(gfar=0.055・gcurve=2.6) | `groundScroll.groundRowTileScaleY` |
| 横の縮み(台形) | `conv(t) = 1 + ((g3dfar + (1−g3dfar)·t^g3dc) − 1)·g3d`(g3dfar=0.10・g3dc=1・g3d=1)。tileScale.x = 0.82·conv | `groundScroll.groundRowTileScaleX` |
| 横の消失点 | 画面中央の列(`overW/2` を中心に収束)。world では `cam.x + screenW/2`(シェイクは相殺) | 同上 |
| 流れる速さ | カメラ 1px あたり 横 `conv(t_i)/conv(t_f)`・縦 `scaleY(t_i)/scaleY(t_f)`。t_f は**足元が乗っている帯の番号の切り捨て値**(`groundFeelAtFoot` の `Math.floor`)=厳密に 1 になるのは**足元が乗っている帯**で、足元の点そのものではない(帯の中の段差ぶん、最大で帯1本ぶんの差) | `groundFeelAtFoot`+`GroundScrollAccumulator`(カメラの移動量×その時の係数を足し込む) |
| ズーム | 帯も物も `worldGroup` の子=**投影の後で一様に** scale/position(支点: 引き=farH・寄り=画面中央) | `sync` 10179行付近 |

**ここから導ける唯一の world→画面(worldGroup ローカル)の写像**(=地面と物の速さが全ての行で一致する条件):

```
ℓ  = 地面の帯のローカルY(=worldY − camera.y − farH)。帯の上端(地平線)=0。
ℓf = 基準行のローカルY = ℓ_ref(★#2 裁定=カメラの基準行。§1-1d で定義する。毎フレームの入力=カメラのズームの定位置へ運ばれる値(★#20 裁定②)。アテンション中は ℓ_refAtt)。以下 ℓf と ℓ_ref は同じもの
縦:  dW/dℓ = scaleY(ℓf) / scaleY(ℓ)   … 帯の上で world 1px が何画面pxか、の逆数
     ⇒ W(ℓ) − W(ℓf) = scaleY(ℓf) · ( G(ℓ) − G(ℓf) ),   G(ℓ) = ∫ dℓ / scaleY(ℓ)
横:  screenX = CXw + conv(ℓ)/conv(ℓf) · (worldX − CXw),   CXw = camera.x + screenW/2
大きさ(立っている絵): s(ℓ) = conv(ℓ)/conv(ℓf)   … = 試作 ?objdepth の groundMatchedDepthScale と同じ値
```

#### 1-1a. 地面も物も「1本の投影の関数」から位置を出す(足し込みをやめる・★未決 #14)

**今の地面の問題(監査 A1)**: 地面のずらしは「カメラの移動量 × その時の係数」の足し込み。係数は基準行で変わるので、
**カメラが止まったまま係数だけ変わる場面**(主人公が画面の中で動く・ズームが変わる(走りの引き・ボス・`?zoomlock` の切替)・
アテンションで焦点面が運ばれる・足元が帯の境目をまたぐ段差)では、**地面は動かないのに投影した物は動く**=止まっている物が地面の上で滑る。
物の投影をどう作っても、地面が足し込みである限りこの滑りは消えない。

**方針(推薦)**: `?proj=1` の時は、**地面の模様を world に固定した1枚の布として、物と同じ投影の関数から絶対値で出す**。
- 帯 i の模様は、その帯の中央の行 ℓc の **world 位置 W(ℓc)・横の基準 CXw** から tilePosition を逆算する(足し込みなし)。
  地面も物も「world 座標 → 投影の関数 → 画面」の1本で決まるので、**係数が変わっても地面と物は一緒に動く**(滑らない)。
- 模様の world の密度 κ(world 1px あたり何テクセルか)は**定数**にする: κx = 1/(0.82·conv(t_std))、κy = 1/scaleY(t_std)。
  t_std = **ズーム1 の ℓ_ref** の行(§1-1d・定数。引きで ℓ_ref が動いても t_std はこの値のまま)。すると帯の tileScale は
  `tileScale.x(i) = 0.82·conv(t_std)·conv(t_{i+½})/conv(t_ref)`・`tileScale.y(i) = scaleY(t_std)·scaleY(t_{i+½})/scaleY(t_ref)`(t_{i+½}=帯 i の中央の行・§1-1b) になり、
  **基準行が定位置にある時は今の tileScale と同じ式**(=今の見た目)。違うのは標本の位置だけ(§1-1b で帯の上端→中央に移す=各帯の縮みが
  帯半分ぶん手前の値になる。見た目の差は帯1本ぶんの縮みの差の半分)。基準行が動いた時だけ、遠近そのものとして模様の細かさが少し変わる。
- テクスチャ座標は `W·κ` を**テクスチャ1周で剰余**して入れる(長時間でも精度が落ちない。足し込みの剰余と同じ考え)。
- `?proj=0` の時は v0.25.5732 の足し込み(`GroundScrollAccumulator`)をそのまま使う(1ビットも変えない)。

#### 1-1b. 帯は「なめらかな関数の標本」・物はなめらかな関数を引く(★未決 #15)

- **正本はなめらかな関数** `scaleY(t)`・`conv(t)`・`G(ℓ)=∫dℓ/scaleY`(新規 `src/utils/perspectiveProjection.ts`・PixiJS を読まない・
  `groundScroll.ts` の `groundRowTileScaleX/Y` を共有)。
  - G は閉じた式にならない(t^2.6 の逆数の積分)ので、**細かい表**(叩き台: 帯1本を8分割=1,440点)を台形則で作り、帯の中は1次補間。
    逆投影(画面→world)は O(1)、投影(world→画面)は単調な表の二分探索(11回)。
- **地面の帯はこの関数の標本**: 帯 i の tileScale は**帯の中央** t_i+½ の値で取る(今は帯の上端 t_i。中央にすると段差の差が半分になる)。
  位置は §1-1a の絶対値。**物は同じ関数のなめらかな値**を引く。
- **残る差(帯の中の段差)**: 帯の中では地面の横の縮みが一定、物はなめらかなので、物の足元と、その下の地面の模様の横位置に
  `(帯1本ぶんの conv の差の半分)/conv × 画面中央からの距離` の差が残る。縦は位置の差が 0.06px 以下(無視できる)。
  画面中央から 215px(縦持ちの画面の端)での横の差(試算):

  | 帯の本数(基準) | t=0.03(地平線際) | t=0.10 | t=0.20 | t=0.46(基準行) | t=0.70 | t=1.0 | t=2.0 |
  |---|---|---|---|---|---|---|---|
  | 72本(今) | 10.7px | 7.2px | 4.9px | **2.7px** | 1.9px | 1.4px | 0.7px |
  | 144本(倍) | 5.3px | 3.6px | 2.4px | **1.3px** | 0.9px | 0.7px | 0.4px |

  式: 差 = `(conv(t+1/71) − conv(t)) / 2 / conv(t) × x`(x=消失点の列=画面中央の列からの距離)。**この差は x を「ズーム後の画面px」で測れば
  ズームに依らない**(ズームは帯のローカルを一様に z 倍し、同じ画面の幅に入るローカルの幅は 1/z 倍になるので打ち消し合う)。
  上の表は x=215(ズーム後の画面px)の値。

  これは**位置の差であって溜まらない**(物が画面中央を通る時は0、端へ寄るほど増える)。地平線際は絵が小さく、地平線フェードで薄い。
  ⇒ 叩き台は**72本のまま中央標本**。実機で滑りが見えたら帯を倍にする(帯の数=TilingSprite の数が倍=180→360。負荷は §7)。
- **行の丸め(どの帯か・基準行の t)は地面と物で同じ関数を共有**する(片方だけ切り捨て/片方だけ連続、にしない)。
- 研究所の `?labpersp` は**屋内だけ**で効く(`labPerspNow = indoorMode && LAB_PERSP`)。段階1は屋内を投影しない(§1-6)ので重ならない。

#### 1-1d. カメラの基準行 ℓ_ref と基準点 W_ref(★#2・★#20 裁定の定義)

- **ℓ_ref**(帯のローカルY) = 「**既定の縦の下げ量(`CAMERA_DOWN_OFFSET_FRAC`=camdown 0.08)に、カメラのズームに連動する下げ量を足した定位置で、主人公の足元が落ち着いて立つ行**」(★#20 裁定②・2026-11-22)。
  式: `ℓ_ref = screenH × (0.5 + zoomCameraDownFrac(CAMERA_DOWN_OFFSET_FRAC, z)) + player.height/2 − farH`(z=カメラのズーム `camBossZoomRef.current.z`)。
  ズーム1では `zoomCameraDownFrac` は camdown そのもの=`ℓ_ref = screenH × (0.5 + CAMERA_DOWN_OFFSET_FRAC) + player.height/2 − farH`
  (カメラは主人公の**中心** `pcCamY = player.y + player.height/2` を画面の 0.5+camdown に置く=useGameLoop の `baseCamY`。
  足元はそこから `player.height/2` 下。縦持ちの1例: 900×0.58 + 14 − 234 = **302**・t≈0.46)。
  - **投影の関数は ℓ_ref を毎フレームの入力として受け取る**(§3-3 作る物1)。ℓ_ref は**毎フレーム、その時のカメラのズームの定位置の行**へ運ばれる
    (アテンション中は §1-6 の ℓ_refAtt を渡す)。
  - **切替のツマミ `?projzref=1|2`**(既定は2=②・§3-1)。`?projzref=1` は比べるための控え(参考・却下された①=ℓ_ref をズーム1の値の定数のまま)。
  - **含めない**: 進行方向の先読み・ボスの縦先読み(`bossCameraLeadY`)・隕石への寄せ。
    =主人公はそれらの間、1:1 から外れる(段階2で主人公を投影する時の影響は §3-3b)。
- **t_std**(模様の密度 κ の行)は**ズーム1 の ℓ_ref** の行(t_std = ℓ_ref(z=1) / stripH / 71・定数。引きで ℓ_ref が動いても変わらない)。
- **基準点** `W_ref = camera.y + farH + ℓ_ref`(world)。投影の縦は `W(ℓ) − W_ref = scaleY(ℓ_ref)·(G(ℓ) − G(ℓ_ref))`。
- **ℓ_ref が動く場面**: ズーム連動の下げ(`zoomCameraDownFrac`)は useGameLoop の**カメラのズーム** `camBossZoomRef.current.z` で決まり、
  その目標は `contextZoomTarget(0, false, ボスの目標)`=**ボス交戦の引き(叩き潰しの登場・隕石の引きを含む)と `?zoomlock` の時だけ**。
  **走りの引き(`runZoomTarget`)・群衆の引き・待機の寄りでは下がらない**(敵の数を 0 として渡しているので群衆の項は 1、走りの引きはこの式に入らない)。
  ⇒ 走り・群衆の引きでは ℓ_ref はズーム1の値のまま(主人公もそこに居る。描画だけが引く)。ボス交戦の引きと `?zoomlock` では ℓ_ref が主人公と一緒に下がる
  =**主人公は引きの間も基準行に居て s=1**、物は今の引きの意図どおり一緒に縮む。南に見える world は 0.7 で 213px・0.4 で 356px(§1-7)。
- **②の経路に要る物**(段階1で作る・§3-3 作る物11):
  - **カメラの下げ量を、useGameLoop の `camBossZoomRef.current.z` から途切れずに pixi へ渡す経路**が要る。上の ℓ_ref の式を、
    カメラ(store の `camera`)と**同じフレームの値**で pixi が引けること。
  - **store の `viewZoom` では代用できない**: `viewZoom` は変化が 0.005 以上の時だけ書かれる(store の per-frame churn を避けるゲート)ので、
    ℓ_ref が段で跳ぶ(試算: 1段で引き0.7 約3px・0.4 約10px)=地面と物が一緒に段で跳ぶ。
  - **使うのはカメラのズーム**(`camBossZoomRef.current.z`)であって、**描画のズーム `wgZoom()`(`worldGroup.scale`)ではない**。描画のズームには
    走り・群衆の引き・寄りの演出が入っているが、それらではカメラは下がらない(上の「ℓ_ref が動く場面」)。描画のズームで ℓ_ref を
    動かすと、走りの引きで主人公が基準行から外れる。
  - 細かい表(§1-1b の G)は**作り直さない**(G は帯の引数だけで決まり ℓ_ref に依らない。ℓ_ref は G(ℓ_ref)・scaleY(ℓ_ref) を引くだけ)。
- **参考(却下)・①=ℓ_ref をズーム1の値の定数のまま**(`?projzref=1` の控え): ボス交戦の引きで主人公が基準行より手前へ下げられるので、
  段階1では主人公の絵の足元に見える地面が主人公の位置からずれ(0.7で world 約69px 北・0.4で約354px 北)、足元の地面が主人公の歩く速さより速く流れる
  (0.7で縦約2.6倍)。段階2で主人公を投影すると、引きで主人公が画面の下へ沈み(0.7で画面Y 577→809・画面上の大きさ約1.67倍・南は約12px)、
  0.4では画面の外へ出る。巨大ボスの遠距離の引き(主人公とボスを同じ画面に入れる)の意図が崩れるため却下(★#20)。

### 1-2. モックのピンホールとの違い(★未決 #1「投影の式の正本」)

モック(`perspective-mock.html`)は**地面も物もピンホール**で描き直している(`z = CAMH + (py − wy)`、`scale = F/z`、地面も走査線ごとに同じ式)。
今のゲームの地面は**ピンホールではない**:

| | 横(conv) | 縦(scaleY) | 地平線までの world 距離 |
|---|---|---|---|
| ピンホール | 地平線からの距離に比例(奥=0) | conv の2乗に比例 | **無限**(地平線=無限遠) |
| 今の地面 | 直線だが奥で 0.10 に下駄 | t^2.6+下駄0.055(手作りの値) | **有限**(試算で足元から約 630 world px・ズーム1) |

- **案A(推薦)**: 今の地面を正本にし、物を地面の表に合わせる(§1-1)。地面の曲線(縮み方)は今のまま(`?proj=1` で変わる点は §1-1c の表の5点だけ)。
  **なぜ面白いか**: 社長が何度も詰めた地面(gcurve 2.6・台形 0.10)の手触りを保ったまま、物が地面に「乗る」。
- 案B: 地面もピンホールに描き直す(なめらかな関数を conv=奥0の直線、scaleY ∝ conv² に替えればピンホールになる)。
  モックと同じ見え方。地面の見た目が変わる(奥の圧縮が弱まる/地平線が無限遠になる)。
- どちらでも**仕組みは同じ**(「なめらかな関数 → 地面の帯は標本・物はなめらかな値」)。B は関数を替えるだけ。
  ⇒ 段階1は A で作る。B は `?projpin=1` のツマミで並べて見せられる(実装コストはほぼ同じ。**ツマミは段階1の外**=★#1 の案Bを見せる時に作る・§3-1)。

### 1-3. 浮き(高さ)

- 立っている絵の高さ方向(頭・武器・頭上マーク・跳び・浮遊)は**立っている絵と同じ倍率 s(ℓ)** を掛ける
  (足元の点を投影 → そこから上へ `高さ × s`)。モックと同じ。地面の縦の詰め(scaleY)は**地面に寝ている物にだけ**効く。
- ★未決 #6「浮きの倍率」: 高さを s(横の縮み)で縮めるか、地面の縦の詰め比で縮めるか。推薦は s(立っている物は縦に潰れない)。

### 1-4. 地面に寝ている形(円・帯・扇・影・水たまり)

- **形の各頂点を投影する**(中心だけ投影して楕円にするのは不可=半径の大きい円ほど奥側と手前側の縮みが違う)。
  円は多角形(叩き台 48 角)、帯は長手方向に分割した四角の列、扇は弧を分割。
- 焼いた素材のスプライト(予告の輪 `fx/telegraph-ring`・帯の素材・影)は**メッシュ(格子の頂点を投影)**で描く。
  前例: 台形の影がすでに `PerspectiveMesh` を使っている(pixiScene で作っているのは2箇所=影の `drawShadowSlot` と計測用の probe)。
- **投影は単調な1対1の写像**なので、「world で円の内側 ⇔ 画面で投影した形の内側」が成り立つ=**赤い予告と判定の一致は投影で崩れない**
  (崩れるのは多角形の弦の誤差だけ。叩き台 48 角で半径 300px の円の弦誤差は 0.6px)。

### 1-5. ズーム・シェイク・オフセットとの関係

- 投影は **worldGroup のローカル(ズーム前)で行う**。ズームは今どおり worldGroup が後から一様に掛ける=地面と同じ順序なので一致する。
  今の `depthScreenY`(ズーム後の画面Yで遠近を決める v8 の補正)は**不要になる**(地面はズーム前のローカルで遠近を持つため)。
- シェイクは今どおり `world` / `groundBase` の位置に足されるので、投影の外側で一律に効く(投影の式に入れない)。
- 実装の形: 物は今どおり `world`(カメラ相対)の子に置き、**置く座標だけを「表示用の world 座標」に差し替える**:
  `表示x = CXw + s(ℓ')·(worldX − CXw)`・`表示y = camera.y + farH + ℓ'`(ℓ' = 投影後の帯のローカルY。farH を忘れない)
  (前例: 研究所の `labProjectFootY` が縦だけ同じことをしている)。zIndex(前後の並び)は**元の footY のまま**
  (投影は縦に単調なので並び順は変わらない)。
- 寄りの遠近(`syncZoomWarp`・worldGroup への射影フィルタ)とは**重ね掛け**になる(★未決 #13)。
- 引き 0.4 の時、地面は帯を 180 本(t=2.5)まで敷いている。表も同じ範囲を持つ。

### 1-6. 投影が効く場面・基準の決め方・定義域の外(★未決 #16・#17・#18)

- **効く場面(段階1)**: **屋外で地面の帯(groundBase)が見えている時だけ**。次は段階1では投影しない(今の描き方のまま):
  洋館の通路(`corridorMode`)・屋内(`indoorMode`。`?labpersp` はここだけで効く)・**研究所テーマ**(`stageTheme==='lab'` の屋外。
  帯の絵が研究所の床に差し替わる)。
  - **場面の切替は瞬時でよい(コードで確認)**: `indoorMode`・`corridorMode`・`stageTheme` を書いているのは出撃の始まりの `resetGame` の1か所だけ
    (gameStore の `resetGame` が返す初期値。ラン中に書き換える所は無い=読むだけ)。つまり屋内外・洋館の通路・研究所テーマは**ラン中に切り替わらず**、
    切替は必ず出撃の画面遷移(前の画面が続いていない所)の陰で起きる。投影の強さを慣性で運ぶ仕組み(旧 §10 B6 の候補)は作らない。
    将来ラン中に切り替わる場面を足す時だけ、B6 を開き直す。
- **基準(1:1 の行)の決め方(★#2「1:1の基準行」・★#17「主人公が画面外の時の基準」=どちらも裁定済み)**:
  - 通常: **基準点 W_ref = camera.y + farH + ℓ_ref**(§1-1d・★#2 裁定)。主人公の位置は見ない。
  - **アテンション**(`attention.zoomToUnity`): 新しい値 **W_refAtt** を作る=**カメラの基準点 W_ref を、今の `depthRefY` と同じ包絡線
    (`attentionZoomEnvelope`・9766行付近)で注目点 `a.y` へ運ぶ**: `W_refAtt = W_ref + (a.y − W_ref) × 包絡線`。
    投影はこの W_refAtt を基準点に使う(地面も物も同じ関数=一緒に注目点を等倍にする)。
    **基準行もそれに合わせて運ぶ**: `ℓ_refAtt = W_refAtt − camera.y − farH`(W_refAtt が写る帯のローカルY)。投影の関数(frame)には
    **基準点と基準行を必ず組で渡す**=ふだんは (W_ref, ℓ_ref)、アテンション中は (W_refAtt, ℓ_refAtt)。片方だけ差し替えると
    `W(ℓ) − W_ref = scaleY(ℓ_ref)·(G(ℓ) − G(ℓ_ref))` の両辺がずれ、注目点が等倍にならない。今の `depthRefY`(主人公の足元+包絡線)は
    `?proj=0` の旧い遠近のためにそのまま残す(投影では使わない)。
  - **主人公が画面外の場面**(登場のヘリ・エンディング・カメラが主人公から離れる演出): 基準点はもともと主人公を見ないので、特別扱いは要らない(★#17 裁定)。
  - 基準行の t も**地面と物で同じ関数**から出す(§1-1b の丸めの共有。ℓ→t の式は §10 B8)。
- **地平線より北(定義域の外・★未決 #18)**: 今の地面は地平線が**有限の距離**(試算で足元から約 630 world px・ズーム1。ボス交戦の引き0.4で約8,060px=★#20 裁定②)。
  それより北の world は投影の定義域の外。推薦は**描かない**: 地平線フェード(`horizonActorAlpha` を投影後のYで)で地平線の手前で消し切り、
  定義域の外は alpha 0・カリングで外す。**絵を地平線に貼り付けて並べない**(縮まないまま積み上がって嘘になる)。
  - **「描かない」のは北(地平線より上)だけ。南の端は描く**: 足元が画面の下端より南(手前)にあっても、絵が上へ伸びて画面に掛かる物
    (手前の大きな木・建物)は見えていなければならない。南は**投影の表を帯の範囲の外へ延長**して値を返し(なめらかな関数をそのまま外へ伸ばす。
    発散・逆転しないことは §10 B1 で固定)、カリングの**南の余白を「絵の高さ×s」の分だけ広げる**(§3-3 作る物4)。南で「描かない」を返さない。
  - 巨大な1枚(城・病院・武器庫などの建物)は**足元が定義域の中なら置く**(絵が地平線より上へ伸びるのは立っている物として正しい)。
    足元が外へ出たら同じくフェードで消す。

## 3. 移行の方式(段階)

### 3-1. ツマミ

- **`?proj=1`** の時だけ新しい描き方。**省略時は今と1ビットも変わらない**(既定OFF)。
- 段階ごとに通す範囲を絞るツマミは作らない(段階はコードの進み具合で決まる。1本のツマミで「今入っている段階まで全部」)。
  段階1で置くのは次の3本:
  - `?projfar=`(★#4「描く距離の上限」)。
  - **`?projzref=1|2`**(★#20「ズーム中の基準行」・**既定は2=②**(裁定済み)。§1-1d・§3-3 作る物11)。2 は ℓ_ref を毎フレーム、ズームの定位置の行へ運ぶ。
    1 は比べるための控え(参考・却下された①=ℓ_ref をズーム1の値の定数のまま)。受け入れ条件は②で確かめ、①は合否に使わない。
  - **`?projaudit=1`**(DEV限定の計器: 位置の差・重なり率・通し漏れ=§3-3 作る物8〜10・§3-4)。
  - **`?projpin=1`(★#1「投影の式の正本」の案B)は段階1の外**(★#1 の案Bを社長に並べて見せる時に作る)。
  - **`?projref` は不要**(★#2「1:1の基準行」は裁定済み=カメラの基準行。作らない)。
- **`?proj=1` の時は、objdepth の地面の傾きも無効**: `?objdepth=2` は地面の既定値 `GROUND_TILE_SCALE_Y_FAR`(gfar)・`GROUND_TRAPEZOID_FAR`(g3dfar)を
  傾き用の値(`OBJ_DEPTH_TILT_GFAR`・`OBJ_DEPTH_TILT_TRAP_FAR`)へ差し替えるが、`?proj=1` ではこの差し替えをせず今の既定(0.055・0.10)を使う
  (★#19「ツマミの同時指定の優先」=`?proj` が勝つ、の中身。`?gfar=`・`?g3dfar=` を明示した時はそれを使う)。

**順番の理由**:
- 地面と置き物は**動かない**ので「地面と同じ速さで流れるか」が一番純粋に見える(社長の最初の観察そのもの)。
- **2〜4 は揃うまで既定に出さない**: 動くもの(2)だけ投影して赤い予告(4)が旧いままだと、**赤い予告と敵がずれる**
  (=「赤いのに当たらない/赤くないのに当たる」に見える)。逆も同じ。だから 2 と 4 は**同時に既定へ出す**。
- 点で出る演出(3)は「派手さの絵」(判定を持たない)なので、ずれても嘘にならない=形(4)の後でよい。
- 高さ(5)は点(3)が入った後に、点の上へ「高さ×倍率」を足すだけ。
- 逆向きの計算(6)は、投影が全部入ってから合わせる方が手戻りが無い。

### 3-2b. 省略できる所(方針・他のゲームの通例)

投影は「全部を厳密に」通すと件数が爆発する(§2-0)。他のゲームの通例に倣い、**見た目に効かない所は省略する**。
省略は**見た目の判断**であって判定には触れない(赤い予告の形だけは省略しない)。

| # | 省略 | 理由 | 効く段階 |
|---|---|---|---|
| ① | **演出の粒子(血・火の粉・破片)は出る位置だけ投影し、その後の飛び方は画面のまま** | 短命なので、飛んでいる間の地面との滑りは見えない | 3 |
| ② | **ダメージの数字・HPバー・名前など読ませる物は、位置だけ投影し大きさは縮めない** | 読みやすさ優先(奥の数字が読めないと意味がない) | 2・3 |
| ③ | **画面の端の判定(描く範囲・湧き・回収)は台形を正確に追わず、台形を囲む長方形で広めに取る** | 端の数px の取りこぼしより、計算と判定が単純な方が壊れない。広めに取る=画面に出るはずの物は必ず描かれる | 1(カリング)・6 |
| ④ | **研究所の壁・洋館の通路は、見た目に破綻が無ければ合わせない(確認だけ)** | すでに独自の疑似3Dを持ち、完結している | 8 |
| ⑤ | **照準の逆計算はPCのマウスだけ** | スマホはスティックの方向で動く(画面の位置→world を引かない)。逆計算が要るのはマウスで狙う所だけ(components で camera を読むのは `MouseControls.tsx` の1ファイル) | 6 |
| ⑥ | **足元の小さな楕円の影は、物と同じ倍率で潰すだけ**(頂点ごとには投影しない) | 足元の小さな楕円は、頂点ごとの歪みが見えない。影の付け根=物の投影点・大きさ=物の倍率。**地面に長く伸びる影(PerspectiveMesh の台形)はこの省略に入らない**=4隅を投影する(先端が地面と別の速さで流れると影だけ滑るため) | 1・2 |

- **省略しない物**: 赤い予告・攻撃範囲・判定を持つ床(段階4)。**判定と厳密一致**の掟があるので、必ず頂点ごと。
- 省略した物で破綻が見えたら(社長の実機)、その物だけ厳密に戻す。

### 3-3. 段階1「盤面と置き物」(最初に入れる)

**通す物**:
- **盤面**: 地面の帯。投影の関数(§1-1)から帯の値を標本で取り、模様を絶対値で出す(§1-1a・§1-1b)。`?proj=1` で見た目が変わる点は §1-1c。
- **動かない置き物(点で置く)**: 木・街/雪/ステージ5の置物・花・松明(炎を含む)・壊せる置き物・城・POIの建物の絵
  (病院/武器庫/交番/祠/隠しPOI)・墓・錬金の岩。
- **松明に付いている光3枚**(`light`・`lightBokeh`・`reflection`): 台座の Container とは別に groundLayer へ置いているので、台座を投影しても付いて来ない。
  **台座と同じ点として投影して置く**(台座の足元を投影し、炎の高さ・映り込みのずれ `3*d` 等のオフセットは s 倍して足す。大きさも s)。
  松明の光が落とす**床の光だまり**(`torchPoolReqs`)はこれとは別物で、床の光だまり全般と一緒に段階4(下の「入れない物」)。
- **地面に寝ている置き物**(静的・判定なし): **街の置物の地面デカール**(`syncCityProps` の `def.decal`=groundLayer に寝かせた絵)と
  **建物の入口の地面の帯**(`drawPoiThreshold`=病院・武器庫・交番の入口に横に引く光の線)。**頂点ごとに投影する**(デカールは絵の4隅をメッシュで、
  入口の帯は横の線なので**両端を投影**して結ぶ。線の太さは s)。中心だけ投影すると地面の上で滑るので、点ではなく形として段階1に入れる。
- **置き物の影・映り込み**: 本体と別の速さで流れると影だけ滑るので本体と同じ段階で通す。
  - 足元の小さな楕円の影=方針⑥(付け根を本体の投影点に、大きさを本体の倍率で潰すだけ)。
  - **地面に伸びる影(`PerspectiveMesh` の台形・絵の高さの0.85倍)は、world で計算して4隅だけを投影する**(作る物6):
    影の形(根元・向き・長さ・幅=`horizontalShadowCorners`)は**今どおり world で**出し、**`setSilhouetteMeshCorners` の中で `mesh.setCorners` に
    渡す直前に4隅を投影**する。光源との距離・向き(どの光がどの物に影を落とすか・影の向き)は **world のまま**。
    影の間引き(画面外の影を描かない)は**可視域の台形を囲む長方形**(`visibleWorldQuad` の外接矩形・方針③)で行う。
  - **地面の映り込み(`syncGroundReflections`)**: **本体と同じ点で置き、大きさは s**(本体の足元を投影した点を映り込みの付け根にし、
    上下反転の絵の大きさも本体と同じ s。映り込みのずれのオフセットは s 倍して足す)。本体と別の点で置くと映り込みだけ地面の上で滑る。
- **場面**: 屋外で地面の帯が見えている時だけ(§1-6)。屋内・洋館の通路・研究所テーマは段階1では今のまま。
- **入れない物**: 静的でも**形を持つ床の印**(試練/クエスト/帰還/拠点の円・エリアのテープ・水たまり・月だまり・光だまり=松明の光だまりを含む)は段階4
  (頂点ごと)。研究所の壁・什器は段階8(研究所テーマは段階1の対象外)。ステージの枠は画面固定(対象外)。

**作る物**:
1. `src/utils/perspectiveProjection.ts`(純関数・PixiJSなし): 帯パラメータ → なめらかな関数 `scaleY/conv/G` と細かい表(§1-1b)、
   `project(wx, wy, frame) → { x, y, s, alpha }`、`unproject(sx, sy, frame) → { x, y }`、`visibleWorldQuad(frame)`(画面の四隅の逆投影=台形。
   **上の辺は「地平線」と「描く距離の上限」の手前の方で切る**=定義域の外を可視域に入れない)。`frame` は次を持つ:
   - **基準点と基準行の組 (W_ref, ℓ_ref)**(最初から毎フレームの入力として受け取る。**アテンション中は (W_refAtt, ℓ_refAtt)**=§1-6。片方だけ差し替えない)。
     ℓ_ref は**ズーム連動の下げに付いて動く値**(★#20 裁定②・`?projzref=2`=既定・作る物11)。控えの `?projzref=1` では毎回同じ値(アテンション中を除く)。
     ほかに camera・farH・screenW/H・曲線の引数。
   - **worldGroup のズーム・支点・パン**(`worldGroup.scale` と `worldGroup.position`=sync で `scale.set(zoom)`・`position.set(pivotX·(1−zoom) − panX, pivotY·(1−zoom) − panY)`
     と入れている値)。`project` の出力は worldGroup のローカル(ズーム前)のままでよいが、`unproject` と `visibleWorldQuad` は画面から逆に引くのでこれが要る。
   - **`unproject(sx, sy)` の入力は「ズーム後の画面px」**(canvas の論理px=マウスの位置や画面の四隅)。中で worldGroup のズーム・支点・パンを外してから、
     帯のローカル → world へ戻す。
2. pixiScene: `updatePerspectiveGround` の帯ループを、`?proj=1` の時は**§1-1a の絶対値**で描く(足し込みを使わない)。
   同じ純関数の値をフレームの投影状態として持つ(地面と物で同じ関数・同じ基準行・同じ丸め)。
3. 置き物の各関数: 置く座標を `project` の結果に、`depthScale` を `s` に差し替え(`?proj=1` の時だけ)。
   地平線フェード・手前フェードは**投影後のY**で引く。
   - **作成時に1回だけ位置を入れている関数は、毎フレーム置き直しに変える**(確認済み: `syncTrees` は `sprite.x/y` を作る時に1回だけ入れ、
     毎フレームは大きさだけ更新している。投影後の位置はカメラで毎フレーム変わる)。他の置き物の関数も着手時に同じ形を洗う。
   - **描く距離のフェード(★#4「描く距離の上限」)**: 主人公から北へ world で **1,200px→1,500px の間で alpha 1→0**(叩き台・`?projfar=`)。

### 3-4. 通し漏れを機械で見つける仕組み

1. **実行時の計器(DEV限定・`?proj=1&projaudit=1`)**:
   - **置く窓口で生成元の印を付ける**: 投影の窓口(`placeProjected(obj, wx, wy, origin)` 等)が、置いた表示物に「どの関数が置いたか(origin)」と
     フレーム番号の印(WeakMap)を付ける。
   - **投影した Container の子は通ったとみなす**: 例えば木の Container を投影で置いたら、その中の葉・影・炎は個別に印を付けなくてよい

   - 免除は「画面固定の層」と、明示的に `projExempt` の印を付けた物(方針①②⑥の省略を含む)だけ。
   - まだ通していない段階の物は「未投影」に出て当然なので、計器は**その段階の対象の台帳(関数の一覧=§2-1 の段階の列)**で絞って数える。
     **段階ごとに対象の未投影が 0 になったら次へ**。
2. **ソースの番人テスト**(前例: `bakeRenderGuard.test.ts`・`extractGuard.test.ts` の流儀・ソースを文字列で検査する):
   - 移行済みの関数の中で、`depthScale(` を直接呼ぶ箇所が `?proj` の分岐の外に残っていないか(移行が進んだ関数を台帳に足す)。

     投影を通す前提で書かれていない式が残ると、その物だけ旧い位置へずれる。
   - **uiLayer に world の位置から置いている物**(例: constructor で置く照準の `reticleGfx`・救助の汗マーク、updateLabDarkLights・updateLabVisibility・ensureSpeedLines・drawBossDistLabel 等)を拾う:

     (載っていない関数が増えたら落ちる)。
3. **純関数のテスト**: 受け入れ条件2・3、投影と逆投影の往復(誤差 1e-6)、単調性(北ほど上・**地平線より北**の定義域の外は「描かない」を返す。

   地面の模様の投影位置と物の投影位置の差(§1-1b の表の範囲)。

## 5. 既存の掟との関係

- **Y方向5つのチェック**:
  1. 地平線フェード: 残す。**投影後のY**で引く(投影では地平線が有限の距離=§1-2 にあるので、フェードが「描く距離」の自然な終わりになる)。
  2. 帯の外の減光(`LAB_CORRIDOR_Y_LIMIT_PX`・world): world のまま残す(判定に近い意味=world で決まる)。見た目の境目の位置は投影で動く。
  3. 擬似遠近スケール(`depthScaleEnemy` 等): **投影の s に置き換わる**(§6)。
  4. 可視域: 台形になる(§4)。ズーム倍率と合わせて `visibleWorldQuad` で出し、判定には台形を囲む長方形を使う(方針③)。
  5. 移動可能帯: 判定は不変。帯の境目を示す絵(テープ等)は投影する。
- **ズーム引き 0.4**: 表は帯と同じ 180 本(t=2.5)まで持つ。北の地平線は ★#20「ズーム中の基準行」裁定②で 約8,060px まで遠のくので、
  描く距離の上限(★#4「描く距離の上限」・1,200→1,500px のフェード)で切る。受け入れ条件8。
- **PC横長**: 論理の画面高が低い(farH の下限 168 が効く)ので帯の縮み方がスマホと違う=**投影もスマホと違う結果**になる。
  既定OFFの間は `phone-guard`/`pc-guard` は変わらない。段階2でアクターを通すと `pc-guard` の「プレイヤー・軍人・敵の大きさの比」
  (6%)が行によって変わるので、比べる場面(同じ world 距離に置く)を決め直す必要がある(段階2の受け入れで扱う)。
- **赤い予告の4つの掟**: 時間の掟(②出る=溜め開始 ③消え切る=当たる ④通る技は当たり得る間ずっと赤)は投影と無関係=そのまま。
  形の掟「赤い予告は判定と厳密一致」は、**頂点投影なら保たれる**(§1-4。投影は1対1なので内外が入れ替わらない)。
  **中心だけ投影して円のまま描くのは違反**(奥側の縁と手前側の縁で縮みが違うので、判定とずれる)。段階4の発注文に必ず写す。
- **攻撃ヴィジュアルの2分類**: 危険を伝える絵(予告・武器・斬撃の弧)=投影の形に揃える。派手さの絵=点で置いて倍率を掛ければよい(形の厳密さは要らない)。
- **慣性 MUST**: 投影そのものは動きを足さない。基準点は ★#2 裁定でカメラに付く行(主人公の動きで揺れない)。基準点・基準行を動かすのは
  アテンション(包絡線で運ぶ)と、★#20 裁定②のボス交戦の引き・`?zoomlock`(カメラのズーム `camBossZoomRef` の速度つきの追従に付いて運ぶ)だけで、
  どちらもパッと切り替えない(段で跳ばないよう `viewZoom` のゲートつきの値は使わない=§1-1d)。場面(屋内外・洋館の通路・研究所テーマ)は出撃の始まりで決まりラン中に切り替わらないので、
  切替の動きはそもそも画面に出ない(§1-6)。描く距離の境目も距離フェード(★#4)。

## 7. 負荷(見込み)

**段階1: 3/10**(帯は72本のまま)。全段階: **4/10**。
- 根拠: 増えるのは北に見える world の置き物の本数で、置き物のスプライトは実測で「強glow以外は事実上ただ」(CLAUDE.md の実測表)。高いのは投影影の
  走査だけで、その上限は今と同じ22体に固定する(条件4d)。北の見える距離(§1-7)は、★#20「ズーム中の基準行」裁定②で
  **ボス交戦の引き0.4なら北 約8,060px**(0.7で 約1,970px)まで地面に乗る。描く距離の上限(1,500px・★#4)で切るので **3/10**
  (**切らなければ 8/10**=描く距離の上限は負荷の安全策として必須)。ズーム1と走り・群衆の引きでは地平線フェードが先に切る。
- シミュレーション: 0(ゲーム側は1行も変えない)。
- 描画(CPU): なめらかな関数の表(叩き台1,440点)は**帯の引数が変わった時だけ作り直す**(毎フレームは「変わったか」の比較だけ・§10 B7。
  作り直す時も台形則の足し算1,440回=帯ループと同じ桁。★#20 裁定②で ℓ_ref が毎フレーム動いても表は作り直さない=G は ℓ_ref に依らない)。
  投影1点=割り算と二分探索11回。置き物・アクター合わせて数百点/フレーム=無視できる。
  **形の頂点投影**は円48点×同時の形の数(叩き台で数十)=数千点/フレーム=軽い。メッシュの頂点更新は前例(PerspectiveMesh の影)と同じ桁。
- 描画(数): **見える world が北に広がる**(§1-7: ズーム1で北 302→632px・ボス交戦の引き0.7で 490→約1,970px・引き0.4で 846→約8,060px。奥ほど左右にも広い=地平線際では画面幅の約5倍の world が横に入る)ので、描く置き物の本数が増える。**これが一番の負荷要因**。
  木は区画ごとに置かれるので、見える world の面積にほぼ比例して増える(試算: ズーム1で北側の面積が**約4.8倍**=奥行き約2.1倍×奥ほど左右に広い。
  木の本数も北側だけで最大それくらい。地平線際は地平線フェードで薄く・小さい)。地平線フェード(定義域の外は描かない・★#18「地平線より北」)で抑え、
  引きでは描く距離のフェード(1,200→1,500px・★#4)で抑える。
- 置き直し: 作成時に1回だけ位置を入れていた置き物(`syncTrees` 等)を毎フレーム置き直す=位置の書き込みが置き物の数だけ増える
  (1点=代入2回。数百本でも無視できる)。
- 地面: §1-1a の絶対値は帯ごとに割り算と剰余が数回増えるだけ(今の帯ループと同じ桁)。帯を倍(★未決 #15)にすると TilingSprite が
  180→360 本=描画の呼び出しが倍(ベンチで確かめてから)。
- **投影影(`syncLocalEventLighting`)**: 強glow1個ごとに世界中の物を走査して影を描き直す=実測で glow 1個 ≈ 2ms(CLAUDE.md の実測表)。
