## ER抽出による間合いAIの再定義(社長指示2026-07-30「エルデンリングのボスの技・間合いから抽出して最適解を再定義」)

### ERボスから抽出した5原則(設計チャットの抽出)
1. **技が間合いを決める(逆ではない)**: ERボスは「次にやる技」を先に決め、その技の発生距離へ自分から
   移動して振る。うろついて「届いたら振る」ではない。移動は常に何かの技のための移動。
2. **ストリング(連段)と休符のターン制**: 攻めは1〜4連の固まりで来て、終端に読める休符=プレイヤーの
   ターンが来る。難度はストリング長と休符の短さで調整される(HPフェーズで加速)。
3. **主戦帯の維持**: ERボスの中立姿勢は「中間距離で横に回りながら(ストレイフ)出入りする」。
   密着張り付きも遠距離待機も例外状態で、すぐ主戦帯へ戻る。
4. **下がりは逃げではなく仕込み**: 後退は短く・斜めで、**終端に必ず牽制技がセット**になっている
   (下がって撃つ/下がって跳び直す)。「下がって終わり」の受動的な絵を作らない。
5. **懲罰の規則化**: 遠くで回復/射撃=即ギャップクローザー、休符中の密着継続=AoEで剥がす、
   同じ位置取りの長居=軸ずらし。プレイヤーの特定行動に特定の答えを返す=「見られている」感。

### 本作への写像(城ボス基本5技・画面内完結280px・実測82.3%が320px以内)
- **主戦帯=近120-300**(実測の主戦場と一致)。ボスの中立=この帯で±30〜60°の弧ストレイフ。
- **状態文法(旧5状態案の改訂)**:
  1. **意図先行抽選**: 現在ゾーン重み表(§確定仕様)での抽選を「フォールバック」に降格し、一次抽選は
     **意図テーブル**=HPフェーズ+直前のプレイヤー行動(回復/遠距離攻撃/密着継続)から技を選ぶ→
     **その技の開始帯へ自分から移動**(上限2秒・間に合わなければ現在ゾーン表で差し替え)。
  2. **ストリング化**: 既存followup連携(40/60/70%)をERの連段として維持し、**ストリング終端に
     休符0.8〜1.6秒**を明示挿入(=カウンター/クリの主窓)。休符中は弧ストレイフで主戦帯を維持。
  3. **下がり=仕込み**: 後退は最大280px(画面内完結)・斜め弧・**終端に牽制(bolt/sweep)を予約**。
  4. **懲罰3本**: (a)距離300+でプレイヤーの回復/射撃を2秒検知→dash/jump即時 (b)休符中の密着継続→
     stomp優先ブースト (c)同角度長居→ストレイフ反転。
  5. **遠600+は「追いつき帯」のまま**(dash70の既存重み維持)=逃げ切り不可の既存意図を保存。
- **実装形**: giantScript純関数の拡張(意図テーブル/休符タイマ/懲罰トリガ=全て純関数+テスト)。
  useGameLoop配線は薄く。着地後に既存の距離プローブで「帯滞在・ストリング率・休符率」の前後比較。
- **数値は全て叩き台**(休符0.8-1.6s/検知2s/弧30-60°)・実機調整前提。
- 状態はPROJECT_STATUS.mdを見る。

## 【確定・社長指示2026-08-01】難易度を「操作を奪う」方向で作らない

> 基本的に**移動不可の方にいかないで、ただの理不尽なので**。なにか大技の演出とかそう言う時はいいけど、
> **普通に移動不可エリアに移動されたら何もできない**。

### 禁止(以後、この方向の提案自体をしない)
- プレイヤーを**掴む / 拘束する / スタンさせる / 凍らせる / 移動速度を落とす**技を**足さない**。
- 「避けられないから難しい」ではなく「**選択を間違えると痛い**から難しい」を作る。
- 例外は**大技の演出**(短い・演出として意味が読める・頻発しない)。**通常の攻撃手段にはしない。**

### 現状(v0.25.2615時点の実測・この方針をほぼ満たしている)
プレイヤーの操作が不随意に奪われる経路は**2つだけ**:

| 経路 | 長さ | 評価 |
|---|---|---|
| 被弾ノックバック(`PLAYER_KNOCKBACK_MS`) | **260ms** | 「殴られた手応え」の範囲。操作不能とは呼ばない |
| 洋館の走り込み入場(`corridorRunInActive`) | 約6秒 | **演出**(=許容される例外)。v0.25.2611のすりぃエル操作不能事故の元凶でもある |

`isInputLocked()` = `isPaused || health<=0 || corridorRunInActive || isGameTimeStopped()`。
その他の「入力を無視する」箇所(刀の一閃ダッシュ・四神舞のスライド・スケーターの急停止)は
**全てプレイヤー自身が出した行動**なので対象外。

**敵側にプレイヤーを縛る手段は現在1つも実装されていない。この状態を維持する。**

### 難易度を上げてよい方向(3つだけ)
1. **時間で難しくする** — 弾を速く / 予告を短く / ディレイで読みを外す(公平性の下限は守る)
2. **空間で難しくする** — 逃げ場を塞ぐ / 面で殺す / 収束する散弾
3. **選択で難しくする** — 走るかカウンターか、間違えると痛い

**「移動を奪う」は楽に難易度を上げられてしまう逃げ道なので、構造的に塞ぐ。**
この縛りがあるからこそ、弾速と面の設計(下記★未決)が意味を持つ。

## ★未決(社長判断待ち): 敵弾の「余裕倍率」の再設計

### 事故の構造(なぜ「簡単に避けられる」数字のまま放置されたか)
1. **弾速をプレイヤーの速度と比べた記録が一度も無い。** 200/230/300/320/380 という値は単体では
   速い/遅いを判断できない。**104.4(プレイヤー速度)で割って初めて意味が出る**。
2. **割る式が v0.25.2614 まで存在しなかった。**「避けやすさ」を言語化する手段が無かった。
3. **数値が他所から流用された**(ミーミルの牙=半径92と同じ病気)。
4. **測っていた指標がズレていた。** 帯別滞在率・技の発動割合は測っていたが
   **「その攻撃は注意しているプレイヤーに当たるのか」を測る指標が無かった。**

### 物差し(v0.25.2614で導出)
```
見てから避けるのに要る最小時間 = 反応 0.25s + 横移動 0.20s = 0.45s
  横移動 = (弾幅14 + 自機幅28) ÷ 2 = 21px ÷ 104.4px/s
余裕倍率 = 弾の到達時間 ÷ 0.45s
```

距離300pxでの現状:

| 弾速 | 到達 | 余裕倍率 |
|---|---|---|
| 200(現行・最遅) | 1.50s | **3.3倍** |
| 300(現行・標準) | 1.00s | **2.2倍** |
| 380(現行・最速) | 0.79s | **1.8倍** |
| 600 | 0.50s | 1.1倍(=ギリギリ) |
| 670+ | <0.45s | **避けられない**=カウンター必須 |

**現行の敵弾は全て「余裕1.8〜3.3倍」に固まっている**=遠距離攻撃が構造的に脅威になっていない。

### 提案(叩き台・全て実機調整前提)
**「全部ギリギリ」にはしない**——憲法第4条(初心者ゾーン不可侵)に抵触し、緩急が消えてリズムが死ぬ。
社長の設計「1発目は避けられる/2発目はカウンター必須」も、1発目が避けられるから成立する。

| 対象 | 余裕倍率 | 弾速の目安 |
|---|---|---|
| 序盤の雑魚 | 2.0〜2.5倍 | **現行のまま(触らない)** |
| 中盤ボス | 1.4〜1.8倍 | 400〜500 |
| 終盤・隠しボス | 1.0〜1.2倍 | 550〜650 |
| ストリングの2発目 | 1.0未満 | 670以上=カウンター必須 |

### 機械化(採用されたら同コミットで入れる)
全ての敵の飛び道具の余裕倍率を計算し、**想定した帯に入っているかをテストで検算する**
(`bodyCenteredAoe.test.ts` と同じ作法)。以後、弾速を触ると帯から外れた瞬間にテストが落ちる。

### 併せて★未決: `Projectile` 型の表現力
現在の `Projectile` は `direction`(固定)と `speed`(一定)しか持たない=**「まっすぐ・等速」しか
表現できない**。加速・旋回・寿命での変化・着弾後に残る、が持てない。ホーミングは型の外の例外実装。
**ボスの技を作り直しても、この型のままでは遠距離の手触りは変わらない。**
