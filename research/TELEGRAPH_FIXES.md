## 1. 突進まわり(社長の指定 1h・1i・N01・N02)

突進は4件とも同じ形の問題なので、**1つの純関数で全突進の予告の位相を決める**設計にする。

### 1-0. 共通の型「突進の予告=走者が食う線+斬り抜けの帯」

**新しい純関数**(`src/utils/dashTelegraph.ts`・描画は読むだけ):

```
dashTelegraphPhase({ windupStart, moveStart, strikeStart, strikeEnd, now,
                     from, arrival, runnerPos }) → {
  line:  { p, er } | null,          // 通り道の線(幅は今の細い線のまま)
  band:  { prog, live, liveAlpha } | null,   // 斬り抜けの帯(斬り抜けを持つ技だけ)
}
```

- **線(通り道)**: 溜めの間 `p = (now−windupStart)/(moveStart−windupStart)`・`er = 0`(=今のミゲル/ウリと同じ「進行同期で伸びる」)。走りの間 `p = 1`・`er = 走者が進んだ割合`。**`er` は時刻ではなく走者の位置から引く**=`dot(runnerPos−from, dir)/|arrival−from|`(0〜1にクランプ)。トールは `airHopEase01` で加減速して走るので、時刻から引くと線と体がずれる(`uGL:9349-9350`)。位置から引けば全突進で同じ式が使える。
  - 走りが途中で止まった(壁・カウンター・州の打ち切り)時は、残りを既存の「中断の型」(灰へ落として根元へ縮める=`bossBiteEndFrame` `pS:16413-16426` の `BOSS_BITE_CUT`)で消す。パッと消さない(慣性)。
- **帯(斬り抜けの判定)**: 溜めの頭から出し(②)、`prog = (now−windupStart)/(strikeStart−windupStart)` で**溜め+走りの全体**を1本の流星にする(③=消え切った瞬間に斬り抜けの判定が始まる)。斬り抜けの判定は `strikeStart..strikeEnd` の毎フレーム生きているので、その間は**一様の帯**(`live`)にし、`liveAlpha = 1 − ease(経過/斬り抜けの尺)` で**判定の終わりにちょうど0**にする(④・慣性。前例=懲罰狙撃の発射中 `0.35*life` `pS:27877`)。
  - 帯の寸法は**判定と同じ定数を読む**(下の各技の表)。描くのは `zoneCapsuleTick`(`pS:33090`)経由(`drawAngelZoneCapsule` を素で呼ぶと最後のフレームが描かれない旧不具合が戻る=`pS:32959-32960` の注意書き)。
- **体幅の帯は出さない**(社長が却下した見せ方)。走りの間に見えている赤は「まだ食われていない細い線」と「斬り抜けの帯」だけ。

**この型が掟を満たす理由**:
- ①: 線は伸び切った後に走者が根元から食い切る=流れて消え切る。帯は外(始点)→終点へ窓が流れて消え切る(帯窓)。
- ②: 線も帯も溜めの頭から出る。
- ③: 線は走者が到達点に着いた瞬間に食い切られる=体当たりが終わる時刻。帯は斬り抜けの判定の最初のフレームで消え切る。
- ④: 走りの間は「走者の前の線」が必ず在る。斬り抜けの間は一様の帯が在る。

**残る妥協(1行で書いておく)**: 体当たりの**横幅(体の半幅ぶん)**は線の外にはみ出して当たる。体そのものが危険の絵として見えている、と読む。これを赤で埋める見せ方(体幅の帯)は社長が却下済み。

**なぜこの型が面白いか**: 走者が自分の線を食っていくので、「線の先端=もうすぐ来る所」が一目で読め、横へ一歩外す回避がはっきり決まる。斬り抜けの太い帯が別に流れることで、「突進は躱した、でも抜けた先で斬られる」という二段の読み合いが生まれる。
