# 「次の技は前の技をキャンセルしない」規則(社長裁定 2026-08-16 / v0.25.3518)

> **これは生きた台帳/規則です(この文書が現行の正)。案件の状態は PROJECT_STATUS.md を見る。**

社長の言葉:
> 全ボスで、次の技は前の技をキャンセルしないってルールあった方がいい気がする。
> **モーションも合わせて出来るまで次は出ない。**

## 1. 調べた結論: 挙動としては既にそうなっている

3系統(裏ボス=`useGameLoop` / 賞金首=`bountyTick` / 城ボス=`gameStore` の aiPhase)とも:

- 技の抽選口が **`bossState === 'chase'`**(城ボスは待機aiPhase)で塞がれている。
- 次の抽選時刻(`bossNextActionAt`)は **前の技の硬直が明ける瞬間に初めて**セットされる。

したがって **技→技のキャンセルは構造的に起きない**。実際にキャンセルしているのは
**カウンター成立 / 紫(体勢崩し) / 気絶 / 拘束 / 浮き / レーザーの近接中断** で、
どれもプレイヤーが崩した結果=「次の技」ではない(ノックバックはv0.25.3497で中断をやめた)。

**問題は、それを保証する仕組みが無かったこと。** 状態機械は3ファイルに手書きで40本近くあり、
新しい技を1本足す時にガードを書き忘れれば静かに破れる。

## 2. やったこと①: 規則の機械化(v0.25.3518)

`src/utils/moveCancelGuard.ts`(依存ゼロの葉・**挙動は1ミリも変えない**)

- `parseMovePhase(state)` … 状態名を `{move, phase}` へ割る(命名規約 `<move>-windup|-active|-recover`)。
- `moveCancelViolation(prev, next)` … **別の技の windup が、前の技の windup / active の途中から
  始まった**を違反とする。中立を挟む / 同じ技の段階遷移 / 硬直から次へ / 技→中立 は違反にしない。
- `ALLOWED_MOVE_CHAINS` … **設計された連携の申告表**。状態名だけでは「終わって繋いだ」と
  「途中で切った」が区別できないので、連携は理由つきで明示申告する。**申告が無い遷移は全部違反。**
- `createMoveCancelWatch()` … 複数体を見張る観測器(状態を持つのはここだけ)。

テスト:
- `moveCancelGuard.test.ts` … 規則そのもの(15件)。
- `bossMoveCancel.test.ts` … **賞金首4種 × 3距離帯を実走30秒**して違反ゼロ(14件)。
  わざと割り込ませた並びが検出されることも確認(空振りテストでない証明)。

### 実走で見つかった唯一の連携
`bm-charge(実行中) → bm-whip360(溜め)` = 馬乗りの「突進→360度ムチ」(社長指示v0.25.3473)。
突進は **目標へ着いた / 持ち時間を使い切った** 時にだけ次へ渡している(`dl<=2 || 時間切れ`)ので
切っていない。**申告表へ理由つきで登録済み。**

### まだ網が掛かっていない範囲(正直に)
**裏ボス・城ボス**。状態機械が `useGameLoop` / `gameStore` の巨大ループの中にあり、
ヘッドレスでボスを出して長時間回す土台が無い(`playtestDriver` はボスの湧きまで届かない)。
判定側(`moveCancelGuard`)は状態名の規約だけに依存するので、**土台が出来たら同じ観測器を挿すだけ**で
網が広がる(判定を書き直す必要はない)。

## 3. やったこと②: 演出の共通時計(latch)の洗い出し

「モーションも合わせて出来るまで」= 技が**中断された時**に絵が途中で消えないこと。
このプロジェクトには既に共通時計があり(`latchFx` / `moveArtClock` / `sweepArtClock` /
`zoneCapsuleTick` / `dashLineTick`)、v0.25.3115で「カウンターで消えても最後まで描き切る」を確立済み。

**方法**: `pixiScene.ts` から「**実行中**(windup/recover以外)の状態名で**武器・体のモーション**を
描いている箇所」を抽出し、近傍40行に latch 系の呼び出しがあるかで分類した。
予告(windup)は**中断で消えて正しい**ので対象外にしてある。

| 判定 | 状態 |
|---|---|
| OK(latchあり) | `g-nihil-chant1` / `issen-dash` / `jump-attack` / `mk-boom-out` |
| **要確認(latchなし)** | `downslash` / `mk-repose` / `mk-spin` / `mk-suiu-hop1` / `mk-suiu-hop3` / `sweep` / `thrust` |

**この表はまだ「疑い」であって「不具合」ではない。** 近傍40行という機械的な当たり付けなので、
別の形で出し切っている可能性がある。**実機で「カウンターした瞬間に絵が消える」が出るのはこの7つの
どれか**、という当たりを付けるための地図として使う。

次の一手(未着手・裁定待ち):
1. 上の7つを1つずつ当たって、本当に切れるものだけ `moveArtClock` へ載せる。
2. 裏ボス・城ボスをヘッドレスで回す土台を作り、規則の網を全ボスへ広げる。
