# 揺れの整理(プレイヤー起因のダメージ揺れを1本にする)— 相談用設計案 v1

- 発端: 社長 2026-09-14「揺れについては一度綺麗に整理したい。銃だけじゃなくて、近接攻撃とか爆発とかその他プレイヤーが使うダメージも含めて、
  全てのプレイヤーから発せられるダメージに対して一気にできた方がいい。純粋なダメージに対する揺れ幅と、爆発・クリティカル・キルなど特殊な
  パターンにはさらに倍率をかけるのがクリアなのでは」。
- 状態: **相談段階(未承認・未実装)**。この文書は「今の実態(事実)」と「案」と「決めてほしい点」だけ。
- 対象: **プレイヤーが敵に与えるダメージ**に伴う画面の動き(揺れ・反動キック)。
- 対象外(この案では触らない): 被弾の揺れ(`SHAKE_MAG` 16)・敵/ボスの技や召喚・登場の着地・四神技/竜巻の発動・ボス撃破の演出(長い低い揺れ+スロー)・
  ヒットストップとスローの長さ・ズーム。これらは「ダメージの通知」ではないので別の物差しのまま。

## 1. 今の実態(事実。数えたもの・全部 `triggerShake`/`triggerKick` 経由・描画のみ)

描画側で全ての振幅に `SHAKE_GLOBAL_MULT`=2 が掛かる(下表の px は掛ける前の値)。重なった時は「強い方優先・長さは延長」。

| いつ | 何が | 振幅px / 長さms | 出どころ | ダメージとの関係 |
|---|---|---|---|---|
| 発砲時 | 反動キック(銃のみ・射線の逆へ・ease-out) | 0.8〜9.5 / 間隔の75% | `recoilSpecForWeapon` | **唯一ダメージを見ている**(1発威力×0.055+基礎1.6、連射は√で減衰) |
| 銃が当たった時 | (無し) | 0 | — | — |
| 銃以外が当たった時(爆発・サブ武器・スキル。damageEnemy経由) | 一瞬の揺れ | 4 / 90(間60ms) | `NONGUN_HIT_SHAKE` | 無関係(グレネード140でも刀12でも同じ) |
| 近接の通常ヒット(カウンター/刀/鞭の3経路) | スイングの揺れ(敵の方向へ) | 7 / 110 | `MELEE_SWING_SHAKE` | 無関係 |
| クリティカル(全経路) | 大きい揺れ+光源 | 14 / 200(間320ms) | `CRIT_SHAKE` | 無関係(7ダメの連射クリも140の擲弾クリも14) |
| カウンター成立 | ストップ100+揺れ+寄りズーム | 8 / 100 | `COUNTER_SHAKE` | 無関係 |
| シールドバッシュ | ストップ100+揺れ | 10 / 160 | `SHIELD_BASH_SHAKE` | 無関係 |
| 近接フィニッシュ(処刑) | ストップ100→揺れ+スロー+最大ズーム | 14 / 180 | `MELEE_FINISH_SHAKE` | 無関係 |
| パニッシャー巻き込み | 揺れ | 4 / 200 | `PUNISHER_SHAKE` | 無関係 |
| 倒した時(通常キル) | (無し。10体連続でスローのみ) | 0 | `registerPlayerKills` | — |
| 爆発(手榴弾/擲弾/ロケット/シグナル) | 上の「銃以外」の4pxだけ。**爆発固有の揺れは無い** | 4 | — | 無関係 |

**読み取れる歪み(事実)**
1. 物差しが無い。値は「社長指示で倍化」を個別に重ねた結果で、**4 / 7 / 8 / 10 / 14** はお互いに比べて決めた数字ではない。
2. 逆転がある: 刀の一振り(12ダメ)は 7px、擲弾の爆発(140ダメ・複数体)は 4px。レールガン(87)のヒットは 0px。
3. ダメージを見るのは反動キックだけ。しかも「当たった時」ではなく「撃った時」。
4. 特殊パターン(クリ/フィニッシュ/カウンター)は**定数の上書き**で表しているので、弱い武器のクリと強い武器のクリが同じ揺れ。

## 2. 案(社長案を具体化)— 「基礎揺れ = f(ダメージ)」×「特殊パターンの倍率」の2層

### 2-1. 1本の純関数(`src/utils/impactShake.ts`・store/描画から独立・テスト可)
```
impactShakeFor(damage, flags) -> { mag, ms }
  base = clamp(K * sqrt(damage), MIN, BASE_MAX)      // 1層目: 純粋なダメージ
  mult = Π(flags に該当する倍率)                       // 2層目: 特殊パターン
  mag  = min(base * mult, HARD_MAX)
  ms   = MS_MIN + MS_PER_PX * mag                     // 長さは振幅に従う(1本の式)
```
- **damage は「1つの事象で同じフレームに入った与ダメの合計」**(散弾5粒=1回、爆発で3体=1回、刀の一振りで2体=1回)。
  同じフレームの多段は1回の揺れに畳む(今も「強い方優先」で畳まれているが、合計ではなく最大を取っている=散弾・爆発が損をしている)。
- **方向は命中点へ寄せる**(既存の dirfx)。事象内で複数体なら重心。
- **叩き台の値**(実機で絞る前提。体系の是非を先に決める):

| 記号 | 叩き台 | 意味 |
|---|---|---|
| K | 1.3 | √ダメージ→px。sqrt を選ぶ理由は §2-3 |
| MIN | 1.5 | 4ダメの散弾1粒でも「触った」と分かる最低線 |
| BASE_MAX | 14 | 倍率を掛ける前の天井(今のクリ/フィニッシュと同じ値) |
| HARD_MAX | 16 | 倍率込みの天井=**被弾(16)を超えない**(「殴られた方が殴ったより大きい」を体系として固定) |
| MS_MIN / MS_PER_PX | 70 / 9 | 1.5px→84ms、7px→133ms、14px→196ms、16px→214ms(今の 90〜200 の帯と同じ範囲) |

叩き台での基礎揺れ(倍率前・×2の描画倍率前):

| 事象 | 合計ダメ | base px | 今 |
|---|---|---|---|
| マシンピストル1発 | 7 | 3.4 | 0(キックのみ) |
| ハンドガン1発 | 9 | 3.9 | 0 |
| 刀の通常斬り(1体) | 12 | 4.5 | 7 |
| 散弾5粒命中 | 30 | 7.1 | 0 |
| ボルトアクション1発 | 52 | 9.4 | 0 |
| レールガン1発 | 87 | 12.1 | 0 |
| 擲弾Ⅲの爆発・1体 | 140 | 14(天井) | 4 |
| 擲弾Ⅲの爆発・3体 | 420 | 14(天井) | 4 |

### 2-2. 特殊パターンの倍率(2層目・叩き台)
| フラグ | 倍率 | 備考 |
|---|---|---|
| クリティカル / ヘッドショット | ×1.6 | 光源(`spawnCritImpact` の強glow)はそのまま |
| キル(雑魚/強個体を倒した) | ×1.3 | 今は無し。10体連続のスローはそのまま |
| 爆発(爆風で入ったダメージ) | ×1.3 | 合計ダメが既に大きいので控えめ。爆発の「面」の読みは光/砂埃(②派手側)が担う |
| カウンター成立 | ×1.5 | ストップ100+寄りズームは不変。揺れだけ本式へ |
| 近接フィニッシュ(処刑) | ×2.0 | ストップ→揺れの順、スロー、最大ズームは不変 |
| シールドバッシュ | ×1.5 | ストップは不変 |
- 倍率は**掛け合わせ**(クリで倒した=×1.6×1.3=×2.08)、最後に HARD_MAX で止める。
- 今の「間(gap)」3種(銃以外60ms・クリ320ms・パニッシャー無し)は **1本の再武装 `IMPACT_SHAKE_GAP_MS`=120ms** に統一
  (直前の揺れより弱い揺れは間の中では出さない。強い揺れは間を無視して出す=強い方優先はそのまま)。
  連射系の常時ブレは「弱い揺れは間の中で捨てられる」+「ダメージが小さい=揺れも小さい」の2つで抑える。

### 2-3. 曲線の選び方(決めてほしい点①)
- **(a) √(推薦)**: 4〜275 のダメージ幅(約70倍)を 2.6〜21(約8倍)へ圧縮。**弱い武器でも「当たった」が読める**上で強い武器が明確に大きい。
  倍率(2層目)が弱い武器にも効く(7ダメのクリ=3.4×1.6=5.4)。
- **(b) 線形**: mag = 0.1×damage(上限14)。**純粋な比例**。マシンピストル0.7、刀1.2、レールガン8.7、擲弾14。
  弱い武器は事実上揺れない(=連射ブレ問題は自然に消える)が、**刀・鞭・ナイフ系の近接がほぼ無揺れ**になり、
  クリの倍率も弱い武器では読めない(0.7×1.6=1.1)。
- 事実: 反動キック(v0.25.4269)は線形+基礎1.6で作ってあり、社長は 2026-09-14 に「ダメージと比例させたら?」と発言(未裁定)。
  キックとヒット揺れを同じ曲線にするなら、キック側も (a)/(b) に揃える(§2-4)。

### 2-4. 反動キック(発砲時)の扱い(決めてほしい点②)
- **(推薦) 残す。ただし同じ曲線から出す。** 「撃った瞬間に射線の逆へ蹴られる」(発砲の手触り)と「当たった瞬間に命中点へ揺れる」(ダメージの通知)は
  別の感触で、どちらも消すと銃が軽くなる。キック=`impactShakeFor(1発威力)` の base×0.6 程度を射線の逆へ(向きが決まっている分、振幅は小さくてよい)。
  `rapidFireKickMult`(√減衰の別枠)は撤去し、連射の抑制は「弱い揺れは間の中で捨てる」に任せる。
- 代替: キックを廃止し、銃も「当たった時」だけ揺れる。最も単純。ただし空振り(外した弾)で何も起きなくなる。

### 2-5. 触らないもの(この案の範囲外・明記)
- 被弾 16/280、敵・ボス・召喚・登場の揺れ、ボス撃破の長い低い揺れ、竜巻/四神技の発動揺れ、エンディングの爆撃。
- ヒットストップ(100)・スロー・ズームの長さと順序。守護霊/幻影/護衛の演出(プレイヤー起因ではない・既に別フラグで除外済み)。
- 光(`spawnCritImpact` の強glow)・血・砂埃などの絵。

## 3. 実装の形(承認後・見積り)
- 新規 `src/utils/impactShake.ts`(純関数+テスト)。store に `registerImpact(damage, flags, x, y)`(同フレーム合算→tick末で1回 `triggerShake`)。
- 呼び替え: damageEnemy 中央(銃/銃以外)・近接3経路(counter/katana/whip の survivors 側)・爆発解決(explosions)・triggerHitImpact(counter/bash/finish)・
  spawnCritImpact(揺れ部分だけ本式へ、光はそのまま)・registerPlayerKills(キル倍率のフラグ立て)。
- 撤去: `NONGUN_HIT_SHAKE_*`・`MELEE_SWING_SHAKE_*`(プレイヤー側)・`CRIT_SHAKE_*`・`COUNTER_SHAKE_MAG`・`SHIELD_BASH_SHAKE_MAG`・
  `MELEE_FINISH_SHAKE_MAG`・`PUNISHER_SHAKE_*`・`rapidFireKickMult`。守護霊(ghostCounter/useGameLoop の GHOST_FX_SHAKE)は
  同じ関数を「守護霊の与ダメ」で呼ぶか、従来値のまま残すか=実装時の1問。
- 負荷 1/10(命中ごとに平方根1回とフラグの積。描画は既存の shake 経路のまま)。
- 検証: 純関数のテスト(単調性・天井・被弾を超えない・間の挙動)+実機。

## 4. 決めてほしい点(まとめ)
1. 曲線: (a)√(推薦)/(b)線形。
2. 反動キック: 残して同じ曲線(推薦)/廃止。
3. 倍率表(§2-2)の顔ぶれと値は叩き台でよいか(足したい/外したいパターンがあるか。例: ボス級への命中、体勢崩し成立、ヘッドショットをクリと別扱いにするか)。
4. 「被弾を超えない」(HARD_MAX=16)を体系のルールにしてよいか。
