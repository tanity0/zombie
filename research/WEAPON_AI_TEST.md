## §1 ★v1が壊れていた理由(設計の土台)

**`playtestDriver`(ヘッドレスのボット)は `useGameLoop` を通らない。**
`runPlaytestTick` が動かすのは `updateEnemies` / `updateProjectiles`(store)と `fireWeapon` だけで、
**武器の状態機械と命中側効果の大半は `useGameLoop.ts` にしか無い**。

| ヘッドレスで**動く**(store/純関数側) | ヘッドレスで**動かない**(`useGameLoop` 専用) |
|---|---|
| デュアルレンジのモード / 切替式の反転 / 大型狙撃銃の静止蓄積 / コイルの軌道 / 誘導ペレットの旋回 / デザートテックの弾種 / レールガンのオート / 錬金の**起爆** | **ハンドキャノンの減衰 / パイルドライバーのKB・体勢 / 収束型SGの命中で狭まる処理 / ガンブレードの近接 / 火炎放射器の扇 / 氷槍の床 / アイレーザー / ロケランの溜めと発射 / シグナルの空爆 / 錬金の破裂と石の付着 / 金環のフェーズtick** |

さらに**ボットの入口で3つ閉じている**: `nonProjectile`(火炎放射器・アイレーザー)は**撃たずにreturn** /
シグナルは**既定へフォールバック** / ガンブレードは **`allowMelee:false`** で至近を空撃ち。
**手動アクション**(`fireSignalLauncher` / `fireRailgunShot` / `detonateAlchemyStones`)の呼び出し元は
**`VirtualJoystick.tsx` だけ**。

★**⇒ ヘッドレスだけでは、22行のうち8行しか成立しない。**

## §2 ★本体は「実機ボット走査」。既に土台がある

**`?bot=standard` で、ブラウザの実プレイにボットを載せられる**(=**実プレイの `useGameLoop` がそのまま動く**)。
**既存のランナーが2本ある**:

| 既存の道具 | 何をするか |

## §4 層Aに足りない部品(★新規に作るのはこの3つだけ)

### 4-1. 出撃時に武器を強制するツマミ(新規)
**現状では対象武器を持てない。**出撃時に持つのは `profile.gunKey` の**T1 1挺+近接**だけで、
装備設定(`zombie.loadout.slots`)は**「そのカテゴリ×Tierの銃を入手した時の解決先」を変えるだけ**。
**rifle-t3 等はラン中に拾うまで現れない。**`?weapon=` 系のツマミは**存在しない**(grep 0件)。

⇒ **開発用ツマミを1つ作る**: `?weapon=<key>`(銃)/ `?sub=<key>`(サブ)。
- **`?unlockall=1` と同じ扱い**(開発導線。`practiceGuard` / `BOSS_TEST_RUN` と同じく**進行に書き込まない**)。
- ★**`grantWeapon` は使えない**——**カテゴリごと1挺・Tierが同じ以下なら付与せず弾薬に化ける**
  (`gameStore.ts`)。**T1ユニーク6挺(デリンジャー/クロスボウ/収束型/切替式/ボルト/デザートテック)が
  全部これに当たる。**⇒ **出撃武器の生成点(`getStartingWeapons`)で差し替える。**
- ★**`autoSwitchIfDry` が弾切れで別の銃へ逃げる**ので、**このツマミの時は所持銃を対象1挺だけにする**。
- **金環**: `resetGame` が `pendingLoadout`(localStorage)を **`purchasedSubLevels>=1` で絞って**反映するので、
  **`?sub=` は購入済み状態も一緒に注入する**。

### 4-2. 観測の窓口(新規・既存の窓口に相乗り)
**`window.__BOT_REPORT__` は既にある**ので、**新しい窓口を増やさず**そこへ武器の観測値を足す。
★**観測は「カウンタ」と「サンプル」の2種類に分ける**(v1はここが矛盾していた):

| 種類 | 中身 | 例 |
|---|---|---|
| **カウンタ**(`botTelemetry` に足す) | **起きた回数だけ** | 発射 / 爆発 / パルス / 石の付着 / 石の起爆 / リロード / クレート / 通貨 / 体勢崩し |
| **サンプル**(ランナーが毎秒 store を読む) | **位置・大小・時刻が要るもの** | 発射時の距離 / 横ズレ / 散り角 / 1発目と2発目のダメージ / 床の長さ / 空爆の記録時刻と着弾時刻 |

### 4-3. 手動アクションの代役(新規)
**ボットは手動系を撃たない。**⇒ **ランナーがプレイヤーの代わりに叩く**(`?bot=standard` と併用):
`fireSignalLauncher` / `fireRailgunShot` / `detonateAlchemyStones` を**一定間隔で呼ぶ**。
★**ボット本体を書き換えない**(ボットの挙動を変えると既存の計測が全部ずれる)。
**ガンブレードの近接**は `allowMelee` の既定が true なので、**ボットの `allowMelee:false` を
このツマミの時だけ外す**(ボットのDPS計測用の配慮なので、武器テストでは要らない)。

### 7-6. ★このコンテナでは層Aを回せない(2026-09-08・実測)
**層Aは社長の実機(またはGPUのある環境)で回す。このリモートコンテナでは意味のある結果が出ない。**

| 実測(`?bot=standard` + `run-weapon-sweep.mjs`) | 実時間 | 進んだ `gameTime` |
|---|---|---|
| デリンジャー 1挺 | 90秒 | **550ms** |
| デリンジャー 1挺 | 240秒 | **1800ms** |

原因は **swiftshader(ソフトウェアレンダリング)**。`gameTime` の進みが実時間の **1/35〜1/130** しかなく、

(ダメージ0・通貨ドロップ0・リロード0 = そもそも撃ち合いが起きていない)。
⇒ **この環境の「赤」を不具合として読んではいけない。**
