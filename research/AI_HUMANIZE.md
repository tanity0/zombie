## §0-2 これは「ではない」(監査・実装の対象外)
- **スクリプト演技ではない**: 「人間っぽく振る舞う台本」を書かない。**録って写すだけ**。演出・セリフ・UIは対象外。
- **判定・バランスの変更ではない**: カウンターの窓300ms・請求・成立条件・ダメージ・技の性能は1bitも変えない。
  変わるのは**守護霊/幻影の「いつ・どこで・振るか」の決め方**だけ。
  (注: 立ち位置癖の再現によって守護霊が予告図形の中に立つ=被弾する頻度は変わりうる。これは
  「失敗してるサイコロの目はそのまま癖として再現される」(社長裁定)の意図どおりで、判定・数値の変更ではない。)
- **オンライン同期の設計ではない**: コマはプロファイル(既存の記録の器)に載るだけ。配信・照合の設計は別案件。
- **弾(BULLET_MOVE_KEYS 27技)への適用は本バッチではない**: 弾の反応(tanked/counterの袋)は現行のまま。第2弾(★未決#4)。
- **性能の上限**: 毎フレームの新規走査・購読を1本も足さない(全てイベント駆動+州開始時のO(10)比較。
  既存の毎tick移動計算**内**の係数追加[慣性ランプ]は可=§5)。

| 2 | posB | 図形ローカル位置・横軸(§1-2) | 同上 | −100..100(=−1.00..1.00)の整数 |

- 記録ゲート: **既存の計測ゲートと同一で確定(社長裁定2026-08-28)**=撃破+リザルト通過のランのみ・

### §1-2 図形ローカル座標(実在の族=CounterReachKindで正規化)
正規化は counterReach の図形パラメータをそのまま受け取る関数 `habitPos(shape, x, y)` として counterReach.ts の
隣に置き、判定側と式を共有する(二重実装しない)。
| kind | posA(主軸) | posB(横軸) | sub |
|---|---|---|---|
| `band`(複数本は**最寄りの1本**で測る) | 始点→終点への射影 t(0..2にクランプ) | 垂直offset / halfWidth(±1にクランプ) | 帯index(逆写像は**同じ帯**へ戻す) |
| `circle` / `circle-or-body` | 中心からの距離 / radius(0..2) | 予告の軸(aiFrom→aiTarget)との差角/π。**自分中心で軸が退化する州(bm-whip360/mk-spin/bite等)は0固定** | 0 |
| `body`(既定。宣言表に無いキー=giant系もこれ) | **縁距離**(判定と同じmeleeDist=AABB最近点)/74(0..2)。**中心距離は使わない**(v0.25.2567で是正済みの単位取り違えの再演になる——jormungand半幅259では中心/74が常時飽和する) | 差角/π(退化時0) | 0 |

  [?thorscript=0]なので録らない=座標系の混入防止)。
- **毎フレーム狙い直す図形の州**(hidden:tsuki-windup / idol:idol-punch-windup / mk-boom系)は
  **位置取りの対象外**(§2-2をスキップ。タイミング§2-3だけ再生)。予告開始時の凍結図形で録った位置と

- クランプ幅・角度基準は叩き台(B1で境界テスト)。

### §1-3 押下の打刻と帰属(v3で入力方式非依存に是正)
- **v2の「beginMeleeSwingで打刻」は誤り**: PC(キーボード/マウス)は `performTapAction → triggerCounter` 直呼びで
  `beginMeleeSwing` を**通らない**(gameStore側コメントにも「PC入力が素通り」と明記がある既知の非対称)。
  そのまま実装するとPCプロファイルは全コマ pressOfs=null → 守護霊が一切振らないバグを出荷する。
- **打刻の正本**: `stepMeleeSpacing`(meleeSpacing.ts)が既に**入力方式非依存の swungThisTick / counterWindowOpen を
  gameTime で受けている**(「押して外した押下」を数える唯一の既存台帳・カウンター窓の別勘定)。B1はこの
  **同じ呼び出し入力**の隣に「直近押下リング(gameTime・4件)」を積む(=3本目の独立台帳を作らず、既存の
  押下勘定を拡張する)。`meleeSwingCommitAt`(スイング確定・全5経路)は**振りの確定**であって押下ではないので使わない。
- **帰属**: コマが閉じる時(T)に、**[T−1500ms, T+300ms] 内で T に最も近い押下**を1件引く。無ければ null。
  1つの押下は最も近い1コマにだけ帰属(同時多発のタイは早い方)。+300msまで拾うのは押し遅れ(人間の失敗の主形)を残すため。

## §2 守護霊の再生(カウンター行動の置き換え)
対象州の**構え開始**(ghostDriverの `counterWatching` 立ち上がり=既存実装の監視エッジ)で:
1. **位置取り=10コマの実座標の中を立ち回る(社長裁定2026-08-28)**: コマ10件から**seqとctxの最近傍1件**
   (距離 = 0.25×min(|Δseq|,2)/2 + 0.5×|ΔctxHp| + 0.5×|ΔctxHit|。**位置は選択に使わない**=自己参照の禁止。
   タイは新しいコマ優先)を引き、その(posA,posB,sub)を「今その技が実際に張っている図形」へ逆写像した点を
   移動目標にする。既存の移動系で**寄れる範囲だけ寄る**。
   - **人工ジッタは足さない(★未決#6は(b)で裁定=社長設計「10個履歴があればその範囲内で立ち回れば
     完全に同じにはならず、且つ正確な動作をする」)**: 遭遇ごとにseqが進み・HP/被弾の状態も変わるので、
     目標は**本人が実際に立った10箇所の間を自然に移り変わる**。ブレの源は乱数ではなく履歴と環境。
     座標は全て実測=本人が一度も立っていない合成座標を作らない(v1中央値・v3ジッタ案の欠点を両方回避)。
   - **v2の「現在位置の最近傍コマへ歩く」は自己参照**(今居る場所に一番近い履歴を選んで「そこへ歩く」=
     移動が構造的に最小化され、立ち位置の癖が実機に出ない)だったため不採用。**位置は選択の入力ではなく出力**。
   - 届かなくても発火はする(予告450〜1700ms・足87px/s=40〜150px分。届かない分は「環境に阻まれて好きな
     位置に立てないコマ」=ゲーム性=社長裁定)。
   - **回避の無効化はその州の予告台帳エントリ1件だけ**: `ghostDodgeVector` の合成のうち①予告(対象州のみ)を
     外す。**②敵弾・③ボス体48px(GHOST_BOSS_BODY_AVOID_PX)・④接触は生かす**。③に合わせ、逆写像した
     目標の縁距離は48pxを床にクランプする(体内目標を作らない。§1-2のbody縁基準とセット)。
   - **到達後は静止してよい**: この局面は「カウンター待ち」なので、裁定v0.25.2534(静止はカウンター待ち
     以外に存在させない)の**例外側に該当**する。オービットで癖の座標から流れ出ない。
2. **(位置取り対象外の州)** `TRACKED_SHAPE_KEYS` は本項をスキップ(移動は現行のまま)。
3. **振る=実位置の最近傍コマの押下時刻**: 振り判断時点(**T−500ms**・叩き台。位置取りが概ね終わる頃)の
   **霊の実位置**を図形座標に写し、最近傍1コマ:
   距離 = |ΔposA| + |ΔposB| + (sub不一致なら+1) + 0.5×|ΔctxHp| + 0.5×|ΔctxHit| + 0.25×min(|Δseq|,2)/2
   - ctxは霊側の同値(`Summon.health/maxHealth`・`Summon.lastHit`=実在確認済み。lastHitはDate.now基準だが
     「直近2秒か」の判定はDate.now側で閉じる=時計を跨ぐ引き算はしない)。
   - seqの再生側=**その召喚中にこの州を見た回数**(Summonに小カウンタ・召喚ごとにリセット)。
   - 重みは叩き台。**サイコロは振らない**(純粋最近傍=社長裁定。タイは新しいコマ優先)。
   - **pressOfsが数値なら「振り始め」を `T + pressOfs` に置く**(**オフセット無し**——現行実装は振り始めの瞬間に
     請求と窓を開く[openGhostSwingWindow/setGhostCounterClaim。「旧: 前隙解決時に積む」は是正済み]ので、
     振り始め=本人の押下=窓開き。v2の「前隙ぶん前倒し」は**200msズレる誤り**だった。
     `GHOST_SWING_WINDUP` という定数も実在しない)。
   - 計算した振り始めが既に過ぎていたら**即振る**(遅れごと再現)。CDが明けるのが `T+300ms` を超えるなら
     **振らない**(無理な帳尻合わせをしない)。**pressOfs=null なら振らない**。
4. **成否はシステム任せ**: 請求・窓300ms・判定時置換は現行のまま1bitも変えない。
5. **袋と乱数**: 袋(rollGhostMoveReaction)は**全州で従来どおり引く**(tank歩き・弾処理・非対象州の挙動が消えない)。
   ただし**消費順の完全不変は要求しない**(v2の§7-4は達成不能だった——counterChance抽選・平時の移動抽選は
   分岐依存で、対象州では自然に消える。「技ロールが無い技」の既存挙動と同型=許容。ダミーrandで埋めない)。
6. **フォールバックは3段(社長指示2026-08-28「履歴が少なくても他で取ってある数値から計算できるように」)**:
   - **段1: 技コマ再生**(そのepisodeKeyのコマ≥3。3件未満は新設のしきい値=旧n<3ゲート[廃止済み]とは別物)
     = §2-1〜§2-3。最強の履歴。
   - **段2: 汎化層**(コマ<3 だが§2-7の族集計・既存計測がある)= §2-7で「この人はこう動くだろう」を
     他の数値から計算して再生。
   - **段3: 現行モデル**(lead 70〜230+counterChance+袋)= コマを持たないプロファイル
     (固定守護霊20体・オンライン由来・旧版保存)とEPISODE_KEYS外。境界はepisodeKey単位=段階移行できる。

### §2-7 汎化層(コマが少ない技への「この人ならこう動く」の計算・社長指示2026-08-28)
**狙い**: 技コマは強力だが1戦2〜3回しか来ない技は貯まりが遅い。**撃破ラン中に取っている他の数値**から
その人の動き方を計算し、コマ不足の技でも「その人らしさ」を出す。材料は**大半が既存の計測**:
| 何を計算するか | 材料 | 実在 |
|---|---|---|
| **どこに立つか** | **族別集計**(§1-4・新設): 全対象州のコマを族(band/circle/body)ごとに畳んだ平均(posA,posB)——「帯技全般で先端寄り・左寄りに立つ人」 | B1で新設(コマ記録のついでにEMA3族×数値) |
| **いつ押すか** | 族別の平均pressOfs(§1-4)+既存 `counterAimLagMs`(窓が開いてから振るまでの平均遅れ・試行ベース) | 族別=新設 / counterAimLagMs=**既存**(meleeSpacing) |
| **振るか振らないか** | 既存 `moveReactions[key].counterRate`(**その技への**成立率・全110キーで計測済み。無ければ族の押下率[pressOfs≠nullの割合]) | **既存**+族別=新設 |
| 平時の間合い・止まり癖 | §4(既存distBuckets・stationaryFrac系) | 既存 |
- **再生(段2)**: 立ち位置=族の平均(posA,posB)を§2-2と同じ逆写像で。振るか=counterRate(または族の押下率)を
  **専用乱数流**で1回引く(既存randは消費しない。段3の現行モデルも元々counterChance抽選=同型)。
  振る時刻=T+(族の平均pressOfs、無ければ−counterAimLagMs)。
- **§1-4 族別集計(B1追加)**: コマ記録と同じフックで、族ごとに「平均posA/posB・平均pressOfs・押下率・件数」を
  EMAで畳む(3族×5値=15値。コマと同じく軸1・量子化保存)。**発動条件: その族のコマ総数≥5**。
- **注**: この§2-7と§1-4は監査2巡の**後**に足した追補(社長指示2026-08-28)。B発注前に追補部分のみ監査に
  一瞥させる(全文の3巡目はやらない)。

## §3 幻影への適用(本バッチの実入り)
- **§4のマイクロリズムを幻影にも本バッチで配線**する(B3の作業項目として守護霊[ghostDriver+useGameLoop]と
  幻影[phantomTick]の**2箇所**を明記)。
- **幻影・固定守護霊のプロファイルは分布を持たない**(fixedGuardians/人格台帳はスカラーのみ)。そのままでは
  幻影に届くのが慣性ランプだけになる=社長の第一声(幻影が本丸)に応えられない。よって
  **分布欠損時は既存スカラーから既定分布を合成**する(B3): 止まり分布←stationaryFrac、攻撃間隔←hitsPerMin、
  間合い分布←preferredDist(それぞれ決定的な写像・人格ごとに違う分布になる)。**本人の実測分布があれば実測が勝つ**。
- **幻影のコマ再生**(対人戦の技への反応)は判定図形が別系のため第2弾(★未決#4)。

## §4 マイクロリズム(操作の指紋・守護霊/幻影の移動へ)
- **録る**:
  ①**止まりの長さ**(移動入力が途切れた区間: 〜200ms/〜600ms/それ以上の3ビン)
  ②**攻撃間隔の揺らぎ**(近接押下の間隔: 密/中/疎の3ビン)
  ③**平時の間合い**=**既存の16ビン距離ヒストグラム(distBuckets・50px刻み)をそのまま保存**する
  (現状foldで中央値1個に潰して捨てている——新しい3ビンを作るより既存の細かい分布を保存する方が安く精度も高い)。
  ①②は既存のmobility/stationaryFrac計測と同じフックで録る(新規の毎フレーム走査を足さない)。
- **写す**:
  - 守護霊/幻影の移動に①の「止まり」を挟む。**既存の止まり癖(ghostMoveChanceのstationaryFrac抽選)は
    分布を持つプロファイルでは①が置換**する(二重にしない)。止まりの絵は過去裁定(完全停止→「遅い横流れ」)を
    踏襲しドリフト床を維持する。
  - 攻撃リズムは②で通常近接の間隔を揺らす(CD・射程・判定は不変。**カウンターの振り§2-3には掛けない**)。
  - ③は `preferredDist` を分布から引いた値へ置換(引き直しは召喚時+状態遷移時のみ=イベント駆動)。
- **慣性(B3の新設作業)**: 守護霊/幻影の移動は現状**速度状態を持たない直接積分**。①の止まり→動き出しに
  **加減速ランプ(150〜250ms・ease)を新設**する(CLAUDE.md慣性MUST。無いと句読点が瞬間停止・瞬間発進になり
  機械感を逆に増やす)。
- **乱数の掟**: 抽選は**専用の決定的乱数流**(シード=召喚id/敵id+ラン)。状態はSummon/Enemyの新フィールド
  (例 `humanRhythm`)に持ち、decideGhost系は現行の流儀どおり**戻り値で次状態を返す純関数**にする。
