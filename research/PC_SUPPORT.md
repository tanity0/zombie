# PC版への対応(research/PC_SUPPORT.md)

社長の言葉(2026-10-02): 「そろそろPC版への対応も検討したい。懸念は操作方法と、画面崩れ」「分けなくて済むなら一番いい」
「見える範囲だけ同じにして、縦と横が違うっていうのは?」→(面積同じ案は上下が狭すぎる、の説明を受けて)「やってみよか推薦で」。

判断の物差し(CLAUDE.md): より面白くなる方。

## 0. 方針(社長裁定2026-10-02)
- **中身(コード)は1本、配る物を分ける**。スマホ=アプリストア、PC=Electron 等で包んで Steam 等。違いは①操作 ②画面の並べ方 ③見える範囲 の切り替えだけ。
  前例: Vampire Survivors(Phaser=ブラウザ系の中身1本を Electron で包んで Steam。スマホは縦持ち既定・横持ち切替)。
- **見える範囲: 横長は縦720(スマホが必ず見せている高さ)固定・横は比率なり(16:9 で 1280)。16:9 より横に広い画面は枠を 16:9 に絞り左右に帯**
  (ウルトラワイドで横が見え過ぎて有利、を作らない。Vampire Survivors も PC は 16:10 固定で帯)。縦持ちは1ミリも変えない。

## 1. 調査で分かった現状(2026-10-02・走査2本+実画)
### 1-1. 画面
- 見える範囲を決める `computeViewport`(utils/viewport.ts)が縦持ち専用で、横長は横の上限540が効き **540×304** に潰れていた(縦がスマホの約1/3)。
  敵の湧き(画面の外+140)・回収・画面外の判定・ボスの引き・背景の縦の組みが全部この寸法を基準にしているので、上下方向が全部縮んでいた。
- 背景の層(遠景・森・手前の森)は縦の比率+最小値で決まる=縦304では手前の森が画面の約9割。縦720なら縦持ちに近い組みになる(要実画確認)。
- HUD は端末px固定で四隅に置く。ゲーム画面は拡大されるのに HUD は等倍=PCでは相対的に小さく散る(1080p で 1.5倍拡大 / 旧540基準は3.56倍)。
- タッチ画面つきPCは「縦にしてください」で全面ブロック+マウス操作が使えなかった。
### 1-2. 操作
- 既にある: キーボード(WASD/矢印=移動、Space/J=近接・カウンター・手動射撃、K/Shift=一閃・ワイヤー、Esc/P=ポーズ)、マウス(左=近接、右=一閃、カーソル=手動の銃の照準)。
- PCで出せない: ホーミング(押してロック→離して発射)/スケーター(ダブルタップで乗る)/四神舞をマウスで。
- 無い: ゲームパッド、キーの割り当て変更、キーボードだけでのメニュー操作(矢印での選択・Escで戻る・最初のフォーカス)。
- 遊びにくい: PCの近接は前隙・踏み込みが無い即時判定(タッチと違う)/鞭等の向きがカーソルではなく歩く向き/キーボードの移動は常に全速/`e.key` 判定=日本語入力オンで WASD が効かない恐れ/タッチ前提の文言13件。
- 不具合2件(v0.25.4776 で直した): 一時停止中に Space/J/K で攻撃が出る/説明画面の表示中に Esc でゲームが動き出す。

### 2-1. 湧き方(★未決 #PC-1「左右の湧く距離」)
敵は4辺から均等(各25%)に「見えている画面の外 +140」に湧く(enemyUtils.ts generateEnemy)。自分からの距離の目安:

| | 上下 | 左右 |
|---|---|---|
| スマホ(405×878) | 約580 | 約340 |
| PC(1280×720) | 約500 | **約780** |

- 社長へ推薦した「左右の湧く距離に上限」は、**そのまま入れると湧く場所が画面の中になる**(左右の見えている端は640先)=見えている所に敵が突然現れる。だから段1では湧き方を変えずに、まず触ってもらう。
- 揃え方の候補(段1を触ってから選ぶ): (a) 左右から湧く割合を下げる(上下を多く) (b) 画面の左右の外側の帯を霧で覆い、霧の中から湧く(見えている端を実質手前に寄せる・演出の追加) (c) そのまま(PCは左右が少し楽)。

### 2-2. 画面の大きさに比例している所(段2で揃える候補・走査の結果)
`max(w,h)` や対角線で決めているもの=PCでは横1280が効いて大きくなる: 緑卵の輪の半径(×0.72)/弾の消去範囲/敵の数によるズームを数える半径(×0.6)/
叫喚型・死神・使者などの湧き位置(対角線)/回収の範囲/音の距離減衰/四神の全体フィニッシュ/洋館通路の遠近(W×比率)/カメラの寄せ(幅に対する比率)/ボスの引きの帯(縦0.45)。

## 3. 段1の実装(v0.25.4777)
- `computeViewport`: 横長(幅>高さ)は scale = max(高さ/720, 幅/1280) → 縦720・横は比率なり(1280で頭打ち)。縦持ちの式は不変(テストで固定)。
- `.game-frame`(index.css): 16:9 より横に広い横長画面は、ゲームの枠の幅を「高さ×16/9」に絞って中央へ(左右は親の背景=帯)。描画・判定・入力は枠の寸法を読むので一致する。
- `isTouchPrimary`(utils/inputDevice.ts): タッチ画面があってもマウス/トラックパッド(any-pointer: fine)があれば縦持ちガードで止めない。
- **操作層は最後に触れた入力で切り替える**(`usePointerKind`・v0.25.4778): タッチとマウスの両方がある端末は、指で触れたら仮想スティック、マウスを押したらマウス操作
  (設計監査 A-1: マウス操作に決め打つと、キーボードを外したSurface・タブレット+マウスで移動手段がゼロになる)。片方しか無い端末は固定。
- 縦持ち⇔横長の境目は幅/高さ=3:4(両方の式が 540×720 で一致=正方形の窓で視野が跳ばない・設計監査 B-3)。
- 縦持ち(スマホ)は不変。ボスメーカー等の画面は段3。
- 実画(ヘッドレス・v0.25.4777): 1280×720 → 見える範囲 1280×720 / 1680×720(21:9)→ 枠 1280 を中央・左右200pxの帯 / 430×932 → 405×878(不変・スマホ模擬は仮想スティックの側=any-pointer: fine は偽)。
- 枠(`.game-frame`)が効くのは Game の子だけ。`fixed` で窓いっぱいに出るもの・OrientationGuard(窓の寸法)は窓を読む(段3)。

## 4. 受け入れ条件(段1)

## 9. スマホを壊さない仕組み(社長指示2026-10-02「絶対スマホ用の現状が壊れないように分けて作業してね」・v0.25.4787)

  ゲームの判定に触る段2は「スマホの寸法で結果が同じ」をユニットテストで固定する。

## 11. 段4: 操作(設計・v0.25.4791〜)
社長の言葉: 「懸念は操作方法と、画面崩れ」→「全て進めて。ただ、絶対スマホ用の現状が壊れないように分けて作業してね」。
**大原則: タッチ(VirtualJoystick)のコードは触らない。** PC の入力(マウス・キーボード・ゲームパッド)は**別の入口**から、タッチと同じ store の行為を呼ぶ。

### 11-1. 「指を置く/離す」を PC にも持たせる(タッチと同じ遊び)
今の PC は**押した瞬間**に近接(前隙なしの即時判定)を出していて、タッチの核「**指を離した瞬間**に出る」とずれている。そのため PC では
ホーミング(押している間にロック→離して一斉発射)・スケボー(2回目を押したまま乗る)・近接の前隙(離して200ms後に当たる)が出せない。
- **主ボタン**(左クリック / Space / J / パッドの A)を「指」とみなす: **押す=指を置く**(`touchActive`=true・スケボーの2度押し判定)、
  **離す=指を離す**(タッチの指離しと同じ順: 帰還確認 → PHILL → シグナル → レールガン → 錬金砲の起爆 → ホーミング一斉発射 → **近接(前隙つき `beginMeleeSwing`)**)→ スケボー降車。
- 共通の入口 `utils/pcPress.ts`(`pcPressDown()` / `pcPressUp(fire)`)。マウス・キーボード・パッドが同じ関数を呼ぶ=3つで食い違わない。
- **フリック**(右クリック / K / Shift / パッドの B・RB)は今どおり押した瞬間に発動(タッチは指の速い払い=PC は専用ボタン)。向きはマウス=カーソル、
  キー=移動キーの合成、パッド=左スティック(倒していなければ向いている向き)。
- 四神舞(リズム)中: 主ボタンを離す=タップ、フリック=フリック(マウスはカーソル方向・キー/パッドは方向入力)。
- 窓が裏へ行った(blur)・ページを離れた時は「撃たずに離す」+移動キーを全部離す(押しっぱなしで歩き続ける事故を防ぐ)。
- なぜ面白いか: PC だけ「押した瞬間に当たる」のは前隙を飛ばせる=タッチより強く、しかもホーミングとスケボーが使えない。同じ「溜めて離す」判断を PC にも渡す。

### 11-2. 照準と向き
- マウスの照準をズーム込みでワールドへ戻す(今は camera を足すだけ=寄り/引きの間カーソルとずれる)。描画側が毎フレーム「ワールドの拡大と位置」を
  `utils/viewTransform.ts` に置き(描画の情報=ゲームの状態ではない)、マウスの層がそれで変換する。等倍の時は今と同じ値。
- マウスで主ボタンを離した時は、向き(lastDirection)をカーソルの方向へ合わせてから近接を出す=**鞭・ナイフの振りがカーソルへ向く**(今は歩いた向き)。
  - ★**v0.25.4868 で撤回**(社長指示2026-10-05「マウスのある方向に近接振るのは難しいのでやめたい。マウス方向はフィルガンなどのターゲットある武器のみ対応」)。
    マウスが向き・照準を決めるのは**照準を持つ銃(PHILL/シグナル/レールガン)を構えている時だけ**(`weaponUtils.mouseSetsAim`)。近接の振り・踏み込み・照準サークルは歩いた向き(キーボード・タッチと同じ)。フリックの向き(カーソル)は今回触っていない。

### 11-3. キー
- `e.code`(物理キー)で判定し `e.key` は予備: 日本語入力オン・JIS/AZERTY でも WASD/Space が効く。

### 11-4. ゲームパッド(標準配置・Gamepad API)
