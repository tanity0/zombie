# シールドで技を防ぐ(設計書・第4版)

## 0. 社長の言葉と決定
> シールドは、判定源からみてシールドの後ろにいれば防げる　にできれば一番よいが、重いなら範囲攻撃だけ対象外
> ただし、それはシールドから40px以内　であること(範囲攻撃は)
> レーザーとかは単純にそこで壁と同じ扱い

社長の決定(2026-10-18):
- **判定源 = 当たり判定の中心**(案A)。
- **予告の絵は盾を例外にする**。赤も紫もそのまま出し、防いだ瞬間に盾が光って鳴る。
- **40px は形で分ける**。円・扇は「影+40px」、線(帯・突進・レーザー)は「影だけ(距離なし)」。

補足と前提:
- 「重いなら範囲攻撃だけ対象外」: 重くない(§6=1/10)ので、範囲攻撃も対象にする。
- 今の作り:
  - シールド(`projectiles` の `weaponType:'shield'`)は、敵の体と `projectiles` の敵弾を止める。
  - 汎用の跳び・突進は、盾に当たると中断する(全部の盾が対象。gameStore 15378/15405/15792/16490/16570)。
  - それ以外の技は盾を見ていない。
- 盾は世界に同時に最大1枚(置くと、持ち主を問わず既存の盾を全部消す=useGameLoop 10449)。
- 既存の先例: 手榴弾・タレット・地雷は、既に「爆心→プレイヤーの線分が壁を通るか」(`segmentBlocked`)で壁の陰を見ている。
  この設計は、その壁の陰に**盾を足す**のと同じ考え方。

## 1. 規則
「影」=判定源からプレイヤー(相手)の中心への線分が、味方の盾の矩形を通ること(`world/obstacles.segmentIntersectsRect`)。

| 形 | 判定源 | 当たらない条件 | 守る相手 |
|---|---|---|---|
| **円**(爆風・回転斬り・着地・手榴弾など) | 円の中心 | 影 **かつ** プレイヤーの体と盾の距離が 40px 以内 | プレイヤー |
| **扇**(ブレス・薙ぎの扇など) | 扇の要 | 影 かつ 40px 以内 | プレイヤー |
| **帯**(突き・振り・一閃・突進の斬り抜け・噛みつきの伸び) | 帯の起点(下の §1-1) | 影(距離なし) | プレイヤー |
| **レーザー**(光線・狙撃線・`beam` 印の帯) | 光線の起点 | 影(距離なし) | **全員**(プレイヤー・守護霊・英雄・軍人) |

- **例外**:
  - プレイヤーの中心、または判定源が盾の矩形の中にある時は防がない(「後ろ」が決まらない)。
  - 判定源がプレイヤーの足元にある技(スカジの氷刃・巨人の g-quad/g-nova・矢の雨など、中心がプレイヤーに置かれる物)は、影が成り立たないので防げない。社長の決定(案A)どおり。
- **対象外**: 判定を持つ床(ジブリルの火・グレンの血溜まり)/ 敵の体の接触 / `projectiles` の敵弾(盾が既に消している)。
  死神の系統・裏ボスは盾を体ですり抜ける。この接触は既存の仕様どおり対象外。
- **味方の盾だけ**: `hostile !== true`(プレイヤー・守護霊の盾)。幻影の盾は何も止めない。
- **時間の一貫**: 判定源と盾はどちらも技の間に動かない。そのため、続けて判定する技でも「影に居る間は当たらない」で一貫する。プレイヤーが影から出れば当たる。

### 1-1. 帯の起点
- 既定: 帯の始点 `capsule.fx,fy`(敵の側の端)。
- 例外(起点を明示して運ぶ):

| 技 | 起点 |
|---|---|
| 伐採人の薙ぎ(`loggerSweepBand`・帯がプレイヤー方向と直交) | 伐採人の中心 |
| トール一閃(帯は固定、本体が上を走る) | 溜め開始の位置 `aiFrom` |
| トール突進の斬り抜け | 到達点 `dnx,dny` |
| スリエルの2本目 | `ring2X/Y` |

- 共通路(`pumpkinBlasts`)の帯に、任意の欄 `origin?:{x,y}` を足す。無ければ `fx,fy`。
  遅れて出る一撃(`giantDelayedHits`→gameStore 14823 で書き写す)も、`origin` と `beam` を書き写す。

## 2. 実装の形
- **純関数**(`src/world/shieldBlock.ts`、描画は import しない):
  - `friendlyShieldRect(projectiles)`: 味方の盾の矩形。無ければ null。
  - `inShieldShadow(src, target, shield)`: 影の判定。例外もここで処理する。
  - `shieldBlocksArea(src, targetRect, shield)`: 影 かつ 40px。
  - `clipBeamAtShield(ox, oy, ux, uy, len, shield)`: 光線の絵の長さ(中心線が盾に当たる所)。
- **差し込み口**: 各経路の「範囲に入った」の真偽を、**カウンター判定より前**に偽へ倒す。防いだ時は何も起こさない。
  - 起こさないもの: ダメージ・押し出し・英雄の回復・被弾反撃の窓・体勢削り・「斬」マーク・ヒットストップ・技の中断。
  - 溜めの最中に成立するカウンター(当たる時刻より前に決まる物)は今までどおり。
  - 共通路では、プレイヤーへの当たりだけを落とす。守護霊・英雄・軍人の処理は続ける(`continue` で飛ばさない)。
- **レーザーの第三者**: 各入口が受ける形に、任意の `shieldSrc?:{x,y}` を足す(`ThirdPartyShape` / `applyGhostAllyCapsuleHit`)。
  渡された時は、相手ごとに `inShieldShadow` で落とす。渡すのはレーザーの経路だけ。
- **レーザーの絵**: 描画は store の盾を読み、`clipBeamAtShield` で長さを切る。
  - 対象: ミミルのレーザー・光輪の各本 / スリエル1・2本目 / バス停 / バスマン狙撃 / アイドル狙撃 / ジブリルの槍 / 巨人の三連射(3本目を含む)/ g-sweepbeam。
  - 描く場所は実装時に1本ずつ列挙し、DEVLOG に残す。
  - 既知の限界: 光線は盾より太い。中心線が盾の端をかすめて外れた時は、絵は切れないのに、盾の後ろの相手は中心の影で守られる。
    逆の食い違い(絵は切れているのに当たる)は起きない。
- **防いだ演出**: 盾を光らせる(`shieldHitAt`)+小さな火花(`spawnBurst`)+`shield-deploy` を小さく鳴らす。
  盾の `shieldHitAt` から 250ms 以内なら出さない(状態は盾の欄だけ)。重い `shieldBlocks`(heavy-impact・画面の揺れ)は使わない。盾の耐久は減らさない(叩き台)。
- **bountyTick の狙いの点**: 1272/1831/1935 の判定は、狙いの点(守護霊のこともある)で行っている。これは変えない。影の線分だけ、本物のプレイヤーの中心を使う。

## 4. 受け入れ条件
1. 円・扇: 判定源から見て盾の後ろ、かつ盾から 40px 以内なら当たらない。41px で当たる。盾の横・前は今までどおり。
2. 帯: 起点から見て盾の後ろなら、距離に関係なく当たらない。
3. レーザー: 起点から見て盾の後ろの相手(プレイヤー・守護霊・英雄・軍人)には当たらない。光線の絵は盾で切れる(撮影で確かめる)。光輪は1本ずつ。
4. 判定源がプレイヤーの足元の技は、今までどおり当たる。
5. プレイヤーまたは判定源が盾の中なら防がない。幻影の盾は何も止めない。守護霊の盾はプレイヤーを守る。
6. 防いだ攻撃では、ダメージ・押し出し・カウンター・被弾反撃・英雄の回復が起きない。
7. 盾が無い時の挙動は1bitも変わらない(盾が無ければ関数は即「防がない」/長さそのまま)。
8. 防いだ演出は、同じ盾で 250ms に1回まで。
9. テスト:
   - 純関数: 影・40px 境界・中に居る時・光線の長さ。
   - 結合: 共通路(円・帯・`origin`・`beam`・遅れて出る3本目)/ ミミルのレーザー(プレイヤーと守護霊)/ アンジェル系の帯1本 / bountyTick の1経路。

## 5. 予告との関係(社長決定)
盾は掟の例外。盾の後ろで赤や紫が出ていても当たらないことがある。
防いだ瞬間に盾が光って鳴るので、「盾が受けた」と読める。発射の途中で盾が消えた時は、壁が無くなったのと同じ。

## 6. 負荷
1/10。盾は最大1枚。当たる瞬間に線分と矩形を1回。光線の絵は毎フレーム、光線の本数ぶん。
