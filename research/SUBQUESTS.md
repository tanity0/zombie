# サブクエスト設計 v1(2026-08-20)

> **この文書には未実装の設計が含まれます。実装済み部分の現行仕様の正はコード+DEVELOPMENT_LOG。案件の状態は PROJECT_STATUS.md を見る。**

## ゴール(社長の言葉のまま)
「これ基準にサブクエスト流し込んでおいて。基本は受注せず勝手に補充されてるタイプのクエストで、
UIは左側に条件表示。一つクリアすると次が次回プレイ時に補充される形。2つまでがいいかなー?とおもう。」
+ ステージ別概要表(本文末尾に転記)+共通方針「普段のプレイの延長で達成できることを優先。
収集・往復・長距離移動などのお使い系は避ける。」

## 裁定(2026-08-20・確定)
1. **報酬=ゴールド 20G〜200G**(難度による采配は設計に委任)
2. **カウントはラン跨ぎの累計**(必要数は累計前提で調整してよい=委任)
3. **プールは固定順**(軽→重の難度曲線)
4. **メイン+フリー周回どちらでも進む**(社長「というかフリー周回しかないので」)。
   練習(ボスモード)・ガントレットは対象外=practiceGuardが書き込みを封鎖するので追加実装不要。

## 「ではない」条件(労力をかけない所)
- 受注UI・クエストログ画面・資料室連携は作らない(左側の常時表示のみ。ログは後段候補)
- お使い系(収集・往復・移動)クエストは作らない
- 既存の二人組クエスト(eventQuest)には一切触らない(完全に別系統・画面上も混ざらない)
- 数値は全て叩き台(Stage1実測→横展開の前提)

## 方式
### 台帳(src/data/subquests.ts・新規)
- ステージごとの**固定順リスト**。1件=
  `{ id, stageId, order, label(表示文・数値は差し込み), kind, target, rewardGold }`
- kind(第1弾で使う種別のみ定義。実在フックに1:1で対応):
  | kind | 条件 | 進捗イベントの出どころ(実在配線) |
  |---|---|---|
  | kill-normal | 通常敵をN体 | damageEnemyのキル確定点(色ティア無し・ボス/賞金首/宿敵を除く) |
  | kill-tier | 色付き(blue/purple/red)をN体 | 同上(enemy.colorTier) |
  | kill-lab | ラボ敵Lv別にN体(stage-2) | 同上(lab-zombie-1/2/3の型) |
  | kill-colored | 色付き(ティア不問)をN体 | 同上(colorTier!==undefined) |
  | rescue | 生存者救助をN回 | 既存レスキュー完了処理(world/rescue系の完了点) |
  | miniboss | 小ボス(賞金首)をN体 | キル確定点(isBountyType) |
  | wanted | 宿敵(指名手配)をN体 | キル確定点(enemy.isNamed) |
  | horde-kills | 大量発生(horde囲い)中にN体 | キル確定点+囲いイベント種別='horde'の在中判定 |
  | rednight-kills | 紅き夜中にN体 | キル確定点+redNight.phase==='active' |
  | hunter-survive | ハンター追跡状態でN秒生存 | ハンターのalerted/追跡状態の継続計測(討伐不要・死亡/追跡切れでリセット) |
- **本文に数値を直書きしない**(チュートリアルの掟と同じ): labelは「通常の変異体を{n}体倒す」形式で
  target差し込み。バランス調整で文面が嘘にならない。

### 進捗と補充(src/utils/subquests.ts・純関数+localStorage)
- 保存キー: `zombie.progress.subquests` = `{ [stageId]: { cleared: string[], active: {id, progress}[] } }`。
- **補充=出撃時**(通常出撃のstartGame経路のみ): activeが2枠未満なら、そのステージのプールから
  **未クリアの次のorder**を補充。ラン中は補充しない(社長裁定「次回プレイ時に補充」)。
- **進捗はラン跨ぎ累計**: 変化のたびに保存(死んでも進捗が残る=累計制の意図)。
  ※保存頻度: キル毎のlocalStorage書き込みで問題ない量(1ラン百数十回・数十バイト)だが、
  実装は「値が変わった時だけ」書く。
- **達成=ラン中に即時**: 行がチェック表示になり、**ゴールドを即付与**+ポップ(+{n}G・既存の
  callout流用)+既存SE(reward系キー流用・新規素材なし)。リザルトにも達成行を出す(あれば)。
  達成済みの枠はそのランでは表示に残す(空欄にしない)。次回出撃で入れ替わる。
- **練習・ガントレット除外**: isPracticeRun()中は進捗判定ごとスキップ(保存はpracticeGuardが
  どのみち封鎖するが、**表示も出さない**=決闘のHUDを汚さない)。
- 瞬間系(horde/rednight/hunter-survive)も進捗自体は累計(例: 紅き夜10体は複数の紅き夜に跨ってよい。
  hunter-surviveだけは「連続N秒」なので1回の追跡内で満たす=リセット仕様をlabelから読める文にする)。

### UI(src/components/SubquestHud.tsx・新規)
- **画面左側・縦2行**の小型表示: 条件文+進捗「n/m」。達成行はチェック+淡色化。
- **React再レンダー規律(CLAUDE.md)**: 進捗の数値だけを購読する専用小コンポーネント
  (shallow selector・毎フレーム再レンダー禁止)。storeには activeSubquests の小さな配列
  (id/target/progress)だけ持ち、書き込みは進捗が動いた時のみ。
- 表示条件: 通常出撃(メイン/フリー)のみ。ポーズ・会話・演出中の扱いは既存HUDと同じ層に置くだけ
  (特別な出し入れはしない)。ズーム非依存(HUDはDOM層)。

### 報酬の采配(20〜200G・裁定1の委任分)
ステージ基礎(S1=1.0/S2=0.8/S3=1.2/S4=1.5/S5=1.8/S6=1.6)×種別重み(通常討伐=軽、色付き=中、
赤・宿敵・生存系=重)で20〜200Gに丸める。個別の額は台帳に直書き(下の叩き台表参照)。

確定した実装上の要点:
