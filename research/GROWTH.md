# 永続育成(強化)設計 v1(2026-08-20)

## ゴール(社長の言葉のまま)
「初期HP200くらいにしようか迷い中。もしくは多少育成要素を持たせるか」→ 育成案を採用。
「あー弾数はアリだな。移動は体感変わっちゃうなぁ」「攻撃力も多少増やせば?」
「いや、ゲームとして面白さが増すなら(敵側を)再調整してもいいと思ってる」
**原則(社長・確定)**: 「**体勢値とクリティカルのサイクルがある以上、縛りプレイ可能 ってバランスを
取れれば。**」= 無育成でも腕(カウンター→体勢→紫→処刑のサイクル)でクリア可能、が壁調整の下限。

## 「ではない」条件
- お使い・実績系の解放条件は無し(通貨はゴールドのみ)。スキルツリーUIの装飾は不要(リスト1枚)。
- 敵側の再調整(Stage4〜6の壁)は**この設計の範囲外**(育成着地→社長実機→別バッチで実施)。
- 数値は全て叩き台(実機で社長が調整)。

## 育成メニュー(5系統・叩き台)
| 系統 | 刻み | 段数 | 上限 | 価格カーブ(段n・G) |
|---|---|---|---|---|
| 体力 | +10 | 10 | **250**(初期150から) | 40×1.35^n 丸め(40,55,75,100,135,180,245,330,445,600) |
| 攻撃力 | +5% | 4 | **+20%** | 120,240,480,900 |
| マガジン | +1発 | 3 | +3発(全銃共通) | 80,200,450 |
| リロード | -5% | 4 | -20% | 60,140,300,600 |
| ゴールド獲得 | +10% | 3 | +30% | 100,250,500 |
- 総額≈6,000G(全カンスト)。収入の目安: サブクエ全消化≈3,000G+金箱/トレジャー/リザルト。
  「全部盛りは長期目標・序盤は取捨選択」の設計。
- **初期HPは110→150へ**(`STANDARD_MAX_HP` 1箇所=全クラス共通)。社長の「200」は育成の中間通過点。
  ※幻影のHPは初期プレイヤー参照なので自動で150に追従する。

## 適用点(写経禁止・全て既存の1本に乗る)
- **HP**: resetGame の `maxHealth = profile.maxHp + equipMaxHealthOf(...)` に**永続ボーナスを1項加算**。
- **攻撃力**: `skillOutgoingDamageMult`(全攻撃の合流点・錬金術の召喚バフが乗っているのと同じ式)に
  永続倍率を1項乗算=ナイフ/銃/カウンター反撃/サブウェポンへ漏れなく等しく効く。
- **マガジン/リロード**: プレイヤーの既存フィールド `magBonus` / `reloadMult`(レベルアップ強化と同じ
  変数)へ resetGame 時に永続ぶんを初期値として注入(ラン内強化はその上に従来どおり積まれる)。
- **ゴールド獲得**: `skillGoldRushMult` と同じ適用面(リザルト獲得・クエスト報酬)に永続倍率を乗算
  (ゴールドラッシュとは独立の項=両方持てば重なる)。

## 保存とUI
- 保存キー: `zombie.progress.growth` = `{ [系統id]: 段数 }`(進行系の名前空間)。
  練習・ガントレット中の購入は発生しない(購入はメニューのみ)が、practiceGuardの封鎖対象である
  ことは追加の安全網として明記。
- **UI: メニューに「強化」タブ1枚**(場所は既存メニューの構成に合わせて実装者が既存タブ列に追加。
  新規画面デザインは不要=リスト+現在段/上限+価格+所持ゴールド表示+購入ボタン)。
  購入時: 既存SE流用(`weapon-pickup`等の取得系)+行フラッシュ。ゴールド不足はボタン無効化。
- リザルト・タイトルには出さない(メニューだけ)。

## 縛りプレイ可能の担保(原則の機械化)
- **育成ゼロでも全コンテンツの判定・文法は不変**(育成は数値の加算のみ・新しい判定を作らない)。
- 壁の再調整(別バッチ)の受け入れ条件に「**無育成+カウンターサイクル習熟で突破可能**」を明記する
  (本設計書はその原則の宣言のみ・実調整は実機後)。
- 不変条件テスト: 育成0段のとき resetGame の結果が現行(150化後)と完全一致/各系統は上限で頭打ち/
  価格表は単調増加/保存キーが進行名前空間。

## 性能
負荷 1/10。per-frame追加ゼロ(全て resetGame 時と会計時の定数演算)。

## 実装地図(バッチ1本・中)
1. data/growth.ts: 台帳(5系統・段・価格・上限)+不変条件テスト
2. utils/growth.ts: 保存読み書き+段数→効果値の純関数+テスト
3. gameStore: resetGameのHP/magBonus/reloadMult注入+skillOutgoingDamageMult/ゴールド適用点
4. UI: メニュー「強化」タブ(React再レンダー規律=静的画面なので低リスク)
5. STANDARD_MAX_HP 110→150(1箇所)+既存テストの追従改訂
6. 検証: typecheck/lint+テスト

## ★未決(実装前に社長裁定が要るもの)

  **育成後のHP/攻撃力ボーナス**まで写すかは裁定が要る。

# v4 最終確定仕様(発注文・2026-08-20。全裁定済み=これ1節だけ読めば実装できる。旧節と食い違えばv4が勝つ)

## 概要
永続育成「強化」を追加する。**ゴールド購入・4系統×5段階・メーター式**(有効段数をいつでも下げられる)。
購入は拠点メニュー、効果は**次の出撃(resetGame)から**反映。育成は数値の加減算のみで、
**新しい判定・文法は作らない**(全メーター0=現行と完全一致、が最重要の不変条件)。

## 系統(4つ・各5段・価格は全系統共通 60/140/300/620/1,200G)
| 系統 | 1段あたり | 5段MAX | 適用 |
|---|---|---|---|
| 体力 | +20 | +100(130→230) | resetGame の maxHealth に加算 |
| 攻撃力 | +4% | +20% | skillOutgoingDamageMult に乗算 **+処刑枝にも適用**(下記) |
| 弾数 | +5% | +25% | **所持弾薬上限** = round(AMMO_MAX×(1+0.05×有効段))。**4種全部**(handgun 72→90 / shotgun 24→30 / rifle 36→45 / **phill 48→60**)。glauncherはライフル弾共用で自動追従 |
| ゴールド獲得 | +10% | +50% | 各付与点で乗算(下記の適用面リスト) |

## 前提変更(育成と同時に入れる)
- **初期HP: STANDARD_MAX_HP 110→130**(playerProfiles.ts の1箇所・全クラス共通)。
- `PLAYER_BASE_HP=120`(store初期プレースホルダ・守護霊台帳の記録基準)は**据え置き**。

## 各系統の実装詳細
1. **体力**: resetGame の `maxHealth = profile.maxHp + equipMaxHealthOf(...)` に育成加算を1項追加。
2. **攻撃力**: `skillOutgoingDamageMult` へ乗算(錬金術バフと同じ式に1項)。**加えて処刑ダメージ
   (体勢崩し×5/クリ×3: resolveStunnedMeleeHit / applyBrokenMeleeFatal 等、通常ヒット枝を通らない
   確定ダメージの枝)にも同じ倍率を掛ける**(社長裁定Q1=乗せる)。適用漏れ防止のため
   「近接処刑」の全経路を洗ってから配線する。
3. **弾数**: `AMMO_MAX` の直接参照(拾得・購入・弾ドロップ抽選)を `effectiveAmmoMax(category)`
   (純関数・有効段数を読む)へ差し替える。マガジン装填数・リロードは**触らない**。
4. **ゴールド獲得**: 適用面=①リザルト獲得(ghostGoldMultiplierと併せ「倍率を全部掛けてから最後に
   1回round」) ②サブクエ報酬 ③二人組報酬+useGameLoop側の吹き出し表示コピーも同時に直す
   ④宿敵トレジャー(NAMED_TREASURE_GOLD)。**掛けない**=ガチャ返金・死亡時の装備換金。
   実装は `addGold` の内側ではなく**各付与点で掛ける**(GoldRushと同じ作法・両方持てば重なる)。

## メーター式(購入と有効化の分離)
- 保存: `zombie.progress.playerUpgrades` = `{ [系統id]: { bought: n, active: n } }`。
  **常に 0≦active≦bought≦5**。購入は不可逆(返金なし)。activeはいつでも上下可・次の出撃から反映。
- storeフィールド+永続保存(purchasedSubLevels と同型)。UIとresetGameが同じstore値を読む。
- practiceGuard の封鎖対象(練習中に購入は発生し得ないが安全網として)。
- **ガチャリセット(resetGachaProgress)の消去対象に追加**(Gだけ消えて育成が残る片落ちを作らない)。

## UI
- **新 Screen('growth')+HubButton「強化」**。購入UIの作法は**開発施設の既存リストをそのまま流用**
  (spendGold→ui-select SE→Lv表示/MAX/価格→残高不足はdisabled)。
- 各行にメーター(有効段数の±)。リザルト・タイトルには出さない。静的画面=React再レンダー規律は低リスク。

## 写し先(社長裁定Q4=両方に写す)
- **守護霊**: スナップショット(playerBuild.ts)に**HP・攻撃力・弾数上限を明示的に写す**
  (「黙って写る/写らない」の非対称を無くす。スナップショット取得時の有効段数で焼く)。
- **幻影**: 「育成込みの初期状態」に変更。**GUARDIAN_PHANTOM_HEALTH はimport時評価でENEMY_STATSに
  焼かれているため、スポーン時に評価する関数へ変更**し、育成後maxHpを返す。幻影の銃ダメ・近接ダメ
  (phantomTick.ts の phantomMeleeDamage / 銃 createWeapon 経由)にも攻撃力育成を乗せる。
  (背景: 幻影は将来ステージ乱入敵にする構想=プレイヤーの現在の強さを写す)。

## 計測路の中立化
- **ボスメーカー/ガントレット(skillInjection分岐)では育成を0段として扱う**(TTK計測の基準が
  育成の進みでズレない)。通常のボス練習は乗る(プレイヤーの実力扱い)。

## DDA(社長裁定Q3=A案)
- `DDA_BASE_MAX_HP`(固定120)を**「そのランの開始時maxHP(育成込み・装備込み前の基礎)」**に
  差し替える=DDAはラン中に拾ったHP成長だけを見る。縛り勢(active=0)は現行と完全一致。
  初期130化も自動吸収(基準が130になるだけ)。

## サブクエ(裁定)
- **ボム(collectPickup 'bomb')の一括キルはサブクエに数えない**(配線しない・現状のまま)。

## 不変条件テスト(同コミットで機械化)
- 全系統 active=0 のとき: HP加算0/攻撃倍率1.0/弾上限=AMMO_MAX素値/ゴールド倍率1.0
  = resetGame の結果が現行(130化後)と完全一致。
- 0≦active≦bought≦5 を常に保証(active>boughtを書けない)。価格表は単調増加。
- メーター変更はラン中に効かない(次の出撃から)。保存キーは進行名前空間(playerUpgrades)。
- 幻影・守護霊の写し: 育成0のとき現行値と一致。

## ★Q3判断材料(DDA・difficultyScaler.ts実物確認済み 2026-08-20)
実物: `playerPower` に `max(0, maxHealth/DDA_BASE_MAX_HP - 1) × 4`(基準120)。
escalation は M>1.1 のときだけ発火し、色ティア/重い型のバイアスにのみ効く(HPや攻撃の直接強化ではない)。
- **HP育成MAX(+100)の影響量**: (230/120−1)×4 ≈ **+3.7PP ≒ レベル4個ぶん**。順調PPは開始4・
  +4.2/分なので、**序盤(0〜3分)ほど比重が大きい**=育成した人ほど開幕から重い型が出やすくなる。
- **A案(推薦)=育成ぶんを除外**: DDA_BASE_MAX_HP を「そのランの開始時maxHP(育成込み)」に
  差し替える(=DDAはラン中に拾ったHPだけを見る)。買った強さは敵の強化で相殺されない。
  縛り勢(active=0)は今と完全に同じ。初期130化も自動で吸収される。
- **B案=何もしない(反映)**: エルデン風の自動平衡。ただし効くのは色/型バイアスのみで
  「HPを買うと敵の当たりが痛くなる」わけではない=平衡としても中途半端。序盤の比重過大が難点。
- 攻撃力・弾数・ゴールド育成はDDAの入力に入っていないので、この論点は**HPのみ**。
