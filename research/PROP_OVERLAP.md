# ランダム配置の置き物どうしを重ねすぎない(設計書)

## 0. 社長の言葉(そのまま・2026-11-21)
「ステージ1に限った話ではなく、ランダムで置かれるオブジェクト同士が重なりすぎない様にってできる?」
「壁判定があるものもランダムでしょ?」→「はい、Bで」(=壁の判定がある物も含めて全部)

## 0-1. 「ではない」条件
- 手で置いている物(拠点・POIの建物・城・ボスの場所)は動かさない。ランダムな物の方が避ける。
- 置き物の数・密度・絵・判定の大きさは変えない(重なりすぎる1個を「選び直す/置かない」だけ)。
- 地雷(卵の群れ)と亡霊の発生物は対象外(罠・演出として近接配置が意図。後で別件)。
- 描画の倍率・遠近・被写界深度は触らない。スマホの画面の配置は1pxも動かさない。

## 1. 決まり
- 各置き物の「絵の矩形」= 足元を下辺の中心にした `{足元x − w/2, 足元y − h, w, h}`(遠近の倍率を掛ける前の基準寸法)。
  寸法の正は world 側の新しい台帳 `src/world/artRects.ts`。**木は箱に縮めて収まった実寸(幅約119·s × 高さ約133·s=`weatherPuddles.ts` の PUDDLE_TREE_ART_* と同じ値。箱 48·2.475×64·2.475 ではない)**。花・街の置物は絵の縦横比の表。回転のある置物(rotateDeg)は回転後の外接矩形で近似。
- **重なり率 = 2つの絵の矩形の交わりの面積 ÷ 小さい方の面積。これが 0.25 を超える置き方はしない**(叩き台)。
- 判定(壁)を持つ物どうしは、上の決まりに加えて **判定の矩形どうしの隙間を 28px 以上**(プレイヤーの体幅ぶん=通れない隙間を作らない)。叩き台。
- 違反した候補は、同じ区画の中で決まった乱数で最大 6 回選び直す。だめなら置かない。決定的(同じ場所には毎回同じ物)のまま。

## 2. 優先順位(上の物だけを参照する=循環しない)
手置き(POI の建物の絵を含む・拠点の円・城・ボスの場所・出撃地点)
> 木(屋外) / 研究所の壁(ステージ2。木は出ない) > 街/雪/ステージ5の置物・研究所の置物 > 松明 > 花 > 水たまり

- 各生成は**自分より上の層の最終配置**を見て避ける(上の層の最終配置もこの規則で局所に決まる=層の数だけの有限の依存)。
- **同じ層の中(監査A1・引く範囲によらず同じ答えにする規則)**: 各個体の候補は決まった乱数の列(1番目=今の位置、2〜7番目=選び直し)。
  - 同じ区画の中: 区画内の番号順に、先に決まった個体の最終位置を避ける(今の水たまりと同じ)。
  - 隣の区画(上下左右斜めの8区画)とは、**相手の「1番目の候補」だけ**と比べる。ぶつかったら、個体ごとの hash の優先値が低い方が選び直す(高い方は1番目のまま)。選び直した候補も、隣の全個体の1番目の候補を避ける。
  - これで各個体の最終位置は「自分の区画+隣8区画の1番目の候補+上の層」だけで決まり、描画と当たり判定で引く範囲が違っても同じ答えになる(テストで「範囲を変えて2回引いて一致」を固定)。
  - 残る例外=隣どうしが両方とも選び直した結果だけが重なる組。受け入れ条件で数え、全組の2%以下なら許容。
- 壊された物(isObstacleDestroyed / 研究所の broken)は**壊される前の配置**で判定する(壊すと別の物が湧く、を起こさない)。
- **研究所(監査A4)**: `labWallsInRegionRaw` / `labPropsInRegionRaw` は**選び直した後・壊す前**の位置を返す(ここが唯一の正)。`nudgeToClearLabSpot`・`labObstacleRectsNear`・`coverPropsInRegion` もこれを引く=古い位置を見ない。
- **保証の遮蔽(監査A2)**: 研究所の遮蔽(`coverPropsInRegion`・v0.25.2243「どの敵からも225px以内に必ず1つ」)は**「置かない」にしない**。選び直してもだめなら元の位置のまま置く。
- **地面のデカール(監査A3)**: `cityProps` の `decal: true`(地面に貼る弾倉・骨など)は**対象外**(他を避けず、他からも避けられない)。地面に平らに貼る物で、立った絵と重なっても不自然でない+ステージ5の「散らばってる方が雰囲気出る」を守る。
- 研究所の壁どうし(同じ生成の上段/下段・同じ列)の隙間は設計どおり=28px の決まりの対象外。
- 松明は RELAX の追加確率を含めた**最大の閾値**で判定する(呼び手で置かれ方が変わっても重ならない)。
- POI の空き地は建物の絵の高さぶん奥(−200)まで広げて判定する(今は水たまりだけが見ている)。拠点・城も全生成が避ける。

## 3. 重さの対策
- 区画ごとの結果をメモ(キャッシュ)。鍵 = 区画+stageId/farKey+「空き地・手置きの版」+無効化フラグ(木/置物/花)+出撃の通し番号。空き地の更新・ステージ切替・新しい出撃で捨てる。**上限 512 区画(古い順に捨てる)**。
- 拠点・城・ボスの場所は `setPoiClearings` と同じ形の口(`setHandPlacedAnchors`)で world 層へ渡す。拠点は隠れている間(loop1Hidden)も位置は避ける(出現で中身が変わらないため)。
- 松明は RELAX の追加確率込みの最大で判定する=平常時は存在しない松明のぶん花・水たまりに小さな空きができる(許容)。
- 毎フレームの当たり判定(木・置物の衝突)は、メモ済みの区画を引くだけ=今と同じ重さ。
- 負荷目標 1/10(初回の区画生成だけ少し増える)。

## 4. 受け入れ条件
- (ステージ6/EX は通路の疑似3Dでランダム配置が無いので対象外)
- ステージ 1/2/3/4/5/7 の各生成で、絵の矩形の重なり率が 0.25 を超える組が 0(テストで ±4000 を数える)。**ただし §2 の「同じ層の隣どうしが両方とも選び直した組」だけは全組の2%以下を許容**(数えて報告)。
- 同じ座標を、引く範囲を変えて2回引いても同じ結果(描画の範囲と当たり判定の範囲で食い違わない)。
- 判定を持つ物どうしの隙間が 28px 未満の組が 0。
- 手置きの物(拠点・POI の建物の絵・城)に、木・置物・松明・花が掛からない。
- 決定的: 同じ座標を2回引いて同じ結果。
- 置き物の数は、ステージごとに 85% 以上残る(減りすぎない)。下回るステージは報告。
- スマホの画面の配置チェック(phone-guard)が変わらない。ステージごとに前と後の画(最大引き 0.4 も)。
