# ボス・ガントレット(全ボス×bot実機テスト)設計 v2

## ゴール(社長の言葉のまま)
「一度全ボスとの戦闘テストを並行して何人かのＡＩで戦わせてバグがないかテスト回したい。ＡＩ実機でやるので設計して」
→ 方式は社長裁定「案A」(v0.25.3600): **土台=練習ラン(ボスラッシュ)・1タブ順次・カウンターは反応表の記録読み**。

## 「ではない」条件(労力をかけない所)
- **製品画面ではない**(開発ツール。見た目・UXに労力をかけない)
- **バランス計測ではない**(勝率・TTKの精密統計は目的外。目的は**バグの検出**)
- **botの腕前の改善は別件**(既存bot=masterをそのまま使う。bossState技へのカウンターを
  botに教えることはしない=「カウンター不成立」を合否判定にしない)
- **完全な再現性(リプレイ)は対象外**(botはMath.random駆動。発見の手掛かりログまでで良しとする)
- **ヘッドレスではない**(実機=実レンダラ・実速。ただし描画の「見た目の崩れ」の自動検出は
  作らない——検出は例外・コンテキストロストまで。見た目は社長が時々画面を見る)

## 方式(v1からの変更=監査22件の反映。土台は全部既存物の接続)
- **土台=練習ラン(ボスラッシュ)**。`beginPracticeRun`(bossPractice.ts)は**リロード無し**で
  通常出撃と同じ経路に入り(v0.25.2862)、**実ステージ・実出現経路・無敵なし・撃破で
  practiceWin・進行書き込みはpracticeGuardで封じ済み**。ボスメーカー部屋は使わない
  (bossTest.ts自身が警告する人工部屋の偽陽性/城ボス不在/無敵既定ON/メーカー調整値の混入を
  全て回避)。
- **対象=PRACTICE_SLOTS 全22枠**(賞金首4+城ボス7+ゲート2天使+裏ボス+アイドル。
  グレンは合体裁定v0.25.3600により**1枠で形態1→形態2まで通し**)。
  ガントレットは開発ツールなので**解放(遭遇)ゲートは見ない**。唯一 `giantbat@stage-2`
  (城ボス不在=どうやっても出ない枠)だけスキップし、スキップした事実を結果に明記する
  (無言の間引きをしない)。実戦枠=**21**。
- **進行**: `?gauntlet=1`(+既存 `?bot=standard&botskill=master` 相乗り)で、タイトルから
  自動で練習ランを枠順に開始→1戦の終了(**practiceWin / bot死亡 / タイムアウト180秒**・叩き台)
  →結果を記録→`endPracticeRun`→次の枠を `beginPracticeRun`。**全周リロード無し**なので
  記録はメモリ保持+localStorageバックアップ(単一キー・走行ID付き)。
- **並行はしない(1タブ順次)**: バックグラウンドタブはrAFが止まるため多タブ並行は不成立
  (監査2)。21枠×最大3分+遷移≒**70〜90分を1タブ放置**。社長は時々画面を見るだけ
  (=「見た目の崩れ」の目視も兼ねる)。
- **プレイヤー条件**: 社長の実データ(実機の現行装備・レベル)で出撃する。素のLv1では
  HP2万級を180秒で削れない(監査5)。タイムアウトは**敗北ではなく「時間内に削れず」の記録**
  (バランスは別件)。
- **URL規約**: `ghost=1` を混ぜない(守護霊が居ると反応表sessionが破棄される=監査18)。
  ガントレット起動時に守護霊同行をオフにして走る。

## バグ検出器(既存の台帳・集計の接続。新しい"判定"は作らない)
| # | 検出 | 実体と扱い |
|---|---|---|
| 1 | **技キャンセル違反** | `createMoveCancelWatch` を実戦bossStateへ常時接続。**既知の穴を明記**: windup接尾辞の無い状態への遷移と1フレーム内の中立挟みは見えない(監査15)。網の目はその範囲で読む |
| 2 | **ソフトロック** | 同一bossState 20秒 / ボス15秒無動作(叩き台)。**時計はgameTime**(実時間だと熱ダレで誤検知=監査19)。除外リスト: dormant・帰巣(return系)・休憩(idol-rest等)・pause中 |
| 3 | **技への反応表** | 既存 `notifyMoveDamage`/`notifyMoveCounter`(playerTraits)の**記録読み**。技キー別の機会/成立/被弾を1戦ごとに出力する。**「カウンター不成立=バグ」判定はしない**(botはbossState技を振らない=監査4。`COUNTER_REACH_DECL` が 'none'/'body' の技も混ざる=監査13/14)。表は人間(設計チャット)が読む材料 |
| 4 | **技カバレッジ** | 1戦で一度も出なかった技(賞金首/天使/裏ボスの技表と突き合わせ)。実HP+実装備でP2も踏むので形態2の技も対象 |
| 5 | **console error / 未捕捉例外** | `window.onerror` + `unhandledrejection`(監査20) + `console.error` フック + **WebGLコンテキストロスト**(canvasの`webglcontextlost`イベント1本) |
| 6 | **座標・状態の異常** | NaN座標 / playableArea外5秒以上 / HP・体勢の負値 |

v1の「赤外被弾」検出器は**撤去**(監査13: COUNTER_REACH_DECLは成立域でありダメージ判定形状では
ない。判定形状の読み口を新設するのは「新しい判定を作らない」方針に反する)。代わりに
被弾内訳(bossState別=`damageSourceMove` 経由)を3の表に含め、不審な被弾は人間が拾う。

## 記録と出力
- 1戦ごと: `{slotKey, 結果(win/death/timeout), 所要(gameTime), 発見[{種別, 詳細, bossState, 時刻}], 技別反応表, 被弾内訳}`
- 発見には**その瞬間のbossState・ボス/プレイヤー座標**を添える(リプレイは無いので、
  再現の手掛かりはこれが全て=監査12への回答)。
- 完走時: 画面に要約表(枠×発見数)+「コピー」ボタン(ボスメーカーのコピー導線と同じ作法)。
  途中経過も毎戦localStorageへ追記(単一キー・走行ID・ブラウザ落ちでも戦績は残る=監査11)。
- スキップした枠(giantbat@stage-2)と、走行時の条件(装備概要・bot設定・バージョン)を
  ヘッダに焼き込む(条件の無い計測結果は資料にならない、のベンチ規約と同じ)。

## 実装地図(見積もり)
1. ガントレット制御: 枠index+戦績配列+終了検知(practiceWin/死亡/タイムアウト)→
   `endPracticeRun`→次枠`beginPracticeRun` のループ(**リロード無し**が土台の利点。中)
   - 純関数化: 「次の枠」「終了判定」「要約集計」は `src/utils/gauntlet.ts` に切り出して
     ユニットテスト(実装精度の規律4)
2. bot同乗の確認: 既存bot分岐(通常ページ)が練習ランでもそのまま効くかの実在確認(小)
3. 検出器: 1(接続)/2(gameTime時計)/5(フック3本)/6(条件3つ)=小。3・4は既存集計の
   出力整形=小〜中
4. 要約表+コピー(小)
- **負荷 1/10**: 検出はイベント時のみ記録。毎フレームは2の時計と6の条件比較だけ。
  記録はメモリ配列+戦間のlocalStorage書き込み1回

## 運用(社長の手順)
1. 守護霊をオフにして、`?gauntlet=1&bot=standard&botskill=master` で開く
2. 放置(≒70〜90分)。時々画面を見る=見た目の崩れの目視を兼ねる
3. 終わったら「コピー」を貼る → 設計チャットが分析

## ★未決(社長裁定が要る点)
- タイムアウト180秒は叩き台(実測で調整。実装備なら大半は3分未満で決着の見込み)
- 出撃順: 台帳順(賞金首→城→天使→裏)で良いか
- 走行に使うセーブ: 社長の現行データで良いか(それが一番「実」に近い)
