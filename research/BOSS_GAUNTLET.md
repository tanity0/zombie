# ボス・ガントレット(全ボス×bot実機テスト)設計 v3

> **この文書は設計時の姿です。現行仕様の正はコード+DEVELOPMENT_LOG。案件の状態は PROJECT_STATUS.md を見る。**

## ゴール(社長の言葉のまま)
「一度全ボスとの戦闘テストを並行して何人かのＡＩで戦わせてバグがないかテスト回したい。ＡＩ実機でやるので設計して」
→ 方式は社長裁定「案A」(v0.25.3600): **土台=練習ラン(ボスラッシュ)・1タブ順次・カウンターは反応表の記録読み**。

## 「ではない」条件(労力をかけない所)
- **製品画面ではない**(開発ツール。見た目・UXに労力をかけない)
- **バランス計測ではない**(勝率・TTKの精密統計は目的外。目的は**バグの検出**)
- **botの腕前の改善は別件**(既存bot=masterのまま。「カウンター不成立」を合否判定にしない)
- **完全な再現性(リプレイ・シード固定)は対象外**(発見の手掛かりログまで)
- **描画の「見た目の崩れ」の自動検出は作らない**(例外・コンテキストロスト検出+社長の目視まで)
- **音まわりは対象外**(自動起動はユーザージェスチャを踏まないため音が出ない。仕様であり不具合ではない)

## 方式
- **土台=練習ラン(ボスラッシュ)**。`beginPracticeRun` はリロード無しで通常出撃と同じ経路に入り
  (v0.25.2862)、実ステージ・実出現経路・無敵なし・進行書き込みはpracticeGuardで封じ済み。
- **対象=PRACTICE_SLOTS 全22枠**(内訳: 賞金首4+城ボス7+ゲート2天使6+裏ボス4+アイドル1。
  グレンは合体裁定v0.25.3600により1枠で形態1→形態2通し)。解放(遭遇)ゲートは見ない。
  `giantbat@stage-2`(城ボス不在=出ない)のみスキップし、その事実を結果に明記=**実戦21枠**。
  ※suriel@stage-6 / acrasiel@stage-ex1 は本編到達不能だが練習経路では出る(v2監査で実在確認済み)。
- **進行**: `?gauntlet=1`(+既存 `?bot=standard&botskill=master` 相乗り)。**App内に専用の駆動を新設**
  (既存`?smoke`は`beginPracticeRun`を通らず進行が汚れるため流用しない)。1戦の終了=
  **practiceWin / bot死亡 / タイムアウト180秒**(叩き台)。
  - **枠の切り替えは「次枠の `beginPracticeRun` を先に呼んで activeSlot を切れ目なく差し替え → `startGame`」**
    (endPracticeRunを先に呼ぶと一瞬 isPracticeRun()=false になり、遅れて来た勝敗遷移が通常経路=
    セーブ汚染へ落ちる)。タイムアウト打ち切りも同じ「次枠のstartGame直呼び」で行う
    (gameTime巻き戻し検知で強制出現refが全て再アームされることを監査で実在確認済み)。
  - **ガントレット中は PracticeResult / GameOverScreen を描かず即次枠へ**(自動運転の画面遷移を挟まない)。
- **並行はしない(1タブ順次)**: バックグラウンドタブはrAF停止のため。21枠×最大3分+遷移≒
  **70〜90分を1タブ放置**。社長は時々画面を見る=見た目の崩れの目視を兼ねる。
- **プレイヤー条件**: 社長の実データ(現行装備・レベル)で出撃。タイムアウトは敗北ではなく
  「時間内に削れず」の記録(バランスは別件)。
- **守護霊は走行不可**: 起動時に守護霊が有効(`?ghost=1` **または装備スキル「守護霊」**)なら
  **走行を開始せず理由を画面に出す**(反応表が全滅する+ボスHPが変わるため。装備を外して再走)。
  装備を無視して走る案は仕様に触るので採らない。

## 状態の表記(実装者向けの前提)
ボスの状態は **`enemy.bossState ?? enemy.aiPhase`** で読む(城ボス7枠=giantbatは`aiPhase`機械で
`bossState`はundefined)。以下「状態」と書いたら全てこの合成を指す。

## バグ検出器
| # | 検出 | 実体と扱い |
|---|---|---|
| 1 | **技キャンセル違反** | `createMoveCancelWatch` を実戦の状態へ常時接続。**接続前に既知の設計連携を申告表(ALLOWED_MOVE_CHAINS)へ追加**: `g-quad-charge→g-quad-breath-windup`(城ボス全枠)/ ミゲル `harai→tate-windup`(未申告のまま繋ぐと最多枠で毎戦誤検知)。既知の穴を明記: windup接尾辞の無い状態への遷移・1フレーム内の中立挟み・命名規約外の `g-nihil-chant1/2/3` は見えない |
| 2 | **ソフトロック** | **時計は2本**: ①gameTime基準「同一状態20秒/ボス15秒無動作」(熱ダレ耐性) ②実時間基準「実時間30秒進んだのにgameTimeがほぼ進まない」(hitstop/attention固まり=本プロジェクト最多のハング型はgameTime時計では原理的に見えないため)。除外: dormant・帰巣・休憩系・pause |
| 3 | **技への反応表** | `moveTally`(playerTraits)を**1戦ごとにsnapshot/resetする読み口をexport**して読む(現状は撃破セッションのみcommit+読む口なし+resetPlayerTraitsで消えるため、**接続だけでは取れない**。読み口は記録専用・挙動不変・snapshotはディープコピー=集計の掟3)。賞金首もこの読み口なら取れる(clearedSlotsゲートを通らない)。「不成立=バグ」判定はしない(表は人間が読む材料) |
| 4 | **技カバレッジ** | 1戦で一度も出なかった技。**per-bossの技表を先に作る**(`MELEE_STATE_TO_MOVE`等は非export・全ボス横断フラットしか無く、突き合わせ相手が現存しない=このバッチで台帳化してexport+テスト) |
| 5 | **console error / 未捕捉例外** | `window.onerror`+`unhandledrejection`+`console.error`フック+`webglcontextlost`(**windowのcaptureで取る**=canvas再マウントで張り直しが要るため)。既存の「1回きりフラグ」(bossCtrlErrLogged等7箇所+errorBeacon)は**枠切替で再アームする口を足す**(現状はページ寿命=2戦目以降が無音) |
| 6 | **座標・状態の異常** | NaN座標 / HP・体勢の負値 / **ボスとプレイヤーの距離が異常(>4000px・叩き台)**(playableArea帯は21枠中2枠にしか存在しないため場外基準を距離へ変更) |

- **被弾内訳の前提整備**: `damagePlayer` の `damageSourceMove` タグは現状7/32箇所しか付いておらず、
  天使・賞金首の近接/AoEはほぼ全部「被弾」が「回避」に化ける。**タグ付けバッチ(約25箇所・記録専用・
  挙動不変)を同時に行う**(ゲーム側の反応表の正確さも上がる=ガントレット外にも利く)。

## 記録と出力
- 1戦ごと: `{slotKey, 結果(win/death/timeout), 所要(gameTime), 発見[{種別, 詳細, 状態, ボス/プレイヤー座標, 時刻}], 技別反応表, 被弾内訳}`
- 完走時: 画面に要約表(枠×発見数)+「コピー」ボタン(ボスメーカーのコピー導線と同じ作法)。
- 途中経過の保全: **毎戦localStorageの専用1キーへ追記**……は practiceGuard(許可3キー以外全遮断)が
  落とすため**★裁定待ち**(§裁定)。裁定までの設計は「メモリ保持+毎戦 `console.info` へJSON1行」
  (タブが生きていればコピーで全量、落ちたらconsoleログが手掛かり)。
- ヘッダに走行条件(装備概要・bot設定・バージョン・スキップ枠)を焼き込む。

## 実装地図(見積もり)
1. ガントレット駆動(App内新設): 枠index+戦績+終了検知+切れ目ない枠差し替え+結果画面の迂回(中)
   - 純関数化: 「次の枠」「終了判定」「要約集計」は `src/utils/gauntlet.ts` へ切り出しユニットテスト
2. 読み口の整備(全て記録専用・挙動不変): moveTallyのsnapshot/reset export(小)/
   エラーフラグ再アーム口(小)/ per-boss技表の台帳化+テスト(中)
3. 被弾タグ付けバッチ: damageSourceMove 約25箇所(中・機械的)
4. 検出器接続: 1(申告表2件追加+接続)/2(時計2本)/5(フック4本)/6(条件3つ)=小
5. 要約表+コピー(小)
- **負荷 1/10**: 検出はイベント時のみ。毎フレームは2の時計と6の比較だけ。

## 実装(v0.25.36xx)
- 駆動: `src/components/GauntletRunner.tsx`(`?gauntlet=1`。App が `startGauntletSlot`/`finishGauntlet` を渡す)
- 判定(純関数)+検出器: `src/utils/gauntlet.ts`(+ `gauntlet.test.ts`)
- 読み口: `playerTraits.snapshotMoveTally/resetMoveTally`(ディープコピー)/
  `moveReaction.MOVE_KEYS_BY_BOSS_TYPE`(per-boss技表・導出)/
  再アーム口 `useGameLoop.rearmLoopErrorFlags`・`PixiScene.rearmDrawErrorFlag`・
  `pixi/renderErrorFlags.rearmRenderErrorFlags`・`errorBeacon.rearmSuppressedError`
- 申告表へ2件追加: `g-quad-charge -> g-quad-breath` / `harai -> tate`
  (**キーは状態名ではなく `parseMovePhase` 後の技名**。`-windup` 等の接尾辞は落ちる)
- 実装で分かった運用メモ:
  - **`?autotut=1` は付けなくてよい**。駆動がチュートリアルのポップアップを「OKを押す」のと同じに
    閉じる(閉じないと stage-2 でポーズしたままシミュが1フレームも進まない)。
  - 1戦の時計は**実時間**(gameTimeごと固まるハングも必ず切れる)。出撃ローディングの時間も
    その180秒に含まれる(キャッシュが温まっていれば1秒程度)。
  - ソフトロックの**実時間の時計はボスが居る間だけ**回す(ローディング中の gameTime 停止を
    ハングと誤検知しないため)。
