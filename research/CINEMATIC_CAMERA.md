# ダイナミック・カメラワーク(ズーム/斜めの時)— 相談用設計案 v2(監査1巡を反映)

- 発端: 社長 2026-09-14「ズームとか斜め処理のとき、FF7リバースみたいに、ダイナミックにカメラワークさせたい」。
- 状態: **社長承認2026-09-14「はい」→ v0.25.4294 で v2 を実装済み(ロールは見送り=§2-4)。数値は叩き台。**
- 対象: 寄りズームのイベント(KILL/処刑・カウンター成立・死亡・救急/救援)の **カメラの動き**(描画のみ)。
- 対象外: 判定・ダメージ・ヒットストップ/スローの長さ・HUD(DOM・固定)・敵/ボスの技のカメラ(別の物差し)・絵(血/光/斬撃)。

## 1. 今の実態(事実)
| 要素 | 今 | 出どころ |
|---|---|---|
| 寄り(パンチズーム) | 命中の瞬間に**即**×2(1+zoomMag 1.0)→**560ms保持(動かない)**→140msで戻す | `triggerZoom`・`computeTimeSlowScale` の hold→ramp |
| 寄り先 | 対象(KILL=倒した敵/死亡=自機)を**画面中央**へ(`ZOOM_TARGET_CENTER_FRAC=1`) | pixiScene 寄り軸のずらし |
| 斜め(zwarp) | 台形の遠近(最大 0.22)。**最初の1コマで最大**→100ms保持→320msでほどける(ばね) | v0.25.4288 |
| 停止/スロー | ストップ100ms→スロー0.2(700ms・保持560) | `triggerHitImpact`/`triggerFinishImpact` |
| 揺れ | ダメージ由来(SHAKE_UNIFY)。処刑は天井14 | v0.25.4284〜 |
| 追従カメラ | 通常時は τ=0.16s の遅れ追従 | `CAMERA_FOLLOW_TAU` |
| 無いもの | **ロール(傾き回転)・保持中の動き(押し込み/横滑り)・三分割の構図・演目ごとの違い** | — |

**読み取れること**: 寄った瞬間から戻るまで**カメラが止まっている**(保持560msが静止画)。FF7Rの「動いている感」は
①寄りながらさらに寄る(押し込み) ②対象の周りを少し回る(横滑り) ③わずかな傾き(ロール) ④主役と相手の両方が入る構図、の**組み合わせで
カメラが常に動き続けている**ことから来る。今は①〜④が全部無い。

## 2. 案 v2(監査1巡=16件を反映。描画のみ・判定/座標/HUDは不変)

### 2-0. 骨格を変える: 「振幅の表」ではなく「演目ごとのキーフレーム台本」(監査1・2・5)
- store に **演目1つ** `cineEvent = { kind: 'kill'|'counter'|'death'|'rescue', startAt, targetX, targetY, dirX, dirY }` を持つ
  (今の `triggerZoom` は mag/尺/寄り先しか持たず**種類が渡っていない**=純関数の入力が無かった)。呼び手(処刑/カウンター/死亡/救援)が種類と
  **相手の座標**(カウンターは今 pan の軸が無い→成立位置を渡す)を書く。
- カメラは `src/utils/cineCamera.ts`(純関数)が **kind ごとの台本**(イン/保持/アウトの**秒数と形を別々に**)を読んで
  `{ zoomFrac, panX, panY, cutAt }` を返す。pixiScene は読むだけ。**振幅ではなく時間構造で演目を分ける**。
- **重なりの規則**: 演目に優先順(death > kill > counter > rescue)。進行中より低い/同じ順位の新イベントは**捨てる**(再キックしない)。
  高い順位は割り込んで最初から(今の `triggerZoom` の「継続中は保持して max 合成」は台本の外=そのまま)。

### 2-1. 台本(叩き台)
| 演目 | イン | 保持 | アウト | 構図 |
|---|---|---|---|---|
| **KILL/処刑** | **カット**: 命中の瞬間、相手側の三分割構図へ**飛ぶ**(連続移動しない・ストップ100msの間は静止画=強い1枚)。寄り**50%**(v0.25.4295: 85→70 / v0.25.4301: 70→50=押し込みを見える量に) | ストップ明けから **押し込み** 50→100%(ease-out・保持の前半40%で到達=「一番寄る瞬間=スローの一番遅い区間」の裁定を保つ)。後半は**横滑り**(画面幅14%・v0.25.4301: 8→14・自機側へ・smoothstep) | 戻り=既存の共有包絡線(140ms・easeOut)のまま。**行き過ぎ(ばね)は未実装**(v0.25.4295 監査(C): 記述を実態へ。包絡線は演目ごとの冪 outPow で形だけ変える) | 相手を自機の反対側の三分割線に。相手座標は `killFx.ex/ey`(処刑中は寄り先が自機の見た目位置に上書きされるため) |
| **カウンター成立** | 即100%+**ズームのばね**(122%→100%・70ms。v0.25.4295: 112% / v0.25.4301: 122%) | **短く**(240ms)。横滑りは**逆側へ1拍**(9%・速く出て遅く戻る。v0.25.4301: 5→9) | **硬く切る**(80ms・ease-in) | 成立位置(渡す)を三分割に |
| **死亡** | 60→100%を**ゆっくり**(1.15s・ease-in-out) | 保持 | 今のまま | 自機中央(今のまま) |
| **救急/救援** | 今のまま(小さい寄り・台本なし) | | | |
- **予備動作**(監査3): 寄る前の引きは「命中の瞬間」より前に出せないので入れない。代わりに**アウトの行き過ぎ(ばね)**で重さを出す。
- **既存裁定(事実)**: v0.25.1524「一番寄る瞬間=スローの一番遅い区間」。押し込みの到達を**保持の前半**に置くことで両立させる(最大寄りは保持の中)。

### 2-2. pan(寄り軸)の一本化(監査7・8・12・13)
- 中央寄せ+三分割+横滑りを**1つの目標点**に合成してから既存のクランプ(`panLimit=(1−1/zoom)×画面半分`)に掛ける。
- **pan が効かない時(演目の最大寄り `base×(1+mag)` < 1=最大まで寄っても `panLimit=0`)は pan 無し版**=押し込みとカットだけ(横滑り/三分割は出ない、と先に決める)。
  **v0.25.4300〜4301**: 判定は `cineModeFor`(cineCamera.ts)。v0.25.4298 までは寄り込み前の base で判定しており、群衆戦(近傍8体以上・文脈ズーム0.8)と
  ボス戦(ボス距離ズーム0.40〜0.7)の処刑が全て縮小モードに落ちていた(§6-2b)。4300 はカット時点の値、4301 でカットを広げた(0.5/0.4)ため
  最大寄りの値に(カットの瞬間は panLimit=0 でも押し込みで 1 を超えた所から横滑り・三分割が育つ=それ自体が慣性)。
- tilt-shift のピント帯 `bandFocalY` は**この目標点**を見る(今は `zoomTargetY` 固定=滑らせた先がボケる)。

### 2-3. 向き(監査9)
- 横滑りの向きは **zwarp の奥側(左右)と同じ側**の1本に統一(「攻撃方向と直交」はやめる=縦成分を持たせない。上下5副作用を踏まない)。
  カウンターは逆側。真上/真下の攻撃は zwarp と同じ fallback(前回と反対側)。

### 2-4. ロールは**今回見送り**(監査10・11・13)
- zwarp は worldGroup のフィルタで、フィルタ枠(`syncWorldFilterArea`)・台形の頂点・立ち絵の逆変形(`counterWarpActors`)が**回転を前提にしていない**。
  親を回すと枠が AABB になり台形がずれる。加えて画面空間の層(速度線/帯外減光/廊下背景/遠景森)が回らず縁がずれる。
- **推薦: ロールは積む**(zwarp の枠整合を回転込みに作り直す別案件)。2D では**カット+押し込み+横滑り**の方が効く(監査の代替案)。
- 事実: v1 では ±2.5° を推薦していた。

### 2-5. 時間軸(監査14・16)
- 命中の瞬間: **カット**(pan/寄り85%へ即)+ zwarp(最初の1コマで最大・v0.25.4288 のまま=zwarp の入力は**旧包絡線**に据え置く。押し込みの
  60ms ランプを zwarp に渡さない)。ストップ100msは静止画。
- ストップ明け: 押し込み開始・揺れ(registerImpact・既存)・横滑り。
- 追従カメラ(τ=0.16s・実時間)は演目中も store 側で動き続ける → **アウトの終点は「その時点の追従カメラ」へ滑らかに合流**(戻し終わりの二度目の動きを作らない)。

### 2-6. モード(監査15)
| モード | 台本 |
|---|---|
| 通常ステージ | 全部 |
| 訓練/エンディング(camY 1:1 固定) | 押し込みのみ(カット/横滑り/三分割なし) |
| 洋館通路/EX(帯が狭い) | 押し込みのみ |
| 演目の最大寄り base×(1+mag) < 1(巨大ボス遠距離0.40×2.0=0.8 など) | 押し込み+カットのみ(2-2)。群衆の引き0.8・通常ボス0.7 は最大寄りで1を超えるので full |

### 2-7. やらないもの(今回)
レターボックス / モーションブラー・放射ブラー(フィルタ増) / **ロール**(2-4) / 敵・ボスの技のカメラ。

## 3. 負荷・安全

- 慣性MUST: カットは「別アングルへ飛ぶ」=カメラの**切り替え**であって物の動きではない(映画のカット)。切り替え以外の全段に ease/ばね。
- 純関数+テスト: 台本の単調性・保持前半で最大・優先順・zoom<1 で pan 0・モード表。

## 6. ★第2弾: 「近景をわざとカメラに切れさせる」=1枚絵の構図(社長2026-09-14・**「はい」→ v0.25.4296 実装済み**・6-6 の4件も同時に実装)

社長の言葉: 「ズームになったとき、近景をわざとカメラに切れさせるとかで演出ってどうかな? 斜めになってる感も、近景などが斜めにわざとかぶって大きくいる
(ただしカメラ中央はくっきり)ことで、1枚絵としての世界観を演出するチャンスではないか」。

### 6-1. 何を作るか
- 寄りの演目(KILL/処刑・死亡。カウンターは320msで短すぎる=対象外の推薦)の間だけ、**画面の縁に大きな近景のシルエット(1〜2枚)を割り込ませる**。
  木の幹/枝・街の柱/瓦礫・松明・霧の房。**ボケていて暗く、斜めに傾いている**。中央(寄り先=三分割の点)は**くっきり**のまま。
- **「斜め」はここで取る**: 世界(worldGroup)を回すと zwarp の枠が壊れる(§2-4)が、近景の板は**画面空間のスプライト**なので**自由に回してよい**。
  台形の奥側と同じ向きへ 6〜12° 傾けて重ねる=「斜めになってる感」を板で増幅する。
- 動き: カットの瞬間に縁の外から**滑り込み**(慣性・わずかに行き過ぎて止まる)、保持中は**横滑りの逆方向へゆっくり流れ**(手前ほど速く動く視差=奥行き)、
  戻りで縁の外へ抜ける。全段 ease。

### 6-2. どこから板を取るか
| ステージ | 板の候補(近くの実在物を優先・無ければ汎用) |
|---|---|
| 森(S1/S4/S5) | プレイヤー近傍の木の幹(`treesInRegion`)・枝のシルエット・霧の房 |
| 廃都(S3) | 街プロップ(柱/瓦礫/看板)・煙 |
| 研究所/通路 | 無し(帯が狭い=押し込みのみ・§2-6と同じ) |
- 実在物が近くに無い時は**汎用の霧の房/枝**のテクスチャ(既存 `frontForest` の素材を流用)。**新しい素材は作らない**(まず既存で)。
- 置き場所: **自機側の縁**(奥=zwarp の側の反対)。上下は寄り先の反対の角。板は**縁の25〜35%**を覆う(小さいと「無い」と同じ=大きく)。

### 6-2b. 事実(監査 v0.25.4298 で追記)
- 三分割は既存の安全上限 `panLimit=(1−1/zoom)×画面半分` に負ける=**遠距離の致命(zoom2 で相手が約250px超)ほど構図は効かない**(相手は縁へ寄り、横滑りも削れる)。
- 板の「40%」(v0.25.4301: 32→40)は足元の数字。12°傾いた幹の上端はさらに中央側へ入る(横長画面で約0.50W)。霧は横 0.7W で中央線を越えるが上下30%の帯なので寄り先は覆わない。

- **v0.25.4300(社長実機「何が変わったのか分からなかった」の実在確認)**: 上の門(モード)が **寄り込み前の base で判定**されていた
  ため、①近傍8体以上の群衆戦(文脈ズーム→0.8)②ボス戦(ボス距離ズーム0.40〜0.7)の処刑・ボス処刑・カウンターが**全部 cutPush**
  (三分割なし・横滑りなし・板なし)。full になるのは「近傍7体以下・ボス無し」の小競り合いだけだった。残っていたのは押し込み
  (1.7→2.0・224ms)のみ=気づけない量。**判定を「カット時点の実効倍率」に直した**(base 0.8×1.7=1.36 で pan は効く)。
  もう1つの事実: KILL のフル演出は共有CD 10秒(JUICE_CD_MS・社長裁定 v0.25.1524)に1回。CD内のキルは白い薄いフラッシュだけで台本は走らない。

- **v0.25.4301(社長「やってみよう」)**: 数値を一段太らせた——KILL カット 0.7→0.5・横滑り 8→14% / ボス処刑 カット 0.6→0.4・横滑り 10→18% /
  カウンター 行き過ぎ 12→22%・逆滑り 5→9% / 板 32→40%・α 0.85→0.95(自機側の余白は板+0.06=0.46 に連動)。判定・座標・HUD は不変。
  同時に社長指示「**CD中は画面揺れだけ入れて**」: KILL の共有CD(10秒)内の処刑は、停止/スロー/ズーム/カメラは出さないまま
  **処刑の揺れ(finish ×2.0)だけ**出す(〜4300 はCD内は kill ×1.3 の揺れ+薄い白フラッシュ。白フラッシュは従来どおり残す)。

### 6-3. 中央をくっきり保つ
- 既存の tilt-shift(帯のピント)は v0.25.4294 で寄り先を追う。板は**事前にボカした1枚**(読み込み時に1回 RenderTexture へ焼く=毎フレームのブラーは無し)なので、
  ピントの文法(中央=鮮明・縁=ボケ)が板でも成立する。
- 板の色: ステージの近景森と同じ暗さ(`FRONT_FOREST_ALPHA` 0.78 相当・黒寄りの tint)。

### 6-4. 負荷・安全
- **2/10**: pooled sprite 2枚+読み込み時の焼き1回。フィルタのパス増なし。カット時点の実効倍率<1(pan が効かない=§2-2 と同じ判定)の時は出さない。
- 画面空間なので ZOOM_MIN_ABS・可視域・上下5副作用に無関係。HUD(DOM)は板の上。

### 6-5. 決めてほしい点
1. 作るか(推薦=作る。演目は KILL/処刑と死亡。カウンターは短いので無し)。
2. 板の大きさ: 縁の25〜35%(推薦)/もっと大胆に40〜50%(半分近く隠す)。
3. 素材: まず既存(森の幹・霧・街プロップの絵を流用)で作る(推薦)/専用のシルエット素材を後で作る。
4. 傾き: 台形の奥側と同じ向きへ 6〜12°(推薦)。

## 7. 第3弾: レターボックス(寄り演目の間だけ上下に黒帯)— **v0.25.4303 で出して v0.25.4304 で取り下げ**(2026-09-14)

> **★取り下げ済み(社長 2026-09-14「とりあえず戻して」「今回のはちょっと違った」)。**
> 実装は revert 済み(コードは残っていない)。**設計と検収監査の結果はここに残す**——同じ判断を後でやり直す時の土台になる。
> 取り下げの理由は「画角を削る」方向そのものが今欲しい見せ方ではなかったこと。**エフェクト(逆光の光条・放射・埃)で
> 処刑のカメラに合わせる方向**へ切り替える(素材は v0.25.4305 で `public/vfx/kenney/` に受け入れ済み)。
> 下の §7-1〜§7-6 は**当時の設計のまま**(事実の記録として更新しない)。

§6 の(B)積みから起こした。**「1枚絵としての世界観」を作るのに、板(縁を隠す)の次に効くのが画角そのものを変えること。**
板は「何が写り込むか」を足す装置で、レターボックスは「どこまで写すか」を削る装置=別の仕事をする。

### 7-1. 何を作るか
- 寄りの演目(KILL/処刑・ボス処刑・死亡)の間だけ、**画面の上下に黒帯を出して 2.39:1 の画角にする**。
- **カットの瞬間に帯は既に居る**(滑り込ませない)。§6 の板と同じ文法——監査8「カットの後にUIが入ってくる」に
  しない。スマッシュカットで映画が始まる読み方になる。
- 抜けは**演目ごとの冪を掛けた包絡線(`zoomDecayCine = zoomDecay ^ outPow`・§2-1の語彙)の √** で上下へ戻る。
  幹の板 `outTree` と同じ入力・同じ形=画角と近景が同時に開く(検収監査4: 「共有包絡線」と書くと生の `zoomDecay` と誤読される)。
- 判定・座標・HUD・zwarp は一切触らない。**画面空間のスプライト2枚だけ**(世界の描画に手を入れない)。

### 7-2. 分類(CLAUDE.md「攻撃ヴィジュアルの2分類」)
**どちらでもない**——攻撃の絵ではなく**画角**。判定を持たず、判定を示唆もしない。よって「判定に揃える」対象外・
「派手さ」の対象外。**掟は1つだけ: 帯が寄り先(三分割の点)を食わないこと。**

1. **帯を滑り込ませるか**: 今の案=カットの瞬間に既に居る(板と同じ文法)。映画/ゲームの定番は 80〜120ms で

3. **帯の太さ**: 0.12(2.39:1 相当・推薦)/ もっと大胆に 0.16(1.85:1 より狭い「シネスコ寄り」)。7-4 の2定数を

4. **霧の板が帯に4割切られるのを許すか**(検収監査1): 推薦=**許す**(帯は画角なので切るのが正しい)。

5. **cutPush で帯だけ出る構図**(検収監査7): 遠距離ボス・群衆戦では三分割も横滑りも板も出ず、**帯と押し込みだけ**になる。

### 8-3. どこに置くか(★v1の最大の誤り)
**v1は全部を `frontForest` の上(`cineFx`)に置いていた。敵は `worldGroup > actorLayer` の中=はるかに下なので、

| 層 | 置く場所 | 中身 |
|---|---|---|
| **A. 世界の中** | `actorLayer` に **相手の足Yより奥でY-sort挿入** | 1 逆光の縁取り(相手が必ず光を隠す=これが逆光の定義) |
| **B. 近景(板と同じ)** | `L.cinePlates` の子 | 2 前景のボケ輪 / 4 手前の埃(板と同じ `BlurFilter` の下=**隣り合う層でボケ量が矛盾しない**) |
| **C. 画面全体** | 新 `L.cineFx`(`cinePlates` の下・`frontForest` の上) | 3 ワイプ / 4 奥の塵 / 6 シャッター |

  v1の画面空間案は、一番見せたい瞬間に一番ズレる配置だった。
- **相手の画面位置**: v1は「寄り先(三分割の点)」と書いたが、`thirdsAim()` が返すのは**画面中央に来る点**で相手はそこから

### 8-4. 素材のロード経路(★v1に一行も無かった=「素材があるのに絵が出ない」事故の5回目になる所だった)
`getTexture(name)` が引けるのは `ensureTextures()` に登録した名前だけで、パスは `spritePath(name)` = **`sprites/<name>.png`**。
現在の置き場所 `public/vfx/kenney/` は**この経路から引けない**(`src/` からの参照は grep で0件)。
- **`public/sprites/vfx/` へ移す**(`lab-floor/` `props/` と同じ「サブディレクトリ込みの名前」の作法)。
- `ensureTextures` の standalone 一覧に `{ name: 'vfx/flare_01', scaleMode: 'linear' }` 等**使う6枚だけ**登録し、`loadProgressBegin` の総数に +6。
- 使わない `spark_04` は登録しない(ロードだけされて描かれない状態を作らない=バッチ4で外した前例と同じ)。

### 8-5. 台本との紐付け(★v1は読む値を3箇所間違えていた)
| VFX | 読む値(v2) | v1の誤り |
|---|---|---|
| 逆光 | 相手の**世界座標**(Aの層)+ `cam.pushNorm` で横スケール 1.0→1.35 | 「寄り先=三分割の点」は相手の位置ではない |
| ボケ輪・手前の埃 | `cam.orbitFrac × (−cineSideX)`(**向きは `cineSideX` が決める**)+ `zoomDecayCine` | 「`orbitFrac` の符号」…符号は常に正。相手が左の回は逆向きに流れていた |

| 周辺減光 | `cam.pushNorm` を**1〜2フレーム遅らせ**、カメラ停止後も 180ms 沈み続ける | 押し込みと完全同一カーブ=数式的 |
| シャッター | カット直後の1拍 | 尺が §8-4(90ms)と §8-5(70ms)で食い違っていた |

**`pushNorm` を直接使えない場面がある(品質監査13)**: `counter`/`rescue` は `pushNorm` が**定数1**、割り込み(`startFrac`)では
kill の `pushNorm` が1フレームで 0↔1 に跳ぶ。→ **`pushNorm` をそのまま読まず、`cineFxPush`(1フレーム遅れの追従値・上限速度つき)を
`cineCamera.ts` に純関数で持たせ、全VFXはそれを読む**。演目の対象外(rescue)は 0 に固定。

**慣性(MUST)**:
- シャッター: 立ち上がり1コマ → 40ms 保持 → 70ms ease-out(**計 ~125ms に一本化**)。
- 逆光: カットの瞬間に既に居る(板と同じ文法)。**回転は入れない**(v1の 0→3° は実機で見えない=「小さくて見えない」違反)。
- 埃: 指数減衰で 0 に貼り付かせない。**終端速度を残す**(`v = v*0.90 + vDrift*0.10`)。`dt` 基準(60fps前提の定数を書かない)。
- **割り込みでプールを配り直さない**(v1は「演目の開始時に配り直し」= 飛行中の粒子が原点にリセット・逆光がワープ)。
  粒子は速度を保って流れ続け、逆光は新しい相手へ 140ms の ease-out で移す。カメラが `startFrac` で解いた pop を、上の絵で作り直さない。
- **始まりを1〜3コマずらす**: シャッター=0、ワイプ=+2、逆光=+3。完全同フレームだと複数の出来事ではなく1枚のフィルタに見える。
- **ばらし方を数字で決める**(「ばらす」だけ書くと等確率乱数=均質の別名になる): 手前の埃は**3枚・画面高の0.6〜1.1倍**、
  そのうち**1枚だけ他の2.5倍**を必ず混ぜる。火の粉は**20〜28個・4〜10px**。「8+4」のような似た数の等分にしない。
