# 赤円テレグラフ全数監査(2026-08-30・社長報告「サークル内が当たり判定になってない嘘がある。グレンの飛び掛かりとかも」)

走査エージェント(Explore)で**全ての赤い円の「絵」と「判定」**(中心・半径・発火タイミング・接触の絡み)を
突き合わせた結果の台帳。行番号は v0.25.4084 時点。

## A.(誤診・撤回)#R1「ボスの体の接触ダメージが赤の外で生きている」

**★2026-09-04: この節の前提は事実と違っていた。着手前監査(Opus5)が実物のコードとテストで反証し、
設計チャットが再確認した。#R1 は取り下げる。**

- **旧の主張**: 「`isBiteSubject` の早期return はボスに効かない=ボスは噛みつき化の対象外なので、
  溜め・硬直中も素の接触ダメージが生きている」。
- **実態**: `combatTick.ts` の呼び出しは `isBiteSubject(enemy, **isBiteExemptType**)` で、第2引数は
  `isBossType` **ではない**。`isBiteExemptType`(`enemyUtils.ts`)= **死神族 / 使者 / 幻影の3つだけ**。
  つまり**グレンを含むボスは噛みつき化の対象**で、**溜め・硬直・しゃがみ中の素の接触ダメージは
  今日すでに入っていない**。
- **機械的な裏付け**: `enemyBite.test.ts` が `isBiteSubject(jormungand,'chase')===true` /
  `'laser-fire'===true` / `'dash'===false` を**値でアサート済み**(=「体をぶつけに行く技の最中だけ痛い」)。
- **よって #R1 の裁定(a)を実装しても挙動は1mmも変わらない**(社長へ報告済み・裁定は白紙へ戻す)。
- **教訓**: 「効かない」と書く前に**呼び出しの引数まで読む**。述語の名前(`isBoss`)は仮引数で、
  実際に何が渡っているかは呼び出し側にしかない。

### 代わりに残っている本物(社長報告の容疑者・優先順)
1. **#R2 の `+pr`(最有力)**: `距離 <= 半径 + 14px`。`GIANT_JUMP_RADIUS=100` なら**実効114**
   (+14%)、パンプキン `r=54` なら**+26%**。社長の言葉「**サークル内が当たり判定になってない**」に一致。
2. **§D-5 の足元アンカー**: 着地円の中心=AABB中心 / 絵は足元アンカー。グレン(120×120)は
   **絵の着地点が円中心の60px南**に見える=「円と違う場所に着地して見える」。
3. **噛みつき(§12)**: 着地→硬直明け→追跡で30px圏なら紫点滅500msで噛む。
   「i-frame切れの2発目」と呼んでいたものの正体はこちらの可能性。

### ★別に見つかった本物のバグ(#R4・新規)
**守護霊/召喚への接触ダメージは、ゲートを1つも通っていない。**
敵→召喚の接触は `useGameLoop.ts` が `checkEnemySummonCollisions` の結果を `damageSummon(enemy.damage)`
へ直に流しており、**`isBiteSubject` も空中族の早期returnも通らない**。
⇒ **ボスは硬直・溜め・滞空中も守護霊を削り続ける**(プレイヤー側では既に無害な州で)。
GHOST_PARITY_LEDGER の「写し」原則に反する。**接触の可否を1本の述語に切り出し、召喚経路もそれを読む**のが直し方。

## B. 系統的な嘘 = #R2「判定は『円の半径+プレイヤー半身14px』」

- applyPumpkinBlastDamage(combatTick.ts:279-281)は `距離 <= 半径 + pr`(pr=14)。
  **絵の円の外側14pxの輪も被弾する**(小円 r=70 では実効+20%)。
- 同じ+pr: applyGlenFloorDamage / mk-spin(bountyTick) / suriel ringspin / acrasiel burst / warp。
- コード内コメントの「赤の外=安全」(pixiScene 2箇所)と食い違う。**裁定待ち #R2**
  (判定を「プレイヤー中心が円内」へ縮めるか、絵を+14pxで描くか)。

## C. 空中の体当たり抑止の取りこぼし = #R3(区分整合の候補)

- 抑止済み(裁定済みの型): 汎用jump / g-jump-air(v2601) / g-trijump-air(v3050) / g-glide-active(v3052) / トール全攻撃州。
- **未抑止のまま同じ動作**: ラフィ jump-attack / 賞金首バランス型 leap-air(combatTick.ts:1513に

  **飛行経路の体に触れると赤円の外で被弾**。裁定済みの区分仕様への整合として直す候補。

## D. その他((B)積み・小)

1. **翼撃(g-wing)**: 判定は windup 明けの1回だが、active 220ms も全濃度の円が残る。
   →sweep等と同じ「activeは見た目のみ」の既存慣習の範囲。据え置き(気になるなら消え際フェード)。
2. **フィルの裁き/急降下**: 絵の半径だけズームでクランプ(phillZoomSafeRadius)・判定は生値。
   現行値(90/70)ではクランプに達しない=潜伏。半径を上げる調整をしたら顕在化する。
3. **スリィエルring-spin/アクラシエルburst の完了latch**: 命中後も短時間、全濃度の円を描き続ける
   (「赤いのに当たらない」の尻尾)。
4. **押し(ノックバック)中は遅延ヒットの消化ループが280ms止まる**: 満了済みの円が遅れて爆ぜる。
   §8(ノックバック)の設計と絡むのでそちらで扱う。
5. **見え方の注意**: 着地円の中心=AABB中心・ボスの絵は足元アンカー。グレン(120×120)は見た目の
   着地点が円中心の60px南に見える。「円と違う場所に着地して見える」の一部はこれかもしれない。
