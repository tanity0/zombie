## 結論(先に4行)
1. **火力面では討伐可能。実測で確証済み**(HP6000を削り切り、消滅と同時に `enemiesKilled` が +1)。TTK は最速**約29秒**。
2. **実戦条件(HP/弾を捏造しない)では現行ボットでは討伐不可**。最良でも**6000中2123(35%)**止まりで死亡(§7)。
   **不足しているのは火力ではなく生存**。61DPSなら約98秒の生存が必要だが、実測は13〜35秒=**あと約3倍**。
3. **最効率ビルドは条件で逆転する**(重要):
   - **無敵条件(純火力)** → 近接5倍型(`katana`+`knife-master`/`combo-master`)が **140〜204 DPS** で1.6倍優秀。
   - **実戦条件** → **銃/kiter型(`support-sniper`+`attack-shooter`/`overclock`)が圧勝**(61〜102 DPS vs 近接5〜7 DPS)。
     死神は**接触ダメ77型**なので、接触圏に入る近接ビルドは**構造的に自殺**になる。**実戦の推奨は銃/kiter型**。
4. **「最強AI」は実装されていない**(§8)。カウンターは死神を脅威と認識せず**一度も発動しない**、攻撃回避機能は**存在しない**、
   距離取りは**銃の射程基準で危険度を見ない**。**レベルも強さの指標にならない**(装備は同一スロット上書き+選択が一様ランダム。
   Lv20で最大HP110の事故が実測で発生)。

## 1. 死神の実体(コードから確定した事実)
| 項目 | 値 | 出典 |
|---|---|---|
| HP(追跡個体) | **6000** | `config/reaper.ts:39` `chaserHealth`(※`enemyUtils`の基本値4000を上書き) |
| 討伐可否 | **可能** | 同 `canBeKilled: true` |
| 接触ダメージ | **77** | 同 `contactDamage` |
| 移動速度 | プレイヤー速度 **×0.9**(自分より遅い) | `getReaperChaseSpeed` |
| ワープ | **4秒ごと**にプレイヤーの **520px** 圏へ回り込む | `warpIntervalMs` / `warpDistPx` |
| 出現条件 | 深度 **14600px** 以上でリスク蓄積(extreme 18200pxで26/秒→約4秒)**または15分経過後の抽選** | `spawnRiskDepthPx` / `timeStartMs` |
| 撤退条件 | **原点900px以内**へ戻ると去る(※時間死神は去らない) | `homeRadiusPx` / `useGameLoop.ts:3591` |
| 討伐後 | **次回は撃破回数ぶん同時出現数が増える**(2体→3体…各6000HP) | `useGameLoop.ts:3566` `defeatCount` |

### ★最重要: 死神は「ボス級」扱い=近接フィニッシュの即死が効かない
`isBossType` に **`reaper` が含まれる**(`enemyUtils.ts:107`)。結果:
- **近接フィニッシュ(通常敵ならHP無視の即死)は死神には通らない** → 6000HPを必ず削り切る必要がある。
  (先日のナイフDPS報告で「即死チャネルがDPS表外の強み」と書いたが、**死神にはそれが使えない**=訂正情報)
- 代わりに**クリティカルが5倍**(通常1.5倍→ボス`BOSS_CRIT_DAMAGE_MULT=5`)、**スタン中の近接も5倍**(`BOSS_MELEE_STUN_MULT=5`)。
- **`crit-up` スキルはボスには 5→5.5倍(+10%)しか効かない**=死神相手には期待外れ。**最効率候補から外すべき**。

## 2. 最効率スキル/サブウェポンの設計(制約: **スキルは2つまで** `MAX_EQUIPPED_SKILLS=2`)
### 選定理由
- 死神は**単体・高HP(6000)・接触型**。→ 範囲攻撃や群れ処理は無価値、**単体持続DPS**と**被弾しない距離管理**が全て。
- 上記の**ボス5倍ルール**が効くのは「クリティカル」と「スタン中の近接」。近接はスタンを挟めば1発250(=50×5)級が出るため、
  素の威力差(ナイフt5 50 vs グレラン95)を逆転する。
- `crit-up`はボスに+10%しか乗らないので不採用。`berserker`は被ダメ+20%で接触77と相性最悪。`skater`(速度3倍)は
  逃げに強いが火力ゼロ=TTKが伸びて弾切れリスク。

### 推奨ビルド(実測1位)
| 枠 | 選択 | 理由 |
|---|---|---|
| サブ | **`katana`**(刀) | 近接強化。スタン中5倍の回転を最大化 |
| スキル1 | **`knife-master`** Lv3 | 近接コンボ +最大60%、**近接クリ +20%**(=スタン発生率が上がり5倍回数が増える) |
| スキル2 | **`combo-master`** Lv3 | コンボ窓延長 + コンボ中**全攻撃**ダメージ増(最大+70%) |
- 注意: `knife-master` は**弾薬ドロップ0%**の代償あり。死神単体戦では影響薄いが、道中の弾薬事情は悪化する。

### 次点(銃型・弾を절約したい場合)
サブ **`support-sniper`** + スキル **`attack-shooter`**Lv3(銃ダメ+30%)/**`overclock`**Lv3(サブCD即リセット30%)
— 過去ソークで最強だった構成(280キル・OC発動72回)。死神相手でも安定して85〜119 DPS。

## 3. 実測結果(3シナリオ + 確証ラン)
テスト設計: `?reapertest=1` で深奥フェーズを強制し、**原点から約20000px** へワープ(撤退条件900pxを原理的に回避)。
最上位装備(グレネードランチャーt3・対変異体ナイフt5・クリ最大30%・弾薬満載)を付与。**AIの質と切り離すため、まず無敵プローブで純TTKを測定**。

| シナリオ | 構成 | 死神出現 | 与ダメージ | 交戦時間 | **実測DPS** | 結果 |
|---|---|---|---|---|---|---|
| **A** 銃型・無敵 | kiter / support-sniper / attack-shooter+overclock | 3.9s・HP6000 | **5886**/6000 | 69.5s | **85** | 残114で消滅=討伐 |
| **B** 近接型・無敵 | standard / katana / knife-master+combo-master | 3.9s・HP6000 | **5925**/6000 | 42.3s | **140** | 残75で消滅=討伐 |
| **C** 銃型・実戦HP300 | kiter / support-sniper / attack-shooter+overclock | 3.9s・HP6000 | **5987**/6000 | 50.4s | **119** | 残13・**プレイヤーHPも0=ほぼ相打ち**(下記) |
| **確証** 近接型・無敵 | standard / katana / knife-master+combo-master | — | **6000**/6000 | 約29.4s | **約204** | **討伐確定**(下記) |

- console エラーは**全ラン0件**。同時出現数は全ラン1体(初回=`defeatCount`0のため仕様どおり)。

### 討伐の確証(100msポーリングの確認ラン)
500msポーリングでは HP114/75/13 の次のサンプルで消えており「HP0」を踏めなかったため、**100msで追跡し直した**:
```
HP推移: 105 → 69 → 45 → 8 → (消滅)
消滅時: gameTime 33.3s / dist 19953px / enemiesKilled が +1
```
**判定=討伐。根拠3点**:
1. **消滅と同時に `enemiesKilled` が +1**(討伐カウント)。
2. **距離19953px**=非討伐の消滅経路(`homeRadiusPx`=原点900px内への帰還)は**原理的に起こり得ない**。
3. HPが単調減少して1桁(8)になった直後の消滅=オーバーキルで0を跨いだ(HPちょうど0は同tickで配列から除去され観測できない)。

### Cの「相打ち」について(重要・正直な限界)
Cは死神を**残HP13**(99.8%削った)まで追い込んだが、**その瞬間プレイヤーHPも0**だった(`lastPlayerHp=0`)。
`gameOver` フラグは未セットのタイミングで、かつ**プレイヤー死亡時のゲーム終了処理でも敵配列が整理される**ため、
**Cの死神消滅を討伐と断定できない**。→ **Cは「討伐確定」ではなく「ほぼ相打ち」として扱ってください。**
HP300 ÷ 接触77 ≒ **4発**で死ぬ計算で、50秒の交戦中に4発貰った、という読み。

## 4. 「最強AI」について(依頼への正直な回答)
- **最強AIは存在しません。** 現行のペルソナは7種(`standard/kiter/stationary/boar/wanderer/rusher/scavenger`)で、
  これらは**プレイテスト用の"性格の型"=わざと最適ではない**もの。回避も確率的(standard=反応250ms・**65%**、kiter=300ms・50%)で、
  「避けられる攻撃を全て避ける」実装にはなっていません。
- **私(テストチャット)はコードを書けない掟**のため、最強AIの実装はできません。そこで今回は
  **AIの質に依存しない設計**(無敵プローブで純TTKを測る)で「討伐可能か」に答えました。**上の結論はAI性能とは独立です。**
- 使ったのは既存の最良ペルソナ(近接=`standard`、射撃=`kiter`)です。

### 最強AIができれば「実戦でも討伐可能」になる見込み(数字の根拠)
- 火力側は**すでに足りている**(近接型で29〜42秒・6000HP完遂を実証)。
- 生存側は**あと1〜2発ぶん**の余裕があれば勝てる位置(Cは4発で落ちた)。死神は**プレイヤーより遅い(×0.9)**ので、
  理論上は**ワープ直後(4秒周期)の520px接近だけを捌けば接触0**にできる=**AI改善の余地が非常に大きい**。
- 併せて `knight`(被ダメ-20%)を1枠使う、HP強化を積む、`seeker`(被弾時に半透明・ただしボスには無効=
  `isBossType`除外あり)は死神に効かない点に注意。

# §7 完全実戦ラン(HP回復なし・弾補充なし)+ レベルラダー 【追記 2026-07-28 09:13 JST】

## 7-1. 【重要】最初の2ランは無効(社長の実機指摘で判明)
当初 20000px へワープして検証したが、社長が実機を見て「**ゲート発動やハンターが出て余計なイベントが混ざっている**」
「**ゲートで無抵抗で死んでいる**」と指摘。ログを確認すると **`[spawn]` が一度も出ておらず与ダメ0**=
**死神が現れる前にゲートで決着していた**。→ **この2ラン(L10-melee/L10-gun @20000px)は無効として破棄**。
- 原因: 20000pxは**ゲート・ハンター・深度による敵強化**が載る領域。私の設計ミス。
- 修正: `?reapertest=1` は **位置に関係なく深度をextremeに強制**する(`useGameLoop.ts:3367`
  `const depth = REAPER_TEST ? extremeDepthPx + 1 : Math.hypot(pcx,pcy)`)。**深く潜る必要は無かった**。
  → **1500px(撤退ライン900pxのすぐ外)で死神だけを隔離**して再実行。毎サンプルで敵種類構成を記録して交絡が無いことを担保。

## 7-2. 実戦ラダー結果(隔離済み・HP/弾の無限化なし・弾は有限120発)
レベルは**正規経路**(XP付与→自然レベルアップ→**ボットが強化装備を自動選択** `useGameLoop.ts:1602`)で上げた。
| シナリオ | 実Lv/最大HP | 死神出現 | 与ダメージ | 交戦 | **DPS** | 結果 | 敵構成(交絡チェック) |
|---|---|---|---:|---:|---:|---|---|
| L10-melee | Lv10 / **160** | 7.7s | **27**/6000 (0.5%) | 6.0s | **5** | 死亡 | `{reaper:1, skeleton:2}` 交絡なし |
| L10-gun | Lv10 / **240** | 7.7s | **2123**/6000 (35%) | 34.7s | **61** | 死亡 | `{reaper:1, bat:3}` 交絡なし |
| L20-melee | Lv20 / **240** | 15.5s | **41**/6000 (0.7%) | 5.7s | **7** | 死亡 | `{zombie:1,bat:1,reaper:1,skeleton:1}` 交絡なし |
| L20-gun | Lv20 / **110** | 15.6s | **1322**/6000 (22%) | 13.0s | **102** | 死神が撤退※ | 交絡なし |
| L30-melee | Lv30 / **320** | 19.4s | (中断) | — | — | 未完(社長の指示で停止) | — |

  → 次回は開始位置を **2000〜2500px** にすべき(1500pxだとボットのふらつきで900pxを割る)。**手法の反省点**。
- **全ラン ハンター出現なし・console エラー0件**=隔離は成功。

## 7-3. §7の結論
- **近接型はレベルを上げても機能しない**(Lv10→Lv20→HP160→240でも **5〜7 DPS・約6秒で死亡**)。
  死神は**接触ダメージ(77)**型なので、殴るために接触圏へ入る近接ビルドは**構造的に自殺**になる。
- **銃/kiter型だけが戦える**(61〜102 DPS・最大35%まで削った)。だが**6000HPには61DPSで約98秒の生存が必要**で、
  実測の生存は13〜35秒=**あと約3倍の生存力が要る**。
- **レベルは強さの指標にならない**: 強化は装備で**同一スロット上書き**、かつ**ボットの選択が一様ランダム**
  (`botUpgradePolicy.pickUpgrade`)。**Lv20で最大HP110(基礎値のまま)** という事故が実際に起きた(Lv10の240より弱い)。
  → 「何レベルで倒せるか」は**レベルよりも装備運とAIの質**で決まる。

# §8 「最強AI」が無い理由=AIの欠落機能(コード実測・設計の参考資料)
社長の「カウンターや攻撃回避や距離の取り方で最強のAIを組んでいるはず」に対する回答: **組まれていません。**
`src/utils/playtestBot.ts` の公開関数を全数確認した結果、以下が**欠落**しています。

| # | 欠落 | コード上の事実 | 死神戦への影響 |
|---|---|---|---|
| ① | **接触型の敵を脅威と認識しない** | `findCounterThreat`(`:387`)が脅威とするのは **`aiPhase==='jump'` / `aiPhase==='charge'` / `hostile`な飛び道具の3種のみ** | 死神はどれにも該当せず=**カウンターが一度も発動しない**。近接攻撃自体がカウンター経路なので**近接の攻撃手段も機能しない**(近接5〜7 DPSの正体) |
| ② | **攻撃回避/危険回避が存在しない** | 回避系は `adjustBotForMines`(地雷)・`avoidMerchantZone`(商人)・`rusherState.dodgeSign`(**rusher専用**・詰まり時の横回り込み)**のみ**。敵の攻撃やテレグラフを避ける関数は**1つも無い** | 77ダメの接触を**避ける機能が無い** |
| ③ | **カウンターが確率+遅延で穴だらけ** | `COUNTER_REACTION_PROFILES`: standard **250ms/65%**、kiter **300ms/50%**。`willAttempt = rand() < chance` で**検知ごとに1回抽選**し、外れたらその脅威に**何もしない**(`:443`) | kiterは**半分棒立ち** |
| ④ | **距離取りが「銃の射程」基準で危険度を見ない** | kiterの帯は `d < range*0.55`で後退 / `d > range*0.9`で前進。`range`は**銃の射程**(`KITER_DEFAULT_RANGE=176`等) | 即死級の接触敵に対して**射程基準の距離しか取らない** |
| ⑤ | **ワープの概念が無い** | 死神は `warpIntervalMs=4000` ごとに `warpDistPx=520` 圏へ回り込む。ボット側に対応ロジック無し | 瞬間移動で懐に入られても帯を取り直すだけ |
| ⑥ | **ターゲットが「最寄り」固定** | `nearestEnemy` のみ。脅威度で優先順位を付けない | 死神が迫っていてもスケルトン/コウモリを撃つ(実測の敵構成がそれ) |
| ⑦ | **タイミング入力が一切不可** | `wantsMelee`→`triggerCounter()` だけ。ジャストタップ等の入力経路が無い | **`slasher`のジャスト追撃(最大3連)・刀/小烏丸の特殊操作・「斬」系は全て不使用** |
| ⑧ | **強化選択が一様ランダム** | `pickUpgrade = options[floor(rand()*len)]`(`botUpgradePolicy.ts`) | ビルドが宝くじ。Lv20でHP110の事故 |

## 8-1. 設計時の要点(優先順位順・実測の裏付き)
1. **接触そのものを脅威として扱う**(①。`findCounterThreat` の3種に「接近中の高危険敵」を追加する発想)
2. **危険度ベースの距離維持**(④。「接触したら死ぬ距離」で帯を取る。**死神はプレイヤーより遅い=`chaseSpeedMult 0.9`** なので理論上は逃げ切れる)
3. **ワープ直後の離脱**(⑤。4秒周期・520px圏。ここだけ捌けば接触0にできる=**改善の余地が最大**)
4. **確率カウンターを決定的にする**(③)
5. **脅威度ターゲティング**(⑥)
6. **強化選択ポリシーの目的化**(⑧)
- **火力は既に足りている**(§3の無敵プローブで29〜70秒で6000HP完遂)。**⑴〜⑶の生存機能だけが不足**、という切り分けが実測で確定している。
