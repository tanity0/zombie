# 不具合報告: チュートリアルで戦闘後に「スタートへ引き戻される」 【2026-08-16 JST】

- 報告元: 社長「チュートリアルステージ、攻撃喰らうとワープしちゃう」「通常敵もハンターも両方、
  強制的にスタートに戻される様な雰囲気」
- 調査: テストチャット(実機/コード読み)。**コードは変更していません。**
- 版: v0.25.3488

## 結論(原因)

**被弾そのものではなく、「戦闘が終わった瞬間に透明壁が復活し、壁より先に居るプレイヤーを
壁の位置まで瞬間移動で引き戻している」**のが正体です。

### 該当箇所1: 戦闘中は壁が消える(意図的な仕様)
`src/utils/m0Tutorial.ts:210` `m0AdvanceLimit()`
```js
if (waveActive) return null;        // ★戦闘中は壁を外す
for (const beat of M0_BEATS) {
  if (fired.has(beat.id)) continue;
  if (beat.gateX !== undefined) return beat.gateX;   // 次の関門の座標
}
```
コメントのとおり「教習中に狭い箱へ閉じ込めない」ための意図的な設計(v0.25.2305の社長指摘対応)。
**戦闘中は自由に前へ進める。**

### 該当箇所2: 壁の復活が「スナップ」になっている(ここが不具合)
`src/world/playableArea.ts:54`
```js
if (ctx.m0AdvanceLimitX !== null) nx = Math.min(ctx.m0AdvanceLimitX - w / 2, nx);
```
`Math.min` は**「進めない」ではなく「その場に引き戻す」**。
戦闘中に壁より先へ進んでいると、**敵を全滅させて `waveActive` が false になった瞬間に
壁の位置へ瞬間移動**する。

### 症状との整合
- **通常敵でもハンターでも起きる** → どちらも `waveActive` を作る敵だから。
- **被弾と結びついて見える** → ノックバックで位置が動いた直後や、敵を倒した直後に発火するため。
- **「スタートに戻される」ように見える** → 引き戻し先が次の未発火ビートの `gateX`
  (実測では `m0AdvanceLimitX = 800`)で、進んだ距離によっては大きく戻る。
- 会話中は `M0_CONVO_ADVANCE_LIMIT_X` も同時に効き(`useGameLoop.ts:4070-4071` で
  `Math.min(gateX, convoCap)`)、**より手前へ引き戻されうる**。

## 修正案(社長指示「城と同じ壁の見せ方にして」)

**このプロジェクトには既に同じ問題を解いた前例があります。** 城ボス戦の移動制限です。

`src/world/playableArea.ts:96` `clampCastleFightCrossing()`
```js
const newDist = Math.hypot(newCx, newCy);
if (newDist <= limit) return { x: newCx, y: newCy };
const oldDist = Math.hypot(oldCx, oldCy);
if (oldDist > limit + CASTLE_FIGHT_EDGE_EPS) return { x: newCx, y: newCy }; // ★既に外ならスナップさせない
const k = (limit - 1) / (newDist || 1);
return { x: newCx * k, y: newCy * k };
```
呼び出し側(`gameStore.ts:5460`)のコメント:
> 「外向きに跨ぐ移動」だけを止める。**既に外に居る場合はスナップさせない**

### 提案: M0の前進壁も同じ作法にする
**「壁より先に居る時は引き戻さない。壁を越えようとする移動だけを止める」**へ変更する。

考え方(実装は設計チャットの判断で):
- 現在位置(移動前)が壁より**手前**なら、これまでどおり壁で止める(=越えさせない)。
- 現在位置が既に壁より**先**なら、**スナップしない**(そのまま進退自由 or 戻る方向のみ許可)。
- 城と同じく「跨ぐ移動だけを止める」形にすれば、**戦闘中に前へ出た結果を没収しない**。

### 影響範囲(注意点)
`clampRectToPlayableArea` は**プレイヤー移動だけでなく、アイテム/敵の湧きクランプでも使われています**
(`gameStore.addPickup`・`useGameLoop` の敵配置など)。同ファイル冒頭にも
「片方だけ直すと移動可能範囲と湧き制限がズレる」と明記があります。
**前進壁の扱いを変えるなら、湧き側をどうするか(従来どおりスナップでよいか)も併せて決める必要があります。**
湧きは「その場に置く」処理なのでスナップのままで問題ないと思われますが、**判断は設計チャット**にお願いします。
