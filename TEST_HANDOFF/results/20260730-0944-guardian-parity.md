# テスト結果: 守護霊はプレイヤーと「同じ仕様・同じエフェクト」で動いているか 【2026-07-30 09:44 JST】

- 依頼: **社長から直接**「守護霊の動きテスト。ちゃんとプレイヤーと同じ仕様、同じエフェクトで動いていそうか?」
- 環境: 本物Chrome headed(GPU)・`npm run dev`(5173)・**v0.25.2496**・`?autotut=1`使用・**src変更なし**(掟)
- 生データ: `_ghost-parity.json` / スクショ `ghost-parity-<武器>.png` 4枚

## 結論(2行)
**エフェクト・見た目は「プレイヤーと同じ関数を共有」する形でかなり作り込まれており、パリティOK。**
**一方、銃弾の生成だけがプレイヤーの `fireWeapon` を通らない手書き実装で、実測で5つの仕様差が出ている。**
うち **`count`(散弾数)無視は影響が大きく、ショットガン装備時に守護霊の火力が本来の1/7になる。**

---

## 1. エフェクト面 = パリティOK ✅
守護霊の描画(`pixiScene.drawGhostAlly`)は**プレイヤーの関数・定数をそのまま共有**していた。
| 要素 | 実装 |
|---|---|
| 歩きコマ | **`playerWalkFrame()` / `playerTextureName()` をプレイヤーと同じ関数で呼ぶ**(クラス別) |
| 向き | `ghostFacing`(左右ミラー) |
| **銃口フラッシュ(C-1)** | `MUZZLE_FLASH_MS` / `MUZZLE_OFFSET_PX` / `MUZZLE_HEIGHT_FRAC` = **プレイヤーと同じ定数** |
| 近接スイング | ナイフ振り3コマ(分身 `syncShadowClone` と同一ロジック) |
| 発砲SE | **銃種別の分岐がプレイヤーの自動発砲と同一**(v0.25.2479で「常にhandgun-fire」から修正済み) |
| 斬撃+血飛沫 | `spawnSlash` + `spawnBlood`(幾何はプレイヤーの `spawnMeleeBlood` と同規則で向き先だけ守護霊基準) |
| スイング揺れ | `triggerShake(MELEE_SWING_SHAKE_MS, MELEE_SWING_SHAKE_MAG)` = プレイヤーの `triggerCounter` 末尾と同型 |
| カウンター成立 | per-bossハンドラへ合流=**本物のパリィ(技中断+確定クリ)**(v0.25.2480) |
| キル音 | `playEnemyDeath()` 同流儀 |
| SEの距離減衰 | `npcSfxDistGain`(遠い守護霊の音は小さく・画面外は無音)=escortの前例に合わせた**意図的な差** |

→ **「同じエフェクトで動いているか」= はい。** ここは丁寧にパリティが取られている。

## 2. 仕様面 = 銃弾に5つの差 ⚠(実測)
守護霊の射撃は `useGameLoop.ts:7209` の**手書き `addProjectile({...})`** で、プレイヤーの
`weaponUtils.fireWeapon()`(`count`ループ/`projectileSize`/`PROJECTILE_SPEED_MULT`/クリ判定/`passthrough`/拡散)を**通らない**。

### 実測(4種の銃を装備し、rAFで全弾の新規出現を拾って比較。各60秒)
| 装備 | 1トリガーあたり発数 | 弾のプロパティ |
|---|---|---|
| **ハンドガン**(count=1) | 守護霊 **1** / プレイヤー **1** | 守護霊 `9x9 spd520 crit:false×70` / プレイヤー `8x8 spd780` + **crit:true 6発** |
| **二丁ハンドガン**(count=2) | 守護霊 **1**(87回) / プレイヤー **2**(73回) | 同上 |
| **オートショット**(count=7) | 守護霊 **1**(16回) / プレイヤー **7**(28回) | 守護霊 `9x9 spd480` / プレイヤー `7x7 spd720` |
| **スナイパー**(count=1・貫通) | 守護霊 **1** / プレイヤー **1** | 守護霊 `9x9 spd1000 **pass:false**` / プレイヤー `8x8 spd1500 **pass:true**` |

### 差分の一覧
| # | 差 | 守護霊 | プレイヤー | 影響 |
|---|---|---|---|---|
| **1** | **`count`(散弾数)を見ていない** | 常に**1発** | `count` 回(二丁2発・ショットガン7発) | **★大**: ショットガンで**火力が1/7**、二丁で**1/2** |
| **2** | **`PROJECTILE_SPEED_MULT`(×1.5)未適用** | 520 / 480 / 1000 | 780 / 720 / 1500 | 弾が**1.5倍遅い**(見た目も当たりやすさも変わる) |
| 3 | `projectileSize` を見ていない | **9×9固定** | 8×8 / 7×7(武器値) | 見た目の差(小) |
| 4 | **クリティカルが出ない** | `crit:false` 固定(0/70発) | 実測 **6/76発でcrit:true** | 火力差(クリ率ぶん) |
| 5 | **`passthrough`/`pierce` 未適用** | `pass:false` 固定 | ライフルは `pass:true` | ライフルの**貫通が効かない** |

## 3. 意図的な非パリティ(差だがバグではない)
コメントに根拠があるもの。**これらは仕様として理解できる**ので、上の5点と区別して扱ってほしい。
- **スキル倍率なし**(`v0.25.2459方針`)。守護霊の弾は `damage: gun.damage` 素の値、近接も
  `Math.round(meleeWeapon.damage)` 素の値。→ **クリ倍率・コンボ倍率・ボスのスタン5倍も乗らない**
  (`damageEnemy` は生の数値を受け取る設計で、倍率は呼び出し側が計算するため)。
- **弾薬を消費しない**(プレイヤーの残弾と完全分離)。
- **計測から除外**(`weaponKey:'ghost-gun'` / `damageChannel:null`)=botTelemetryを汚さない。
- **SEは距離減衰**(escortの前例)。
- ヘイト計測は `hateSource:'ghost'` で明示。

## 4. 申し送り(判定は設計チャット)
- **#1(count無視)だけは体験に直接出る**と思われる。ショットガンやSMG/二丁を装備して守護霊を呼ぶと、
  守護霊だけ「単発をポツポツ撃つ別の武器」を持っているように見える(絵は同じ銃なのに散弾が出ない)。
  **CLAUDE.md の「見たまんまが当たり判定」の観点でも、絵と挙動が食い違う側**に入る。
- **#2(速度1.5倍)と#5(貫通)も"同じ武器なのに挙動が違う"型**の差。
- **#3・#4 は火力/見た目の微差**なので、スキル倍率を意図的に外している方針(§3)と合わせて
  「守護霊は素の武器性能で戦う」という整理にするなら、#4(クリ)はその一部とも読める。
  ただし **#1・#2・#5 は"武器そのものの仕様"** で、スキルや倍率とは別の層。
- 直し方の方向(参考): 守護霊の射撃も `fireWeapon()` を通す(オーナーを守護霊にする)か、
  `count`/`speedMult`/`size`/`passthrough` だけでも手書き側に写す。**判断は設計チャット。**

## 5. 手法メモ(限界)
- 弾の識別は `weaponKey==='ghost-gun'`(守護霊)と、それ以外(プレイヤー)。
  表に混ざる `14x14 dmg42/100` は**手榴弾などのサブウェポン**(プレイヤー起因)。
- 「1トリガーあたり発数」は同一40msバケットに出た弾を1トリガーとして束ねた近似。
  プレイヤーのショットガンが `7:28回`・`8:2回` と出ているのは、隣接トリガーが同バケットに
  入った際の合算(=7発が正しく出ている裏付け)。
- 総数の多寡(例: ショットガンで守護霊16 vs プレイヤー222)は**発射頻度の違い**も含むため、
  火力比の根拠には**1トリガーあたり発数**を使うこと。
- **移動そのもの**(速度・すり抜け)は今回未測定。守護霊の速度はスナップショット再現
  (前回検証済み)で、木/岩のすり抜けは `0db49824` でコード上は入っている。
