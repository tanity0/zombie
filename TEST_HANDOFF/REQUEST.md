# テスト依頼 #5: 廃病院オブジェクトの**描画崩れ**確認(v0.25.2331)

> **全体の目安 50〜60分・後半は放置可**(社長が席を外す時間に合わせた構成)。
> **パート1(stage-1・約20分)→ パート2(他ステージ・約15分)→ パート3(ボットラン・約20分/放置)** の順で回す。
> 時間が足りなくなったら**パート3を切る**(パート1・2が本題)。

## 目的
新規追加した**廃病院**が、実際に描いた時に**崩れていないか**を見る。ロジック(位置計算・当たり判定・
3秒滞在)はユニットテスト17ケースで既に通っているので、**今回見たいのは絵だけ**。
新規の建物スプライトは久しぶりなので、**重なり順(Y-sort)・裏回りの透け・影・地平線フェード・
ズーム引き**あたりに漏れが出やすい(v0.25.1324/1325の教訓=ズーム対応はレイヤーごとに潜伏する)。

**本題(パート1・2)は botrun ではない**。ボットは病院(原点から6250px)まで歩いて行かないので、
**プレイヤーをワープさせて絵を撮る**。`scripts/botrun-local.mjs` と `request.config.json` を使うのは
**パート3(回帰チェック・時間が余ったら)だけ**。

## 前提
- **PCの本物のChromeを headed(`headless: false`)で使う**。GPUが効いた状態で撮ってほしい
  (headless/swiftshader だとブルーム・加算合成・ライティングの出方が実機とズレて、描画崩れの判断に使えない)。
- **必ず `npm run dev` の開発サーバ**(`npm run build`+preview では不可)。ワープに使う
  `window.__gameStore` は **DEVビルド限定**のデバッグハンドルで、本番ビルドには付かない。
- `git pull` して **HEAD が v0.25.2331 以上**であること(`package.json` の version で確認)。
- **viewport は 390×844(縦持ち)が正**。これが本番の見え方。
  加えて **1280×800(横・PC)でも3枚だけ**撮ってほしい(周りが見えて崩れが分かりやすいので)。
- URL: `http://localhost:5173/zombie/?smoke&stage=stage-1`
  (ポートは `npm run dev` の出力に合わせる。`?smoke` でタイトルを飛ばして即プレイ)
- ステージ1の裏ボスは西なので、**病院は東= `(x=6250, y=0)`** に立つ。
- 座標系: **上が -y**。当たり判定は足元基準で `y ∈ [-80, 0]`・幅260(`x ∈ [6120, 6380]`)。
  絵は足元 `y=0` から上へ約300px・幅約370px。サークルの中心は足元 `(6250, 0)`・半径95。

## ワープの仕方(全ステップ共通)
```js
// page.evaluate。x,y を差し替えて使う
window.__gameStore.setState(st => ({ player: { ...st.player, x: 6250, y: 300 } }));
```
ワープ後は**1秒待ってから**撮る(カメラ追従とフェードのlerpが落ち着くまで)。

## A. まず素材が出るか(ここがコケたら以降は無意味)
```js
const s = window.__gameStore.getState();
return { hospital: s.hospital, taken: s.hospitalTaken };
```
→ `hospital` が `{x:6250, y:0}` であること。`null` なら**そこで止めて報告**。
→ プレイヤーを `(6250, 420)` へ → スクショ **`01-far.png`**。
   建物の絵が出ているか。**真っ白/透明/黒箱なら素材ロード失敗**なので、その時点で
   **Networkの `hospital.png` のステータス**と console を添えて報告して終わってよい。

## C. ズーム引き(CLAUDE.md「ズーム引き考慮」=必須)
`http://localhost:5173/zombie/?smoke&stage=stage-1&zoomlock=1` で入り直して:
- `(6250, 300)` → **`10-zoomlock-near.png`**
- `(6250, -260)` → **`11-zoomlock-behind.png`**

→ 建物・サークル・影の**位置がズレていないか**、**二重に出ていないか**、
  **画面外へはみ出す/切れる**ことがないか。とくにサークル(加算合成のGraphics)が
  ズーム時に位置ズレしやすいので念入りに。

## D. フェードアウトの見え方(消える瞬間)
`?smoke&stage=stage-1` で入り直して:
```js
window.__gameStore.setState(st => ({
  player: { ...st.player, x: 6250, y: 60 },
  hospitalDwellMs: 2900, hospitalTaken: false,
}));
```
→ 1秒ほど待つ(3秒到達で自動的に入手→フェード開始)。**入手の瞬間から**:
- 約 **300ms 後** → **`12-fade-300.png`**
- 約 **600ms 後** → **`13-fade-600.png`**
- 約 **1500ms 後** → **`14-fade-done.png`**

→ 建物・**影**・サークルが**一緒に**薄くなって消えるか。
  **影だけ残る / サークルだけ残る / 建物がパッと消える**のが崩れ。

## E. 方角マーク(画面端の緑の十字)

# パート2: 他ステージでの見え方(約15分)

病院は**通常ステージ全部**に立つ。ステージごとに**色調とライティングの系統が違う**ので、森で
問題なくても他で破綻しうる(廃都=夜の街灯 / 雪原=寒色グレード+霧 / 軍本部=炎ゆらぎ+爆発フラッシュ)。
**裏ボスの方角の反対**に立つので、ステージごとに座標が違う。下の表のとおりワープして撮る。

| ステージ | URL の `stage=` | 病院の座標 | 解放する拠点ID |
|---|---|---|---|
| 3 医療科学センター(廃都・夜) | `stage-3` | `(-6250, 0)` | `base-2` |
| 4 封鎖地域(雪原) | `stage-4` | `(0, 6250)` | `base-1` |
| 5 軍本部(戦争照明) | `stage-5` | `(0, -6250)` | `base-3` |

各ステージで**4枚ずつ**(viewport 390×844・ファイル名の `<n>` はステージ番号):
1. `s<n>-01-near.png` — プレイヤーを病院の**手前240px**へ(例: stage-3 なら `(-6250, 240)`)。
   → **建物の色がその背景から浮いていないか**(夜なのに昼のまま光っている/寒色に染まりすぎて真っ青、等)
2. `s<n>-02-behind.png` — 病院の**奥260px**へ(例: `(-6250, -260)`)。→ 裏回りの透けとY-sort
3. `s<n>-03-shadow.png` — 病院の**左脇**(例: `(-6500, 20)`)。→ 影の位置・濃さがそのステージの光源と合っているか
4. `s<n>-04-arrow.png` — 上表の拠点を制圧して原点へ。→ 画面端の緑の十字が出るか
```js
// <BASE_ID> は上表のもの
window.__gameStore.setState(st => ({
  baseSites: st.baseSites.map(b => b.id === '<BASE_ID>' ? { ...b, status: 'captured' } : b),
  player: { ...st.player, x: 0, y: 0 },
}));
```
→ あわせて各ステージで1回、`window.__gameStore.getState().hospital` の値も記録(座標が表と一致するか)。

**ここまでがパート2(合計12枚・約15分)。**
