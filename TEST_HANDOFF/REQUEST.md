# テスト依頼: クリティカル頻度の実機計測(2026-08-15・設計チャット)

## 目的
クリティカルの塩梅調整(PACING_PUZZLE.md §7-11(8))の裁定材料。v0.25.3395で BOT_REPORT に
**クリ集計(critStats)**が入った——RNGクリ/確定クリ(カウンター・紫中フィニッシュ等)の回数と
総ヒット数が、対ボス/対雑魚の内訳つきで出る。これを実機で取る。
※数字の分析・良し悪しの判断は設計チャットがやる。テストチャットは実行と記録だけでよい。

## 実行(2系統・計5ラン)
**必ず `git pull` して v0.25.3396 以降で回すこと**(critStatsが無い版では意味がない。
BOT_REPORTに `critStats` が出ていることを1ラン目で確認してから続行)。

### A. 通常ラン(対雑魚のクリ頻度)= 3ラン
- いつも通り `node scripts/botrun-local.mjs`(request.config.json 更新済み: crit-base-1〜3)。
- stage-1固定・15分cap。前回のベースラインと同条件(比較のため)。

### B. ボス戦ラン(対ボスのクリ頻度・絞りの実効)= 2ラン
- config の crit-boss-1〜2(URLに `?bountynow=1&bountytype=melee` が付けてある)。
- 賞金首(馬乗り)が出現し、ボットが交戦すれば対ボスの critStats が乗る。
  ボットが賞金首と絡まず死んだ場合はその旨を1行書けばよい(リトライ不要・1回まで再走可)。
- 15分cap。**目安: ビルド+5ランで45〜70分**。

## 記録(results/ へ・いつもの形式)
- 各ランの `[BOT_REPORT]` 生JSON全文(critStats と elapsedSec が本体)
- consoleエラー全文(なければ「0件」)
- 実行環境(headed/headless・OS)・ショップが開いた回数・気づき(任意)
- ※crit-boss ランでは「賞金首と交戦したか(体感でよい)」を1行
