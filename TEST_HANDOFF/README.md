# TEST_HANDOFF — 設計チャット⇔テストチャットの受け渡し(社長運用決定 v0.25.1706)

## 流れ
1. **設計チャット**: テストが必要になったら `TEST_HANDOFF/REQUEST.md`(+`request.config.json`)に
   依頼内容を書いて push。
2. **テストチャット(ローカル・テスト専用)**: 社長が「**テストして**」とだけ言う →
   `git pull` → `REQUEST.md` を読む → 実行(基本は `node scripts/botrun-local.mjs`) →
   結果を `TEST_HANDOFF/results/` に書いて push(下記の掟)。
3. 社長が設計チャットに「テストしたよ」と言う → 設計チャットが pull して結果を分析。

## テストチャットの掟(テスト専用)
- **コード(src/等)・設計書・CLAUDE.mdは編集禁止**。触ってよいのは `TEST_HANDOFF/` 以下のみ
  (必要ならローカル一時スクリプトは /tmp に)。
- push は `claude/chat-context-continuity-saxlH` ブランチへ。**TEST_HANDOFF/ のみの変更は
  バージョンbump・changelog・DEVELOPMENT_LOG不要**(コミットメッセージ先頭に `[test-report]`)。
- 結果ファイル: `results/<YYYYMMDD-HHMM>-<件名>.md`(人間向け要約)+同名 `.json`(生データ)。
  最低限入れるもの: 実行環境(OS/ブラウザ/headed or headless)・各ランの `[BOT_REPORT]` 生JSON・
  consoleエラー全文(なければ「0件」)・気づき(任意)。
- ブラウザはローカルChromeを使用(`scripts/botrun-local.mjs` は `channel:'chrome'`)。
- **既定はローカルビルド**(`request.config.json` の baseUrl:"local")——スクリプトが自動で
  `npm run build`→previewサーバ起動→実走→サーバ停止まで行う。**pullした最新コードをそのままテスト**
  できる(Pagesのデプロイ待ち・配信環境差の影響なし)。Pages版を叩きたい時だけ baseUrl にURLを書く。
  ※Pages版はテスト環境によってローディングが完走しない事象が報告済み(v0.25.1707時点・原因調査は設計チャット)。

## セットアップ/トラブルシュート
- 初回: `npm install`。ブラウザ起動に失敗したら `npx playwright install chromium`(Chrome不在フォールバック用)。
- `?smoke=1` はタイトル/メニューを全部スキップして即プレイに入るデバッグ導線。**効かずタイトルで
  止まった場合はスクリプトが自動でUIクリック**(はじめる→狂い咲きの森→出撃準備→START)にフォールバックし、
  `smokeFallback: true` を結果に記録する(=smoke不発の証拠。そのまま結果をpushしてよい)。
- **手動でゲーム開始する場合の操作手順**(スクリプトが全滅した時の最終手段):
  1. `https://tanity0.github.io/zombie/?bot=standard` を開く(botパラメータ付き)
  2. タイトルの「**はじめる**」→ ミッション一覧で「**狂い咲きの森**」(ステージ1)→
     「**▶ 出撃準備**」→ キャラ選択で「**▶ START**」
  3. ゲームが始まればボットが操作を自動で引き継ぐ。死亡 or 15分でF12コンソールに `[BOT_REPORT]` が出る
- どうしても開始できない場合: スクリーンショット+console全文+開いたURLを results/ に書いて終了
  (原因調査は設計チャットの仕事。自分でコードを直さない)。

## 設計チャットの掟
- REQUEST.md には「目的・構成(ロードアウト/スキル/ペルソナ)・時間・記録してほしい項目」を明記。
  `request.config.json` を同時に更新(スクリプトはこれを読む)。
- 結果の分析・裁定材料化は設計チャットの仕事。テストチャットに判断をさせない。

## 自動テストの申し送り(v0.25.2474)
- **ポップアップ対策**: チュートリアル等のポップアップは `isPaused=true` を立てる=放置するとシミュが
  1フレームも進まない(stage-2で実際に誤判定が起きた)。対策は2択:
  ①URLに **`?autotut=1`** を付ける(ポップアップを出さず既読処理のみ・ポーズしない・v0.25.2474〜)
  ②headedでポップアップが出たらOKを押して閉じる。
- **レベルアップ/宝箱の選択画面も `?autotut=1` で自動選択される(v0.25.2481〜)**: ボットと同じ
  greedyポリシー(決定的乱数)で即選択して閉じる=選択画面のポーズで gameTime が凍結しない。
  `?bot=` 併用時はボット側の既存自動選択がそのまま担当(二重には走らない)。
- `?idolnow=1` は idol が**2体**になる(配置済みdormant個体+force-spawn個体)。個体はidで区別すること。
- その他の地雷は ENGINEERING_NOTES.md「自動テストの地雷」を参照。


## 自動ラン中の詰まり対策(2026-08-07追記・設計チャット)
- **武器商人の購買画面**: 出撃地点近くの商人に触れると購買画面(showShopMenu)が開き、ボットは閉じられず

## 初回起動(新規プロファイル)の関門 — 2026-08-19追記・テストチャット
`?smoke=1` を付けない/**新規ブラウザプロファイル**で開く指示のとき(例: ガントレットは
Lv1初期装備・守護霊なしにするため新規プロファイルで開く)、**ゲーム開始までに以下の壁がある**。
使い回しプロファイル+`?smoke=1` の従来運用では出ないので、ここに残す。

| 順 | 壁 | 見た目 | 通し方 |
|---|---|---|---|
| 1 | 更新情報モーダル | タイトルの上に更新情報+下部に「**OK**」 | OKを押す |
| 2 | ステージ導入シーン | 全画面のシーン+右下に「**スキップ ▶**」 | スキップを押す |
| 3 | チュートリアルポップアップ | 中央のポップアップ(`isPaused`が立つ) | `?autotut=1`、または OK を押す |
| 4 | 武器商人の購買画面 | `showShopMenu` | 上記「自動ラン中の詰まり対策」どおり false に戻す |

- **1・2は `gameTime` が 0 のまま進まない**ので、「ボタンが押されるまで永久に待つ」形で止まる。
  ポーリング側は `gameTime===0` かつ `OK` / `スキップ` / `閉じる` のボタンがあれば押す、で通せる
  (押すのはプレイヤーがする操作と同じ。進行データは書かない)。
- **ガントレット(`?gauntlet=1`)は `tutorialPopup` だけ自動で閉じ、1・2は閉じない**(v0.25.3613時点)。
  自動で閉じる余地があるかは設計チャットの判断(こちらでコードは直さない)。

## ★スクリーンショットは results/ に貯めない(2026-08-22・実測から)

**現状 `results/` に PNG が 748枚・618MB 溜まっており、リポジトリ全体が 4.8GB(クローン時の転送
993MB)になっている。** この重さが、**コンテナ起動時の再クローンを不安定にしている疑いが強い**
(実際にこの日、ローカルの作業ツリーだけが過去へ巻き戻る事故が3回起きた)。

**これからの掟**:
- **1回のテストで `results/` に入れる PNG は最大5枚**。「その1枚が無いと設計側が判断できない」ものだけ。
- **連番の全景スクショ(`01-far.png` 〜 `20-…`)のような撮り貯めはコミットしない。** 見せたいものは
  **社長へチャットで直接見せる**か、依頼文が「1枚」と言っているならその1枚だけ。
- **json / md(要約・生データ)は今までどおり入れてよい**——軽く、後から引くのはこちらなので。
- 既に入っている748枚は**消さない**(社長の資産・過去の判断材料)。**増やさないことだけ守る。**


## 実機(headed)/ヘッドレスの切り替え — 2026-09-10追記(社長指示「実機テストをCodexでも回したい」)
**同じPCで動く Codex に実機テストを回させる場合も、追加の仕組みは要らない。**
3本のランナーが**すべて `request.config.json` の `headless` を見る**ようにしてあるので、
誰が実行しても同じ表示モードになる。

| ランナー | 表示モードの決まり方 |
|---|---|
| `scripts/botrun-local.mjs` | `cfg.headless !== false`(**キー省略時はヘッドレス**) |
| `TEST_HANDOFF/run-e2e-sweep.mjs` | `cfg.headless === true`(**キー省略時は実機**) |
| `TEST_HANDOFF/run-weapon-sweep.mjs` | `cfg.headless === true`(**キー省略時は実機**) |

- 起動時に `[setup] 表示モード: 実機(headed)` の1行が出る。**回す前にこの行を必ず確認する**
  (黙ってヘッドレスで回っていた事故の再発防止)。
- **既定が2種類ある点に注意**。TEST_HANDOFF の2本は「省略=実機」に倒してあるが、
  `scripts/botrun-local.mjs` は従来どおり「省略=ヘッドレス」。**`request.config.json` に
  `headless` を必ず明示する**のが安全(設計チャットが依頼を書く時の項目)。
  ※`scripts/` はテストチャットの担当外なので揃えていない。揃えるかは設計チャットの判断。
- コンテナ(GPU・表示なし)へのフォールバック経路は表示が持てないので**常にヘッドレス**のまま。

### なぜ既定を実機に倒したか(実測)
当PCで **headed = 実時間の80.7%(35.3fps)/ headless = 2.3%(1.9fps)**。
ヘッドレスだと**10分回してもゲーム内は約14秒**しか進まず、ボスの技も守護霊の成立も観測できない。
しかも見た目は正常に完走するので、**気づかないまま無意味な結果を報告する**事故になる。

### 同じPCで2本同時に回さない
ウィンドウが隠れると `document.hidden` → `setBackgrounded(true)` でシミュレーションが止まる
(製品の仕様)。Codex とこのチャットで同時に走らせると、**隠れた方は進まない**。**実機テストは1本ずつ。**
