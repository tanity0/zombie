# 実機テストを他のAIに任せるための説明書(2026-09-17)

社長指示「他のAIにも実機テストさせたいので」に対する引き渡し資料。**これ1枚を渡せば回せる**ことを目標に、
現に動いている仕組みだけを書く(構想・未実装は書かない)。

---

## ★0. 最初に伝えるべき一番大事なこと — **これは「画面を見て操作するAI」ではない**

社長の項目に「画面認識→判断→操作の優先順位」があるが、**現行の仕組みにその層は無い**。誤解したまま渡すと、
相手のAIは存在しない機能を探して詰まる。実態はこうなっている。

| 層 | 誰がやるか | 中身 |
|---|---|---|
| **プレイ操作**(移動・攻撃・回避・カウンター・強化選択) | **ゲーム内蔵のボットAI**(`?bot=` で起動) | ゲームのコード内(`src/utils/playtestBot.ts` ほか)。**外から操作しない** |
| **起動と観測** | **Playwrightスクリプト**(固定手順) | URLを開く・起動の関門を押す・時間まで待つ・consoleとDOMを採取 |
| **結果の記録** | **担当AI(あなた)** | 生データを `results/` に書いて push |

つまり**方式は「固定手順」**で、**画面認識による判断は使っていない**。
担当AIの仕事は「上手くプレイすること」ではなく、**回して・止まっていないか見て・事実を記録すること**。

- DOMは読める(`document.body.innerText`)。ゲーム画面そのものは `<canvas>` なので**DOMからは読めない**。
- 開発サーバ(5173)でだけ `window.__gameStore` が生えており、状態を数値で読める。
  **本番ビルド(`vite preview` 4173)では `__gameStore` は存在しない**(実測)。
- よって「画面を見て判断」が要る場面は、**スクリーンショットを撮って人間か担当AIが後から読む**形で代替する。

## 2. 画面認識→判断→操作の優先順位

**上から順に試し、上で解決したら下は見ない。**

| 順 | 見るもの | 取り方 | やること |
|---|---|---|---|
| 1 | **ページが落ちていないか** | `page.evaluate` が例外/null | 落ちていれば終了して記録(復旧しない) |
| 2 | **起動を塞ぐボタン** | `document.body.innerText` とボタン列挙 | §3の関門を押す |
| 3 | **`showShopMenu`(商人画面)** | `__gameStore.getState().showShopMenu` | true なら false に戻す・**回数を記録** |
| 4 | **`gameTime` が進んでいるか** | `__gameStore.getState().gameTime` | 進んでいれば正常。止まっていれば§5へ |
| 5 | **`window.__BOT_REPORT__`** | 同上 | 出たらそのランは終わり(死亡/クリア/帰還) |
| 6 | **console** | `page.on('console')` | error を全文ためる |
| 7 | **画面の絵** | `page.screenshot()` | §7のタイミングでだけ撮る |

**操作してよいのは §3 の関門と §2-3 の `showShopMenu` だけ。** それ以外の操作(移動・攻撃・強化の選択)は
**ゲーム内ボットの仕事なので、外から触らない**。触ると「ボットの実力」を測れなくなる。

## 3. 初回起動・タイトル・ステージ選択・出撃までの行動

**原則: 押して進むのではなく、`?smoke=1` で丸ごと迂回する。**

```
http://localhost:4173/zombie/?smoke=1&bot=standard&autotut=1&stage=stage-1
```

`?smoke=1` がタイトル・ミッション一覧・出撃準備・キャラ選択を**全部飛ばして**出撃する
(`src/App.tsx` の smoke 処理)。**これが正規の入口**で、UIを順に押す必要はない。

### それでも塞がれる関門(**新規プロファイルだと必ず出る**)

| 順 | 関門 | 画面 | 抜け方 |
|---|---|---|---|
| 1 | 更新情報モーダル | タイトルの上に更新情報+下部に「**OK**」 | OKを押す |
| 2 | ステージ導入シーン | 全画面のシーン+右下に「**スキップ ▶**」 | スキップを押す |
| 3 | タイトルが残った時 | **ルートdiv全体が押せる**(`aria-label="タップして開始"`。**textContent は `v0.25.xxxxSTARTCAMERANEWS`**) | aria-label で当てて1回押す。**「はじめる」は現在存在しない**(2026-09-17 実測) |
| 4 | チュートリアルポップアップ | 中央のポップアップ(`isPaused` が立つ) | **`?autotut=1` を付ければ出ない**。出たらOKを押す |
| 5 | 武器商人の購買画面 | `showShopMenu` | false に戻して続行・回数を記録 |

**1と2は `gameTime` が 0 のまま永久に待つ**ので、放置では絶対に進まない。実装は「ボタンが在れば押す」ループ:

```js
for (let i = 0; i < 12; i++) {
  const label = await page.evaluate(() => {
    const btns = Array.from(document.querySelectorAll('button,[role="button"]'));
    const hit = btns.find(x => /^スキップ/.test((x.textContent || '').trim()))
      ?? btns.find(x => (x.textContent || '').trim() === 'OK')
      // ★aria-label でしか名前を持たない要素がある(タイトルの入口)。textContent だけ見ると空振りする。
      ?? btns.find(x => /タップして開始/.test(x.getAttribute('aria-label') || ''));
    if (hit) { hit.click(); return (hit.textContent || '').trim(); }
    return null;
  });
  if (!label) break;
  await page.waitForTimeout(3000);
}
```

### ステージの指定
`&stage=<id>`。有効な id は `stage-tutorial` / `stage-1`〜`stage-7` / `stage-ex1` / `stage-ex2` / `stage-ending`
(`src/data/campaign.ts`)。**存在しない id を渡すと背景が空になり、症状がステージ由来か分からなくなる**。

## 4. 戦闘・回避・強化選択の基準 — **担当AIは決めない**

全部ゲーム内蔵のボットが決める。担当AIが指定するのは**URLのつまみ2つだけ**。

### `?bot=<persona>` 行動の型(`src/utils/playtestBot.ts`)
`standard`(既定) / `kiter`(距離を取る) / `stationary`(動かない) / `boar`(猪突) /
`wanderer`(徘徊) / `rusher`(敵へ突っ込む) / `scavenger`(拾い集め)

### `?botskill=<skill>` 上手さ(`src/utils/botSkill.ts`)
`novice` / `casual`(**既定**) / `skilled` / `master`

- **強化(レベルアップ)の選択は自動**。`skilled`/`master` は greedy(装備Tier優先)、`novice`/`casual` はランダム。
- `?autotut=1` を付けると、**ボット無しのランでも**強化選択が greedy で自動選択される。
- **回避・カウンター・紫円の尊重度は `botskill` で変わる**。例: `casual` は紫円を尊重せず円内で振るので、
  「カウンター不可の技に当たる」挙動を見たい時はこちらを使う。

### 目的(任意)
`?botgoal=clear|campaign|score|hiddenBoss[:Lv]|hunt:<敵type>|depth:<px>|kills:<n>|bases:<n>`
**未指定は `none`=目的なし**(その場の戦闘だけ)。**ボスを探して歩かせたい時は `hunt:` が要る**
(未指定だと離れて湧いたボスと一生出会わない事故が実際に起きた)。

## 5. ポップアップ・停止時の復帰方法

**ゲーム側に保険が入っている**: ボット稼働中に `isPaused` が **60秒**続くと、
`showShopMenu` / `showEventQuestMenu` / `showUpgradeMenu` を強制的に閉じて `isPaused=false` にし、
console に `[BOT] paused >60s — force-closing menus` を出す(`src/hooks/useGameLoop.ts`)。
**この行が出たら記録する**(=想定外のUIで詰まった証拠)。

担当AI側の復帰手順:

| 症状 | 最初の1手 | それでも駄目なら |
|---|---|---|
| `gameTime` が 0 のまま | §3の関門ボタンを押す | スクショ+URL+console を記録して終了 |
| `showShopMenu === true` | `__gameStore.setState({ showShopMenu: false })`・回数記録 | 同上 |
| `isPaused` が続く | 60秒待つ(ゲーム側の保険が効く) | 同上 |
| `gameTime` が進むのに画面が動かない | **ウィンドウが隠れていないか確認**(§8) | 同上 |
| ページが例外を吐いた | 何もしない | console全文を記録して終了 |

**5分粘っても開始できなければ、スクリーンショット+consoleエラー全文+開いたURLを `results/` に書いて終了。
自分で直さない**(原因調査は設計チャットの仕事)。

## 6. 待機時間・再試行・タイムアウト・終了条件

| 項目 | 値 | 出どころ |
|---|---|---|
| ページロード後の初期待ち | **9秒** | 既存ランナー共通 |
| 関門クリック後の待ち | 3秒 × 最大12回 | 同上 |
| 状態ポーリング間隔 | **5秒**(短命イベントを追う時は rAF 蓄積器) | 同上 |
| **1ランの上限** | **900,000ms = 15分**(`request.config.json` の `runMs` で変更可) | `scripts/botrun-local.mjs` |
| ガントレット1枠 | **実時間180秒**(撃破/死亡/180秒で次枠へ) | `?gauntlet=1` |
| 停滞の警告 | 60秒 変化なし | README の掟 |
| 停滞で中断 | 5分 変化なし | 運用 |

**1ランの終了条件(どれか1つ)**
1. `window.__BOT_REPORT__` が出た(死亡・クリア・帰還)
2. 上限時間に達した(= `[BOT_REPORT]` は出ない。**これは異常ではない**=ボットが生き残っただけ)
3. ページが落ちた

**再試行の掟**: 同じやり方の再試行は**2回まで**。3回目に入る前に止めて、試したことを社長へ報告する。
**長い1回のタイムアウトを粘るのも「再試行」に含める**。

## 7. スクリーンショット・ログを取るタイミング

**PNGは1回のテストで最大5枚。** リポジトリが既に4.8GB(`results/` にPNG 748枚=618MB)あるため、
**「その1枚が無いと設計側が判断できない」ものだけ**入れる。

| 撮る場面 | 必須か |
|---|---|
| ランの終了時(死亡画面/結果画面) | **必須**(1ラン1枚) |
| 60秒以上停滞した時 | **必須** |
| 依頼(REQUEST.md)が名指しした瞬間 | 必須 |
| 起動の関門で詰まった時 | 必須 |
| 経過観察(2分ごと等) | **任意。5枚枠を食うので普段は撮らない** |

**ログは全部取る(こちらは容量問題なし)**:
- `page.on('console')` の error 全文、`page.on('pageerror')`
- `[GHOSTLOG]` / `[GHOSTDMG]` / `[BOT_REPORT]` を含む行は全部(依頼による)
- 30秒ごとの `document.body.innerText` 先頭200文字(**停滞の事後解析に効く**)

**★死亡後の「停滞」を固まりと誤報告しない。** ボットが死ぬと結果画面で文字列が止まる。
**停滞の開始時刻とそのランの死亡時刻が一致していれば、それは正常**。実際に誤報告しかけた事例がある。

## 8. 既知の苦手・できないこと(**ここを知らないと嘘の結果を出す**)

| # | 事実 | 影響 |
|---|---|---|
| 1 | **ウィンドウが隠れるとシミュレーションが止まる** | `document.hidden` → `setBackgrounded(true)`(製品仕様)。最小化・他ウィンドウで被覆・**2本同時実行**で止まる。**実機テストは必ず1本ずつ** |
| 2 | **ヘッドレスは実時間の2.3%(1.9fps)しか進まない**(headedは80.7%/35.3fps・当PC実測) | 10分回してもゲーム内14秒。**見た目は正常に完走するので気づけない**。必ず実機(headed)で回す |
| 3 | **`window.__gameStore` は開発サーバ(5173)にしか無い** | 本番ビルド(4173)では状態を数値で読めない。`showShopMenu` を戻す処理が要る依頼は dev で回す |
| 4 | **canvasの中身はDOMから読めない** | 「絵が出ているか」はスクショを見るしかない。テキスト検索では判定できない |
| 5 | **dev サーバを起動したまま `git pull` すると版ラベルだけ古いまま焼かれる** | pull後は必ず再起動。既存3本のランナーは毎回ビルドするので影響なし |
| 6 | **`?smoke=1` を外すとタイトルで止まる** | 25分無駄にした事例あり。`gameTime` が5秒経っても0なら中断する保険を入れる |
| 7 | **PowerShell の `-Encoding utf8` はBOMを書く** | JSONを壊す。`New-Object System.Text.UTF8Encoding($false)` を使う |
| 8 | **`/tmp` に置いた .mjs を実行すると `ERR_MODULE_NOT_FOUND`** | node_modules を解決できない。**プロジェクト直下で実行する** |
| 9 | **`npx playwright install` は絶対にしない** | 環境のブラウザと版が食い違って壊れる |
| 10 | **Git Bash の `TZ=Asia/Tokyo date` はこの環境でUTCを返す**(9時間ズレ) | 時刻は PowerShell の `Get-Date` を使う |

## 9. 方式 — **固定手順**(画面を見て判断する方式ではない)

- **固定手順**: URLを開く → 関門を押す → 時間まで待つ → 採取する。**分岐は §2 の優先順位表がすべて。**
- **画面を見た判断が入るのは2箇所だけ**: ①関門ボタンが在るか ②`showShopMenu` が開いたか。
  どちらも**文字列とストアの値で機械的に判定できる**ので、視覚認識は要らない。
- **プレイの巧拙はゲーム内ボットの担当**。担当AIが上手く遊ぼうとしてはいけない
  (外から操作すると、測ろうとしていたボットの挙動そのものが変わる)。

### 掟(README と同じ。破ると結果が資料にならない)
- 触ってよいのは **`TEST_HANDOFF/` 以下だけ**。`src/`・`scripts/`・設計書・`CLAUDE.md` は編集禁止。
- **コード・数値・仕様は一切変更しない。**
- **TEST_HANDOFF/ のみの変更は、バージョンbump・changelog・DEVELOPMENT_LOG が不要。**
  コミットメッセージの先頭に `[test-report]`。
- **結果は毎回 push する**(人間の確認を待たない)。push されていない結果は存在しないのと同じ。
  途中で落ちた場合も、落ちた地点までを push する。

### 要約(.md)に必ず入れる項目
1. **版**(`package.json` の version と、画面に出ている版。**両方**。食い違ったら食い違いを書く)
2. **実行環境**(OS・ブラウザ・**headed である証拠**・ビューポート・使ったランナー名とコマンド)
3. **各ランの `[BOT_REPORT]` 生JSON全文**と `deathCause`
4. **consoleエラー全文**(無ければ「**0件**」と明記)
5. 60秒以上進まなくなった場面があれば、その時刻とスクリーンショット
6. 気づき(任意・1〜3行。**判定はしない**)

### 報告の書き方
- **事実と、自分の手順の都合を混ぜない。** ランナーの都合で撮れなかった/測れなかったものは
  **「製品の不具合ではなく手順の問題」と明記する。**
- **「必ず」「全部」「◯本」は数えてから書く。** 数えられないなら書かない。
- **社長の実機観察とコードの読みが食い違ったら、社長の観察が正。**
