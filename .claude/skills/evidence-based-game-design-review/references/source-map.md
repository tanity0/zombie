# 正本ルーティング(source map)

**最終更新: v0.25.3653**(この表より後に正本が乗り換わっている可能性を疑うこと)

**使い方**: 知りたいことに対応する行を1つ選び、**そのファイルだけ**開く。
複数行に当たりそうな時も、まず1本読んでから次を決める(横並びで開かない)。

## 採否履歴(過去に却下された案かを調べる)

1. まず**その分野の設計書の「★未決事項」「裁定」節**を見る(`PACING_PUZZLE.md` 等)。
2. 無ければ `DEVELOPMENT_LOG.md` を該当バージョン付近まで遡る
   (※通常運用の「最新部分だけ」の例外。**採否を調べる時だけ**遡ってよい)。
3. 見つからなければ「**未確認**」と書く。「却下された記録は無い」と断定しない。
4. 見つかった裁定は**事実として併記**する(それを理由に、今ベストな案を引っ込めない — `CLAUDE.md`)。

## 迷った時の優先順位

1. **実装状態を問う質問** → コードとテストが正本。文書は補助。
2. **現在どうすべきかを問う質問** → 現行の正本(`PACING_PUZZLE.md` / `STORY_*` 等)。
3. **なぜそうなったかを問う質問** → 旧背景・履歴(`PACING_REDESIGN.md` /
   `AI_DIRECTOR_HANDOFF.md` / `DEVELOPMENT_LOG.md`)。
4. 文書どうしが矛盾したら、**新しい方・現行の正本を採る**。古い方は「経緯」として併記する。

## Drive 等の外部資料

- Google Drive の資料が読めない場合は、**その項目を「未確認」として扱う。**
- **古い handoff 文書で代用しない。** 「Drive の◯◯が未確認」と書いて先に進み、
  その未確認箇所に依存する結論は出さない。
